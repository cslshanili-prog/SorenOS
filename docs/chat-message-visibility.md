# 首頁或通知有消息，私聊裡卻沒有

2026-09-11 排查記錄。兩個反饋只有截圖，以下是代碼與復現能確認的缺陷，不代表已經確認反饋設備上的唯一原因。

## 已修正

- 首頁消息卡原來只排除 system，會預覽 `source: date / call / story_theater_memory` 和主動消息的內部提示；私聊則排除這些內容。正文未必帶來源格式，不能靠文案判斷它屬於哪個界面。桌面消息卡現在複用 `utils/chatMessageVisibility.ts` 的私聊範圍。
- Chat 原來先取最近 N 條，再過濾來源。連續大量見面/通話記錄會佔滿窗口，真正的聊天仍在數據庫裡，卻沒有被取出來。`DB.getRecentMessagesWithCount` 現在支持在游標收集時篩選，只有可展示的消息佔用數量額度。普通主動回覆、通話後的私聊回信和評分卡保留原有顯示規則。
- 默認首頁的消息預覽不再使用受記憶處理水位影響的上下文查詢。界面讀取與模型上下文截斷是兩件事，本次不重置記憶或遷移聊天數據。
- `saveScheduledMessage` 原來發起寫入就返回；`saveMessage` 原來在單條請求成功時返回，事務仍可能隨後回滾。現在等事務提交，錯誤或中止會拒絕 Promise，調用方不會把這種失敗當保存成功繼續安排通知或銷掉定時任務。定時任務刪除也等待提交。

手遊/電子寵物桌面的消息預覽同樣排除其他界面來源；等級與互動統計維持原有取數方式。

## 定時通知的邊界

`chatPrompts.ts` 的本地定時指令允許角色自行安排未來留言，不要求用戶先手動配置主動消息。`chatParser.ts` 保存任務後，可以在原生環境安排系統鬧鐘通知；真正的聊天記錄由 OSContext 的定時輪詢補入。正在見面或通話（含掛起通話）時會暫緩該角色的投遞。

因此係統通知出現不等於聊天記錄此時已經落庫。只有通知截圖、沒有平台/版本/日誌，無法認定它就是傳統定時消息、主動消息 1.0 或 2.0。“找回沒收到的消息”檢查的是 2.0 雲端補收帳本，不能據此排除其他通道的問題。本次未修改雲端補收協議，也不能恢復已經丟失且沒有留存副本的內容。
