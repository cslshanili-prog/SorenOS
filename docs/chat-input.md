# 私聊與群聊輸入設置

入口：私聊底部「＋」→「設置」→「輸入與發送」，或群聊「群設置」→「輸入與發送」。四項輸入習慣在當前設備的所有私聊和群聊之間共用，修改後點擊底部「保存設置」或「保存修改」。

- **發送按鈕代替生成按鈕**：輸入框有光標時發送文字，點擊聊天空白處後變為生成回覆；未發送草稿保留。群聊沿用導演／輪詢模式，生成期間保留頂部停止按鈕。
- **回車發送文字**：開啟後回車發送，Shift + 回車換行；關閉後回車只換行。輸入法選字回車不會誤發。
- **發完後自動生成回覆**：發送成功、輸入框無草稿和光標、面板及彈窗收起後等 2 秒觸發。繼續輸入、發送或處理圖片期間暫停；倒計時可取消。手動生成、退出聊天、切群或關閉開關會取消等待，不因加載歷史補觸發。群聊使用原有導演／輪詢流程，無需新的 API 或後台配置。
- **表情包智能匹配**：見下節。

## 表情包智能匹配

- 默認關閉；舊存檔缺少該字段時也保持關閉。
- 輸入“抱”可匹配“抱抱”“給你抱抱”等名稱，完全匹配優先，其次是名稱開頭、名稱中包含輸入文字。短句裡出現完整表情名稱也可匹配。
- 私聊從當前角色可見的所有分類中查找，群聊從群聊表情庫全部分類中查找，不受表情面板當前分類限制。相同圖片去重，最多顯示八個候選，可左右滑動。
- 點擊候選通過現有表情發送流程發送一次，保留未發送的文字草稿。當前候選行收起；繼續修改輸入後重新匹配。
- 輸入法組詞時不顯示聯想，選字回車不會誤發。空輸入、無匹配、消息多選或展開底部其他面板時不顯示候選行。
- 只在本地匹配表情名稱，不請求模型，也不新增輸入內容埋點。

`utils/chatInputPreferences.ts` 的四個字段統一存到 `sully-chat-input-preferences-v1`，沿用現有完整備份的輸入偏好字段。匹配邏輯在 `utils/emojiSuggestions.ts`，候選顯示在 `ChatInputArea`；私聊傳入已有的角色可見表情列表，群聊傳入其完整表情庫。群聊點擊候選複用原有表情消息落庫和引用流程並保留草稿；切群會重置上個群收起的聯想狀態。只有開啟自動回覆且滿足等待條件才觸發模型。

### 與社區美化兼容

表情聯想和自動回覆倒計時位於 `.sully-chat-inputbar` 外側的同級區域，不插入輸入欄內部。顯示、收起輔助提示不會改變原有 `> div:first-child` / `:nth-child(1)` 的輸入行目標，也不會重建輸入框、丟失草稿或光標。

新美化建議使用固定鉤子：`.sully-chat-composer`（輸入行）、`.sully-chat-input-wrap`（輸入框外殼）、`.sully-chat-textarea`、`.sully-chat-actions-button`、`.sully-chat-send-button`。聯想區可單獨用 `.sully-chat-emoji-suggestions` 定製（舊 `.sully-emoji-suggestions` 仍保留），倒計時用 `.sully-chat-auto-reply`。不改寫用戶保存的 CSS。

## 摺疊設置

聊天設置分為六組，默認全部收起：輸入與發送、聊天外觀、上下文與記憶、翻譯與語音、擴展功能、聊天記錄。標題行常顯，點擊或鍵盤操作可展開；摺疊不會丟失未保存的修改。各項原有的保存方式和執行行為不變。

```sh
pnpm vitest run utils/emojiSuggestions.test.ts utils/chatInputInteraction.test.ts utils/chatAutoReply.test.ts utils/sarReleaseBackup.test.ts
```
