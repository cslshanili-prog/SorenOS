# 角色自定義時區

角色卡里可以給角色單獨設一個時區（角色編輯頁 →「角色自定義時區」開關 + 時區下拉）。開啟後，注入給這個角色的「當前時間 / 今天幾號 / 現在是白天還是深夜」都按 ta 所在地折算，而不是跟著用戶手機走。

典型場景是異國戀：用戶在中國，角色設定在紐約。用戶這邊晚上 9 點，角色那邊是同一天的早上 9 點，兩邊看到的鐘本就不該一樣。

沒開這個開關的角色，一切照舊跟隨設備時間。

## 兩把尺子，別混用

改動任何跟時間有關的代碼前，先分清這個時間代表誰：

| 代表誰 | 例子 | 該用什麼 |
|--------|------|---------|
| **角色那邊幾點** | 角色此刻在做什麼、ta 的作息、prompt 裡的「現在是」、角色寫下的時間戳 | 角色時區 |
| **用戶自己的時間** | 狀態欄時鐘、桌面日曆、消息氣泡上的收發時間、導出文件的時間 | 設備時間 |
| **跟時區無關** | 「距上次聊天多久」這類純時長差 | 絕對時間戳直接減 |

判斷不了的時候問一句：這個數字是給角色看的，還是給用戶看的？

## 基礎件

都在 `utils/` 下，別自己手搓時差：

| 函數 | 用途 |
|------|------|
| `timezone.ts` → `resolveCharTimeZone(char)` | 取角色生效的時區 id；沒開開關返回 `undefined`（= 跟隨設備） |
| `timezone.ts` → `nowInTimeZone(tz, base?)` | 返回一個 Date，用**本地** getter（`getHours()` 等）讀出來正好是 `tz` 的牆上時間 |
| `timezone.ts` → `wallClockToTimestamp(text, tz)` | 上一條的逆運算：把「角色當地的牆上時間」文本還原成真實時刻 |
| `timezone.ts` → `tzAwarenessNote(tz)` | prompt 裡那段時差提示 |
| `scheduleTime.ts` → `getScheduleWallClock(char, base?)` | 角色牆上時間，`nowInTimeZone(resolveCharTimeZone(char))` 的快捷方式 |
| `scheduleTime.ts` → `getScheduleDateKey(char, base?)` | 角色所在地的日曆日 `YYYY-MM-DD` |
| `scheduleTime.ts` → `getCurrentScheduleSlotIndex(slots, char, base?)` | 按角色時間找當前時段 |
| `dailySchedule.ts` → `getDailyScheduleForChar(char, at?)` | 按角色的日曆日讀日程，帶舊 key 兼容 |
| `localDate.ts` → `getLocalDateKey(date)` | 日期 key。注意別用 `toISOString().slice(0,10)`，那是 UTC 日 |
| `hooks/useLocalDateKey.ts` → `useLocalDateKey(tz)` | 組件裡用的響應式日期 key，跨午夜自動刷新 |

### `nowInTimeZone` 返回值的坑

它返回的 Date，**絕對時間戳是被挪過的**——只有用本地 getter 讀字段才有意義。所以不要再把它的 `getTime()` 餵給另一個同樣會折算的函數，那樣時差會被減兩遍。要真實時刻就用 `Date.now()`。

## 日期 key 的寫讀一致性

日程存 IndexedDB 用的 key 是 `${charId}_${dateKey}`。**寫入和讀取必須算出同一個字符串**，否則會「寫進 A、讀 B」，每次打開都判定沒日程、反覆調 LLM 重新生成——燒 token 而且從界面上看不出來。

寫入側統一走 `getScheduleDateKey(char)`，讀取側統一走 `getDailyScheduleForChar(char)`。

`dailySchedule.ts` 裡還有一層舊 key 兼容（更早版本按 UTC 日、接入角色時區前按手機日）。遷移時會校驗 `generatedAt` 確實屬於角色當地的今天，並且把舊記錄**搬走**而不是複製——留副本的話，等角色當地日曆翻到那個日期，同一份日程會被當成兩天用。

## 已接入的地方

聊天注入、見面（VN 模式 + 感知開場）、打電話、實時信息（時間/天氣/節日）、日程全鏈路（生成、卡片、桌面組件、小小窩、小屋、聊天裡的日程注入、音樂氛圍）、角色自由活動、定時消息解析。

## 還沒接的

下面幾處目前仍按設備時間走。不影響日常使用，但角色開了自定義時區時會出現「同一份 prompt 裡兩個時間打架」。

### 主動消息（改之前先確認 amsg2 分支的狀態）

| 位置 | 現狀 |
|------|------|
| `context/OSContext.tsx` 主動消息觸發段 | 寫進隱藏系統提示的「現在是 X」取設備時間，而同一次請求裡 `buildSystemPrompt` 注入的是角色時區的時間。這條 hint 會落庫，之後幾輪上下文裡都留著 |

改法：拿 `resolveCharTimeZone(char)` 折算；注意別把用來算時間差的 `now` 一起換掉，那個必須繼續用真實時刻。

主動消息 2.0 那條鏈（`utils/activeMsgClient.ts` 的 `buildFirePack`）已經接好了：模板帶一個 `tzId`，worker 到點渲染的每個時間都以它為參照系（`utils/amsgFirePack.ts`）。凡是「打包這一刻」的狀態都不烤進模板，改由 `AMSG_SLOT_*` 槽位到點現算 —— 當前時間、日程當前時段、此刻在聽的歌、今日節日 / 天氣 / 熱搜都走這條路，見 `ChatPrompts.PromptBuildOptions` 上那張表。

其中今日節日按角色時區判「今天幾號」，並且跟著角色的「時間感知」開關走（關掉的角色到點也不會知道今天是聖誕節）——這個開關隨 `tool_pack` 上雲，見 `worker/amsg/src/realtimeWorld.ts`。熱搜的時段劃分則固定按 `Asia/Shanghai`：榜單本身就是國內的作息，worker 跑在 UTC 上，不指定的話「今日上午」會差好幾個時段。

### 一組角色共同排日程（feature request）

來自用戶反饋：設定成一家人的多個角色，日程是各排各的——同一時刻打開，一個在畫畫、一個在盤算偷東西、一個在發呆，誰也不知道誰在幹嘛。「一家人」只存在於人設文字裡，日程上看不出他們有關係。希望能在生成日程時把同組角色一起生成，至少讓晚飯這類時刻湊得到一塊。

做之前想清楚的地方：全部對齊容易變成幾個角色在同一時刻說同一件事的復讀，比各活各的更假。比較穩的形態是共享少量錨點（晚飯、集合、出勤），其餘時段仍各排各的。

順帶一提，日程卡上「NOW」標的是**當前這個時段從幾點開始**，不是當前幾點。同一時刻打開三個角色的卡，NOW 會分別停在 10:00 / 11:00 / 11:30，因為各人這段活動的起跑線不同。卡片頭部現在直接顯示當前時間，就是為了避免把 NOW 那行的數字當成鍾來讀。

### 界面上的「鍾」該跟誰

這幾處是產品判斷，不是純 bug——先想清楚這塊表是掛在角色屋裡還是用戶桌上：

- 小小窩直播看板的電子鐘、錶盤天色（清晨/白天/黃昏/夜晚）
- 「查手機」裡角色手機主屏的大時鐘和日期
- 見面「感知」頁頂部的星期 + 時間
- 夢境「一天最多看 N 個」的配額按哪一天清零

小小窩判斷「角色睡沒睡」已經改成跟角色時區了。如果看板的鐘繼續跟設備走，會出現看板寫著「營業中 / ON AIR」、錶盤卻是月亮的觀感衝突，兩者一起定比較好。

### 測試還沒蓋到的

- 日程生成的**寫入側**：prompt 裡那句「今天是 X (星期 Y)」和落庫用的 `date` / `id`
- `nowInTimeZone` 本身沒有直接的單測

## 已知限制：設備夏令時空檔

`nowInTimeZone` 是先讀出目標時區的年月日時分，再用**設備時區**重新構造 Date。如果那個鐘點在設備時區當天恰好不存在（夏令時往前跳的那一小時），JS 的 Date 構造器會靜默往後推一小時。

觸發條件：用戶設備在有夏令時的地區，角色所在地此刻的鐘點正好落進設備當天被跳過的那一小時。後果是時段判定漂 1 小時，一年一次、持續一小時，且通常在角色那邊的凌晨。

根子是「用本地 Date 承載異地牆上時間」這個設計——那個鐘點在設備時區沒法表示，怎麼補償都只是挑一個近似值。目前按已知行為留著。

秋令時那個重複的小時不受影響，`getHours()` 讀出來仍是對的。
