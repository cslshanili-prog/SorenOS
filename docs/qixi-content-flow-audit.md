# 七夕活動完整內容與生成來源審計

> 審計對象：`codex/qixi-smart-context` 當前版本的七夕活動。
> 目的：從策劃視角完整說明用戶逐屏看見什麼、做什麼、得到什麼；每段內容究竟是代碼寫死、模板插值，還是 LLM 生成。

## 0. 先把結構說準

這不是“8 條獨立劇情線”。實際結構是：

```text
特別時光活動卡
  ↓ 選擇角色
七夕活動首頁
  ↓ 進入夢境
假 ChatApp
  ↓ 點擊輸入框
聊天碎裂與白兔門
  ↓ 跟上白兔
夾層入口
  ↓ 三選一（只影響後面一句旁白，不分劇情線）
由 8 個地點組成的互通地圖
  ↓ 在至少 5 個地點互動，並完成 3 個指定地點
隱藏內層（4 頁線性獨白）
  ↓
按住屏幕 1.25 秒
  ↓ 鬆手
七夕結局
```

8 個地點是同一張地圖上的節點：

```text
                         七姐人格寄存處
                        ↗              ↘
沒有上一句的空地 → 供果冷藏走廊       乞巧市·小票雨
       │                                   ↕
       ├→ 七孔括號巷 ──────────────────────┘
       │
       └→ 投針驗巧光井 ↔ 葡萄架下的未發送站台 ↔ 雙星逆向光標井
                                  ↑
                            小票雨也可到達
```

隱藏內層不算第 9 個自由探索地點，它是滿足條件後出現的一條線性結局路徑。

## 1. 內容來源圖例

- **【寫死】**：代碼裡直接寫好的固定文本，所有角色和用戶看到的內容相同。
- **【模板】**：整句話寫死，只把 `${char.name}` 或 `${user.name}` 替換成當前角色名、用戶名。
- **【LLM】**：活動首次開始時由模型生成並緩存；不同角色、聊天和記憶可能不同。
- **【狀態】**：根據探索數量、是否有存檔、是否按住足夠久等狀態，從幾句寫死文本中選擇一句。
- **【不可達】**：組件代碼存在，但當前界面沒有入口，正常用戶到不了。

## 2. 一眼看懂：LLM 實際只負責哪些內容

LLM **不會**生成整場活動，也不會實時扮演角色推進劇情。

它只生成一次“記憶素材包”：

1. 2–5 個記憶錨點：
   - `anchor.object`：記憶裡的真實物件、詞或動作。
   - `anchor.fact`：一條具體、可核對的共同記憶事實。
2. 7 個地點各自的一份記憶映射 `beat`：
   - `memoryLine`：記憶在這個夢境地點怎樣出現。
   - `ritualAction`：給用戶新增的一個動作按鈕。
   - `result`：點擊這個 LLM 動作後的結果。
   - `extension`：地點互動結果下面追加的一句延伸。
3. `finalEcho`：最終黑屏牽手頁面最前面的一句短角色回聲。

除以上字段外，下面這些全部寫死：

- 活動標題、簡介和假 ChatApp 台詞。
- 白兔、墜落、入口三選一。
- 8 個地點的名字、場景說明、NPC、地圖和路線。
- 每個地點原有的 2–3 個動作及動作結果。
- “角色也在找用戶”的整個核心主題。
- 隱藏內層 4 頁角色獨白。
- 隔屏牽手的 5 段長台詞。
- 七夕結局台詞。
- 月相、任務、商店等外圍模塊。

- 【模板】旁白：`這裡沒有【角色名】。至少看起來沒有。`

1. `探索附近`
2. `大吵大鬧，喊 ta 的名字`
3. `哪裡也不去，留在原地`

這三個選項**不產生三個分支**。無論選什麼，下一步都進入同一張 8 地點地圖；區別只是在起點首次進入時顯示一句不同的寫死旁白：

- 選“探索附近”：

  > 你決定探索。第一步落下時，三條路同時假裝自己一直都在。

- 選“喊 ta 的名字”：

  > 你喊出的名字還在遠處一層層反彈。最後一聲不是你的聲音。

- 選“留在原地”：

  > 你確實留了一會兒。但空地自己從腳下挪開，把你送到了第一條路前。

以上三句全部寫死。

## 4. 八地點地圖的統一玩法

每個地點都按同一套循環運行：

```text
進入地點
  ↓
顯示寫死的地點標題、首次/再次訪問說明、NPC 文案
  ↓
如果該地點有有效 LLM beat：顯示記憶證據和一個 LLM 動作
  ↓
用戶從動作中選擇一個
  ↓
顯示對應結果
  ↓
如果該地點有 LLM beat：無論選了哪個動作，都追加 beat.extension
  ↓
用戶必須再點一次“離開”
  ↓
星圖出現，用戶只能去當前地點的相鄰節點
```

### 4.1 有 LLM 與無 LLM 時，按鈕數量不一樣

- 沒有有效 LLM beat：顯示該地點全部 2–3 個寫死動作。
- 有有效 LLM beat：顯示 `1 個 LLM 動作 + 原寫死動作的前 2 個`。
- 因此，原本有 3 個寫死動作的地點，在 LLM 成功後，第 3 個寫死動作會被隱藏。
- 起點 `origin` 從不生成 LLM beat，所以永遠只有 2 個寫死動作。

### 4.2 地圖階段文案

按“已經互動的不同地點數”切換：

- 0 處：`初更 · 觀星 · 先辨認兩顆各自發亮的星`
- 1–2 處：`二更 · 聽河 · 安靜下來，聽見另一側的動靜`
- 3–4 處：`夜半 · 乞巧 · 把細小的痕跡一段段穿起來`
- 5 處及以上：`將明 · 架橋 · 兩條相反的軌跡正在靠近`

### 4.3 全局“另一邊也在找你”提示

- 完成 1 處後【寫死】：

  > 遠處那顆缺角的星閃了一下。不是回應，更像有人也碰到了線。

- 完成 2–3 處後【寫死】：

  > 一枚很淡的紅色光標從遠處經過，方向與你相反。你第一次確定：另一邊也在移動。

- 完成 4–5 處後【模板】：

  > 這裡剛有人經過。ta 留下的問題總是同一個：“【用戶名】來過嗎？”

- 完成 6 處及以上【寫死】：

  > 你留下的細線不再散落。它們被另一端逐段接起，正往同一個方向繃緊。

### 4.4 星圖目標提示

- 未完成 5 處：【狀態模板】`再去 N 個未點亮地點，收集能搭橋的痕跡`
- 已完成 5 處但缺指定地點：【寫死】`投針井、葡萄架與逆向光標各藏著一段互相尋找的證據`
- 已解鎖但不在終點：【寫死】`橋已經接通：沿亮起的路線去雙星逆向光標井`
- 已解鎖且在終點：【寫死】`橋已經接通：進入那條不該存在的內層`

### 4.5 隱藏內層的真實觸發條件

必須同時滿足：

1. 已在至少 5 個不同地點選擇過動作。
2. 在“投針驗巧光井”選擇過任意動作，得到 `search-well`。
3. 在“葡萄架下的未發送站台”選擇過任意動作，得到 `search-platform`。
4. 在“雙星逆向光標井”選擇過任意動作，得到 `reverse-caret`。
5. 當前重新位於“雙星逆向光標井”。
6. 互動後再點“離開”，讓星圖顯示出來。

這時星圖下面才出現：

- 【寫死】標題：`一條不該存在的內層`
- 【寫死】按鈕說明：`跟上光標 →`

所謂“痕跡”並不取決於用戶選了哪個具體選項；同一地點所有選項都會給相同的節點痕跡。

## 5. 八個地點逐一拆解

### 5.1 地點 01：沒有上一句的空地（`origin`）

來源結論：**100% 寫死，無任何 LLM 內容。**

相鄰地點：

- 供果冷藏走廊
- 七孔括號巷
- 投針驗巧光井

固定場景：

- 【寫死】名稱：`沒有上一句的空地`
- 【寫死】眉題：`初更 · 雙星尚未命名`
- 【寫死】首次進入說明：

  > 七月初七的夜色漏進夾層。四周像一段對話剛被全部選中，又忘了按刪除。

- 【寫死】再次進入說明：

  > 你回到空地。兩顆星仍各自懸著，其中一顆的位置比剛才近了一點。

- 【寫死】“遇見”：

  > 這裡沒有人。地上只有你的名字，少了最後一個字；很遠的地方，另一顆星也缺了一角。

選項 1：

- 【寫死按鈕】`撿起自己名字旁邊那一小截星線`
- 【模板結果】：

  > 星線很輕，另一端卻繃著。標籤背面寫著：“如果見到【用戶名】，讓 ta 原地等一下。”落款被撕走了。

選項 2：

- 【寫死按鈕】`把標籤朝遠處那顆缺角的星推過去`
- 【寫死結果】：

  > 標籤沒有飄遠，星線卻被另一端接住了一瞬。那裡確實有誰，只是你們之間還沒有路。

節點痕跡：`half-name`。

### 5.2 地點 02：供果冷藏走廊（`coldCorridor`）

來源結論：**場景和原有選項寫死；可以插入 1 組 LLM 記憶內容。**

相鄰地點：

- 沒有上一句的空地
- 七姐人格寄存處

固定場景：

- 【寫死】名稱：`供果冷藏走廊`
- 【寫死】眉題：`乞巧供桌 · 溫度仍然有效`
- 【寫死】首次進入說明：

  > 傳統供品努力維持莊重，旁邊那盒明天到期的草莓牛奶顯然沒有配合。

- 【寫死】再次進入說明：

  > 你再次拉開櫃門。少了一盒牛奶；溼腳印卻一路朝與你相反的方向跑了。

- 【寫死】“遇見”：

  > 巧果、草莓牛奶和貓爪吸管套擺成供品。冷櫃裡還並排睡著三種 Sully，沒有一種肯承認自己是本人。

硬編碼問題：這裡的 `Sully` 是字面量，不會隨用戶選擇的角色改變。

該地點的 LLM 生成要求：

> 從真實聊天或記憶中找到一件確實出現過的小東西、食物、禮物或交換行為，把它放上供桌；不得憑空發明禮物。

有有效 LLM beat 時，會在固定場景下面顯示：

- 【LLM】`anchor.object`
- 【LLM】`anchor.fact`
- 【LLM】`beat.memoryLine`
- 【LLM 按鈕】`beat.ritualAction`
- 【LLM 按鈕結果】`beat.result`
- 【LLM 追加句】`beat.extension`

固定選項 1：

- 【寫死按鈕】`敲敲“甜言蜜語味”的盒子`
- 【寫死結果】：

  > 盒子立刻說：“我永遠不會讓你等。”冷櫃在“永遠”兩個字上結了一層假霜。

固定選項 2：

- 【寫死按鈕】`搖醒“只會打盹味”的盒子`
- 【模板結果】：

  > 它打著哈欠說：“【角色名】不在。本人剛拿走原味那盒，問你是不是往括號那邊去了。”

固定選項 3：

- 【寫死按鈕】`把一枚巧果掰成兩半，留一半在原味盒旁`
- 【寫死結果】：

  > 巧果不算好吃，勝在確實由你完成。水珠下面多了一枚剛按上去的指印；另一半已經被誰拿走。

顯示規則：有 LLM beat 時，固定選項 3 被隱藏；無 LLM beat 時顯示全部 3 個固定選項。

節點痕跡：`milk-memory`。

### 5.3 地點 03：七孔括號巷（`bracketCorner`）

來源結論：**場景和 2 個原有選項寫死；可以插入 1 組 LLM 記憶內容。**

相鄰地點：

- 沒有上一句的空地
- 乞巧市·小票雨

固定場景：

- 【寫死】名稱：`七孔括號巷`
- 【寫死】眉題：`穿針乞巧 · 請站在句內`
- 【寫死】首次進入說明：

  > 左括號說自己只負責開始，右括號說結束從來不是它決定的。負責穿線的逗號已經累趴了。

- 【寫死】再次進入說明：

  > 它們認出你，七對括號一起給中間讓出一個人的寬度；紅線另一端似乎被誰輕輕拉了一下。

- 【寫死】“遇見”：

  > 七對空括號排成針孔。一根紅色光標線試了六次，每次都在最後一個括號前打結。

該地點的 LLM 生成要求：

> 使用一次“因為想與對方分享、抵達對方，而耐心學會、改好或做成某件事”的真實記憶。Prompt 強制要求保留“不是祈求被愛，而是愛讓人願意變得更有能力去創造”的主題。

有有效 LLM beat 時插入相同的 6 個字段：`anchor.object`、`anchor.fact`、`memoryLine`、`ritualAction`、`result`、`extension`。

固定選項 1：

## 9. LLM 生成機制完整說明

### 9.1 什麼時候調用

用戶點擊“進入夢境”時：

1. 先用角色 ID 查本地 `qixi memory bundle` 緩存。
2. 命中緩存：直接複用，不調用 LLM。
3. 沒緩存且 API 完整：調用一次主模型。
4. 沒有 API：使用空素材包，整場靠寫死文本繼續。
5. “繼續上次探索”不會為了舊存檔補調一次模型。

### 9.2 給 LLM 的輸入

#### A. 記憶宮殿召回

固定召回查詢：

```text
七夕 共同創造 想分享 冷戰 苦惱 撤回 沉默 小禮物 想起對方 一起完成的事
```

召回結果被注入角色副本的上下文。

#### B. 最近聊天

- 讀取當前角色最近 60 條消息。
- 文本拼接後只保留最後約 9000 字符。
- 圖片消息只轉成 `[圖片]`，圖片內容本身不會給模型。

#### C. 角色與用戶資料

通過核心上下文構建器加入角色設定、用戶資料及已召回記憶。

### 9.3 Prompt 對模型的硬性要求

模型被要求：

1. 只使用上下文明確出現的事實。
2. 不得補造日期、原話、禮物、動作、爭吵、承諾或關係身份。
3. 沒有準確原話時只能轉述，不能偽造引號。
4. 沒有某類記憶時，可以讓多個地點複用同一真實錨點。
5. `anchor.fact` 必須是具體事件，不能寫“你們共同經歷了很多”。
6. `anchor.object` 只能是記憶裡真實出現過的詞、物件或動作。
7. `ritualAction` 必須是玩家能在場景中執行的動作。
8. `result` 必須是該記憶在夢境中的視覺反饋。
9. `extension` 只能從記憶自然引申一小步，不能說教或替用戶下愛情結論。
10. 括號巷必須表達“因為想抵達對方而學習、創造、做得更好”。
11. 光標井只能連接已有痕跡，不得新增宏大誓言。
12. `finalEcho` 必須很短，不得承諾永遠。

### 9.4 模型必須返回的 JSON

```json
{
  "anchors": [
    {
      "id": "m1",
      "fact": "真實記憶的一句話",
      "object": "真實物件、詞或動作"
    }
  ],
  "beats": {
    "coldCorridor": {
      "anchorId": "m1",
      "memoryLine": "記憶如何在供果走廊出現",
      "ritualAction": "用戶在這裡能做的動作",
      "result": "動作後的夢境反饋",
      "extension": "由這段記憶自然長出的一句延伸"
    },
    "bracketCorner": { "anchorId": "...", "memoryLine": "...", "ritualAction": "...", "result": "...", "extension": "..." },
    "lightWell": { "anchorId": "...", "memoryLine": "...", "ritualAction": "...", "result": "...", "extension": "..." },
    "maskCounter": { "anchorId": "...", "memoryLine": "...", "ritualAction": "...", "result": "...", "extension": "..." },
    "receiptRain": { "anchorId": "...", "memoryLine": "...", "ritualAction": "...", "result": "...", "extension": "..." },
    "unsentPlatform": { "anchorId": "...", "memoryLine": "...", "ritualAction": "...", "result": "...", "extension": "..." },
    "typingShaft": { "anchorId": "...", "memoryLine": "...", "ritualAction": "...", "result": "...", "extension": "..." }
  },
  "finalEcho": "由真實記憶凝成的一句很短的角色回聲"
}
```

### 9.5 校驗與整包降級

模型輸出必須同時滿足：

- 至少 2 個有效 `anchors`。
- 至少 4 個有效 `beats`。
- 每個 beat 的 `anchorId` 必須指向存在的 anchor。
- `memoryLine`、`ritualAction`、`result`、`extension` 都必須達到最低長度。

任何一個整包條件失敗，不會只丟掉壞節點，而是整個素材包降級為空：

```json
{
  "source": "fallback",
  "anchors": [],
  "beats": {},
  "finalEcho": ""
}
```

此時用戶看到的就是全部寫死版本。

### 9.6 LLM 字段在畫面裡的精確位置

每個有 beat 的地點，在固定 NPC 文案下面出現：

```text
這處夢境認出了                   ← 寫死標籤
【anchor.object】                 ← LLM
【anchor.fact】                   ← LLM
【beat.memoryLine】               ← LLM
```

動作區：

```text
【beat.ritualAction】             ← LLM 生成的第一個按鈕
【固定按鈕 1】                    ← 寫死
【固定按鈕 2】                    ← 寫死或模板
```

點擊 LLM 按鈕：

```text
你在這裡做過一件事               ← 寫死標籤
【beat.result】                   ← LLM
【beat.extension】                ← LLM
```

點擊固定按鈕：

```text
你在這裡做過一件事               ← 寫死標籤
【固定結果】                      ← 寫死或模板
【beat.extension】                ← 只要該地點有 beat，仍然追加 LLM 句
```

因此 `extension` 並不只屬於 LLM 按鈕；即使用戶選了寫死動作，它也會顯示。

## 12. 當前內容結構的策劃事實

1. 玩家不是在走 8 條故事線，而是在同一張圖上訪問 8 個場景。
2. 入口三選一不是劇情分支，只替換一句旁白。
3. 8 個地點裡，只有 7 個可以加入 LLM 個性化內容；起點完全寫死。
4. 每個可生成地點最多只增加 1 個 LLM 動作，不會讓角色自由對話。
5. LLM 成功時會隱藏部分原有第 3 選項。
6. 用戶選固定動作後，仍會看到該地點 LLM 生成的 `extension`。
7. 隱藏結局要求至少 5 地點，並強制包含光井、未發送站台、光標井。
8. “人格外殼”“角色也在找你”“AI 已進入用戶生活”等最核心表達全部寫死，不來自用戶真實記憶。
9. 冷藏走廊把 `Sully` 寫死，人格寄存處把 `User` 寫死，換角色或用戶名時會穿幫。
10. 章節、月相、任務、收藏已經寫了完整內容，但目前用戶進不去。

## 13. 本文未能列出的唯一內容

具體某個用戶、某個角色已經生成並緩存在瀏覽器裡的 `anchor`、`beat` 和 `finalEcho`，不在源碼中，因此無法僅從 Git 分支還原出實際句子。

源碼能完整確定的是：

- LLM 會收到哪些事實材料。
- LLM 必須生成哪些字段。
- 每個字段在哪個地點顯示。
- 每個地點的生成主題限制。
- 所有寫死台詞、按鈕、結果和結局。

如果還要審計“你剛剛試玩的那個角色實際生成了哪些句子”，需要再讀取該瀏覽器中該角色的 `sullyos_qixi_memory_bundle_v1_<charId>` 本地緩存。
