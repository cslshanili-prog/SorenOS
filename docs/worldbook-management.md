# 世界書編輯、分組與角色掛載

2026-09-13 修復。

## 用戶操作

- 關閉「關鍵詞觸發」改為常駐時，主關鍵詞、輔助關鍵詞仍然保存；重新啟用即可繼續使用。
- 世界書每組下方可「編輯整組」：改分組名、保持原觸發方式、全部常駐或全部關鍵詞觸發。任一條缺少主要關鍵詞時，整組關鍵詞切換不執行，提示先補齊。停用狀態和其它匹配規則不變。
- 改名不允許與已有分組合並，避免意外混組。分組名稱是分類字段，不是綁定標識。
- 「刪除整組」會顯示條目數量並確認，同時從已掛載的角色中移除這些條目。取消不更改數據。多選刪除使用同一批量通道。
- 神經鏈接的擴展設定按已掛載條目的分類摺疊。展開組可查看條目，展開條目才掛入正文；「整組取消掛載」只修改當前角色，不刪公共庫、不影響其他角色。

舊版本若已把關鍵詞清空並保存，不能從現有數據推算回來。應從原文件補回原條目的關鍵詞；不要通過替換條目 ID 自動重建綁定。

## 綁定不變量

綁定只按條目 `id`，從不按標題、分組名或導入的 `sourceUid` 匹配。

`DB.mutateWorldbooks` 在同一個 IndexedDB 讀寫事務內讀取最新庫記錄、修改目標條目、同步角色的 `mountedWorldbooks` 緩存；事務提交後才刷新 OSContext。批量操作不能循環使用捕獲了舊 `characters` 的單條更新函數，否則後一次保存可能復活前一次已刪除的掛載，或覆蓋前一次同步。

- 修改保留原有 ID、創建時間和掛載順序；只更新已綁定該 ID 的角色，不新增掛載。
- 部分掛載繼續保持部分掛載；角色卡自帶、公共庫沒有的其它條目保留。
- 刪除按顯式選中的 ID 集合執行，不按同名分類刪除角色自帶條目。
- 世界書庫與緩存任何一步失敗，全事務回滾。已修改角色在提交後標記雲端提示詞待刷新。

## 注入到提示詞

- 「角色設定前 / 後」「作者註釋頂部 / 底部」「示例消息前 / 後」由 `ContextBuilder.buildCoreContext` 寫進 system prompt，所有拼角色設定的入口都會帶上。
- 「聊天記錄指定深度」的條目不進 system prompt，要由有多輪對話的入口自己插進消息數組：`resolveWorldbookDepthEntries` 取條目，`injectWorldbookDepthEntries` 按深度插入。深度從對話末尾往回數，本輪用戶消息算最後一條，深度 0 放在它之後。目前接了私聊、見面（開場感知和會話）、通話三處；其餘入口是單次生成或把歷史壓成了文字，這類條目在那裡不生效。
- 群聊裡，兩個及以上成員都掛了的條目只在開頭的「共有擴展設定集」寫一次，不分位置平鋪，`{{char}}` 換成掛了它的幾位成員名；只有一個成員掛的條目按位置寫進那個成員的檔案。群聊的歷史是壓成文字的，「聊天記錄指定深度」在只掛一人的條目上不生效。
- 關鍵詞觸發的條目靠調用方給 `buildCoreContext` 傳 `worldbookMessages`（最近的對話）來掃，不傳就永遠不觸發。新增帶對話上下文的入口時兩件事都要接上。

## 跟 SillyTavern 的格式對齊

導入導出都是 ST 的 `{ entries: { [uid]: {...} } }`，上游 Sully 也是同一套，三邊互讀。原則：**欄位名和數值都照 ST，不自創欄位、不改既有欄位的意思**；Soren 多支援的東西，到 Sully 只是不生效，不會壞。

- 完整詞匹配的邊界照 ST 用 `\W`：只有英文字母、數字、底線算詞內，中日文前後緊貼的字都算邊界，所以中文關鍵詞開了也能中。含空白的多詞關鍵詞直接找整串。
- 關鍵詞寫成 `/pattern/flags` 就按正則匹配（規則同 ST 的 `parseRegexFromString`），不受大小寫、完整詞兩個開關影響；`g`/`y` 去掉。編輯器拆關鍵詞時，帶逗號的正則整條保留。
- 位置 7 是 ST 的 outlet，原樣保存、不注入（`resolveWorldbookEntries` 裡濾掉）；編輯器只對本來就是 7 的條目顯示這個選項。
- 導出時 `entries` 的鍵等於 `uid`（ST 有大量 `entries[uid]` 查找，鍵不等於 uid 會改不了、刪不掉），列表順序靠 `displayIndex`，導入時照它排。
- Soren 還沒做的 ST 欄位（sticky / cooldown / delay、互斥組、遞迴開關、額外掃描來源、`extensions` 等）收在 `stExtra`，導出時原名寫回；只收 `ST_PASSTHROUGH_FIELDS` 白名單，不掛角色緩存。要真正支援其中某個功能時，把它從 `stExtra` 提成正式欄位。
