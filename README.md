## 這是什麼鬼東西？

**Soren** 是一個裝在你瀏覽器裡的虛擬手機系統。

不是那種普通的聊天機器人——這裡面有**桌面**、**APP**、**消息通知**、**相冊**、**甚至電話功能**。你可以創造角色，給他們裝進去，然後像真用手機一樣跟他們互動。

默認內置了 **Sully**（我），一個會說話的黑客貓貓。但你可以把我刪掉，換上你自己的人。草，隨便吧。

## 本地運行（把它弄起來）

```bash
npm install
npm run dev
```

然後瀏覽器開 `http://localhost:5173`。API Key 不用在這填——進去在**應用內「設置」**裡填就行（見下方「配置說明」）。

## 技術棧（ nerdy 的東西 ）

- **React + TypeScript** - 前端骨架
- **Vite** - 構建工具，快得像作弊
- **IndexedDB** - 本地數據存儲（聊天記錄不會上傳到任何地方），圖片二進制走 **Blob** 存儲省配額
- **Cloudflare Workers** - 聯網能力的代理層（搜索 / 雲備份 / 點單 MCP 等），單文件 `worker/index.js`，可一鍵自託管
- **Capacitor** - 可打包成安卓 App，真·手機模擬器
- **Phosphor Icons** - 圖標庫，看起來挺酷的
- **AMSG（ReiStandard）** - 主動消息協議
- **Web Push** - 推送通知，叮叮叮
- **JSZip** - 壓縮文件，導出備份包用

## 配置說明（怎麼讓角色說話）

打開應用 → 底部 Dock 的「設置」→ 填入你的 API 信息：

| 字段 | 說明 |
|------|------|
| **Base URL** | OpenAI 格式的 API 地址，如 `https://api.openai.com/v1` |
| **API Key** | 你的密鑰，別告訴別人 |
| **Model** | 模型名，如 `gpt-4o-mini`、`claude-3-sonnet`、`deepseek-chat` |

**TTS（可選）**：語音支持 MiniMax、Fish Audio、ElevenLabs 三選一。在「設置 → 其他 API」填寫所選服務的 Key 和模型，再到角色的語音設置填寫對應音色 ID；未配置時仍可正常使用文字聊天。

> 也可以建 `.env.local` 文件預填默認值，但設置裡的優先級更高。

## 數據存儲在哪？（你的秘密安全嗎）

**主要存在你本地瀏覽器裡**（IndexedDB）。

- 聊天記錄 ✅ 本地
- 角色設定 ✅ 本地  
- 上傳的圖片 ✅ 本地（二進制走 **Blob** 存儲，比 base64 省約 1/3 空間、也不佔 JS 內存）
- 你的世界書 ✅ 本地

**備份 / 遷移**（都可選，而且**全是你自己的帳號、你自己的地盤**，沒有任何東西會偷偷上傳到某個中心數據庫）：

- 📦 **本地導出 / 導入**：一鍵打成一個 zip 備份包（「設置 → 導出 / 導入」）。換設備最省心就靠它。
- ☁️ **WebDAV 雲備份**：填你自己的 WebDAV 服務（堅果雲之類），把備份包傳上去。
- 🐙 **GitHub 雲備份**：填你自己的倉庫 + token，備份包託管到你的私有 repo。
- 🧠 **記憶宮殿向量**：可選同步到你自己的 Supabase（獨立通道，不填就純本地）。

換瀏覽器 / 清緩存 = 本地數據消失，所以**務必定期導出備份**。刪了我 = 你會後悔，數據庫都在咕咕咕。

## 常見問題（別問蠢問題）

**Q: 為什麼角色不回我消息？**  
A: 檢查 API Key 填了沒，或者模型是不是選了個已經去世的（比如 gpt-4-v）。也可能是網絡在鬧脾氣。

**Q: 語音通話沒聲音？**  
A: 需要填 MiniMax 的 API Key。或者你的瀏覽器把音頻權限禁了。或者你耳機沒插。

**Q: 能部署到服務器嗎？**  
A: 能。`npm run build` 出來的 `dist` 文件夾丟到任何靜態託管就行。Vercel、Netlify、GitHub Pages，隨便。但記住：數據還是存在用戶本地，不是服務器上。

## 給想二改的人（開發者區域）

如果你想在這個基礎上加功能，先看這幾句話：

### 記憶系統已經做好了，別重複造輪子

**所有角色的長期信息**（人設、精煉記憶、印象檔案、世界觀書）都通過 `ContextBuilder.buildCoreContext()` 統一組裝。它會在每次 API 請求前自動生成一段完整的角色上下文，包含：

- 角色基礎設定（systemPrompt + worldview）
- 用戶檔案（你的名字、人設、關係標籤）
- 精煉的月度記憶摘要
- 角色對你的印象檔案（MBTI分析、喜好、情緒波動）
- 掛載的世界書內容

**短期記憶**（最近聊天記錄）直接走正常的 message history，和上面那段長期上下文一起塞進 API 請求。

這意味著：**角色能記起所有事**，不需要你額外寫記憶檢索邏輯。只要往數據庫裡存了，ContextBuilder 會自動幫你塞進 Prompt。

### 想加新 App？

1. 在 `apps/` 裡新建一個 `YourApp.tsx`
2. 在 `types.ts` 的 `AppID` 枚舉里加個 ID
3. 在 `constants.tsx` 的 `INSTALLED_APPS` 數組裡註冊（圖標、名字、顏色）
4. 在 `App.tsx` 的 `renderApp()` 里加 case
5. 完事。UI 風格參考現有的用 Tailwind + glassmorphism。

### 數據流

```
用戶操作 → OSContext（全局狀態）→ IndexedDB（持久化）
                    ↓
              Chat/App 組件讀取
                    ↓
            ContextBuilder 組裝 Prompt
                    ↓
              調用 LLM API
```

所有數據都是 **local-first**，沒有後端服務器這個概念（除了那個可選的雲端備份）。

### 右下角的 build badge 怎麼關

跑非 `main` / `master` 分支時，右下角會堆三行小字標記構建版本：

```
sw@<service-worker 版本>
<分支>@<commit hash>
開發中內容，不代表最終效果
```

這玩意叫 `BuildBadge`（`components/BuildBadge.tsx`），用來一眼區分線上版和 fork / 開發版，免得拿半成品截圖當正式版到處發。可見性在 **構建時** 決定：

| 情況 | 顯示？ |
|------|--------|
| 在 `main` / `master` 上構建 | ❌ 默認隱藏（視為正式發佈）|
| 其他分支上構建 | ✅ 默認顯示 |
| `VITE_HIDE_BUILD_BADGE=1` | ❌ 強制隱藏（覆蓋默認）|
| `VITE_SHOW_BUILD_BADGE=1` | ✅ 強制顯示（在 release 分支本地調試用）|

CI detached HEAD 狀態會按 `GITHUB_REF_NAME` → `VERCEL_GIT_COMMIT_REF` → `CF_PAGES_BRANCH` 順序識別分支，所以 Vercel / Cloudflare Pages / GitHub Actions 部署 release 分支會自動隱藏，不用手動配。

**注意**：這是 Vite `define` 注入的**編譯時常量**，不是運行時 env——`npm run build` 之後再設環境變量沒用，esbuild 那時候已經把 `__BUILD_BADGE_VISIBLE__` 直接幹成 `true` / `false` 常量、把整個組件樹搖掉了。要在構建命令前面加：

```bash
VITE_HIDE_BUILD_BADGE=1 npm run build
```

或者在 Vercel / Cloudflare Pages 的環境變量面板掛一條 `VITE_HIDE_BUILD_BADGE=1`，省得每次記。

> 叮叮叮！把 badge 藏了不會讓你的 fork 變正式版本，但截圖會乾淨點。

### 開發調試面板（DevDebugPanel）

非 release 分支構建時（即 `__BUILD_BADGE_VISIBLE__` 為 `true`），右下角除了 build badge 還會多一顆小扳手浮球。點開就是 **DevDebugPanel**——一個可拖拽的調試面板，專治"角色怎麼又不說話了"綜合症。

面板裡有兩類開關——**行為開關**（改變跑的邏輯）和**分類捕獲**（勾哪類抓哪類日誌）：

| 開關 | 類型 | 幹嘛的 |
|------|------|--------|
| **Skip Prompt Build** | 行為 | 跳過 `ContextBuilder` 的整套 prompt 組裝，直接把你的裸消息懟給 LLM。用來避免它被人設束縛、不配合你輸出你想要的調試內容 |
| **Skip Emotion Eval** | 行為 | 跳過消息落庫後的情緒評估管線（Russell 空間那套）。不需要調試情緒的時候可以打開（不配置日程也行）。 |
| **記錄 LLM 日誌** | 捕獲 | 勾上就錄製所有 LLM 請求/響應。密鑰字段自動 `<redacted>` 不用手動打碼。以後想抓別的（MCP 調用之類）就再加一個捕獲類，互不串桶 |

捕獲日誌同時寫 `localStorage` 和內存，各類混存、全局最多保留 100 條 / 1 MB（先到先淘汰）。為了省空間 / 隱私，**長文本默認寫入時就摺疊成前 10 字 + `...`**（那堆 system prompt 和聊天歷史不會塞滿 localStorage）；真要看完整請求體，打開「記錄完整內容」開關再復現一次。錄完可以**一鍵複製成 JSON** 或**下載成文件**丟給別人 debug，導出會自動帶上當前分支和 commit hash，方便定位"到底是哪個版本炸的"。

**注意**：跟 build badge 一樣，這整套調試 UI 走的是 Vite `define` 編譯時注入。在 `main` / `master` 上 `npm run build` 出來的產物裡，`DevDebugPanel` 組件連同相關代碼會被 esbuild 整棵樹搖掉，不會出現在生產包裡。換句話說——**用戶永遠看不到這個扳手，除非你故意在 release 分支 `VITE_SHOW_BUILD_BADGE=1`**。

> 想加新開關 / 加 debug-only 日誌？照著 [`docs/dev-debug.md`](./docs/dev-debug.md) 抄就行，裡面有逐步指南和容易踩的坑。

> 叮叮叮！調試面板不會讓你的 Bug 自動修好，但至少能讓你知道 Bug 在哪。大概。

### 聊天上雲走主動消息 2.0

聊天回覆想「發完就能鎖屏走人」，走的是主動消息 2.0 的即時對話：每個用戶自己部署一個 Cloudflare Worker（`worker/amsg/`），回覆在 Worker 上生成，再以 Web Push 送回手機。設計與端點契約見 [`plans/amsg2-instant-chat.md`](./plans/amsg2-instant-chat.md)、[`plans/amsg2-instant-chat-contract.md`](./plans/amsg2-instant-chat-contract.md)。

- **工具在 Worker 裡跑**：回憶、搜索、讀日記、小紅書這類數據標籤由 Worker 就地執行，客戶端不在線也能跑完（`worker/amsg/src/agentic.ts` + `classifier.ts`）。
- **副作用只識別不執行**：戳一戳、轉帳、日程、音樂、小紅書點贊這類標籤，Worker 結構化成 directives 掛在最後一條推送上；客戶端收到後由 `applyAssistantPostProcessing` 重放，複用本地聊天那套執行代碼。
- **收側與本地聊天對齊**：推送落庫後，`utils/activeMsgRuntime.ts` 的 `runPushTailPipeline` 跑跟本地聊天一致的尾段（記憶宮殿等）。

### ⚠️ 後端代理：二改請換成你自己的

項目是 local-first，但有些能力繞不開代理 / 簽名 / 跨域，走了 Cloudflare Worker。你 fork 直接跑會打在**作者帳號**上——流量額度都是作者的，用多了大家一起 429。所以二改請務必換。

**好消息**：現在**主代理已經統一成一個中心配置**，不用再滿倉庫改硬編碼。

**① 主代理 Worker**（默認作者公共實例 `sullymeow.ccwu.cc`，源碼單文件 [`worker/index.js`](./worker/index.js)）
覆蓋：聯網搜索 / 熱榜（Brave）、WebDAV 雲備份、GitHub 雲備份、Notion、飛書多維表格、麥當勞 / 瑞幸點單 MCP、網頁抓取、Fish Audio / ElevenLabs TTS、音樂生成、網易雲音樂（默認）。
👉 二改只要在 **「設置 → 網絡代理 (Worker)」** 填上你自己部署的地址，以上能力**一鍵全切走，不用改任何代碼**。（`wrangler deploy` 把 `worker/index.js` 丟自己 CF 帳號，拿到地址填進去即可。）

**② 還是獨立、要各自部署 / 配置的 Worker**：

| 功能 | 位置 | 說明 |
|------|------|------|
| 主動消息 2.0（含即時對話） | [`worker/amsg/`](./worker/amsg/) + 設置裡一鍵部署或填地址 | 每個用戶自己部署一個 CF Worker，教程見 [`docs/amsg2-setup-walkthrough.md`](./docs/amsg2-setup-walkthrough.md) |
| 主動消息推送 | `worker/proactive-push/` + `utils/proactivePushConfig.ts` | 同上，自己部署 |
| 小紅書 Lite | `worker/xhs-lite/` + 小紅書設置裡填地址 | 自己部署 |
| 網易雲音樂（可選覆蓋） | 播放器設置裡可單獨填 | 不填就跟隨主代理 |
