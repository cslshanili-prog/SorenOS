# 關係線 · 第 3 批：補齊還只認主線的地方

> 狀態：**3a、3b 已做**（2026-11-12）。上層見 [`persona-bond-redesign.md`](./persona-bond-redesign.md)，第 1、2 批見 [`persona-line-batch1-2.md`](./persona-line-batch1-2.md)。
> 第 1、2 批之後，私聊、通話、見面、記憶都照線走了；這批把「背景替角色做事」和幾個 App 裡還只看主線的地方補上，補完再打開「關係線預覽」開關。

## 已做

- **定時消息**（角色在聊天裡用 `[schedule_message]` 排的）：`ScheduledMessage.personaKey` 記在哪條線上排的，到點送回那條線。
- **未讀按線記**：`unreadMessages` 的鍵改成 `lineKey`（主線就是 charId，跟舊資料一樣）。訊息列表、切換鈕的未讀照線算；聊天頁只清這條線的未讀。桌面小組件等只看主線的地方照舊讀主線。

## 3a：本地的（不用動雲端）— 已做（2026-11-12）

- **主動消息 1.0**：每條線各自一個排程，非主線用 `lineScheduleId`（`c1~line~pB`）排，到點由 `runProactive` 拆回是哪條線，用那條線的視圖生成；訊息、未讀、改關係、拉黑、自訂數值都落在那條線。非主線的開關是 `proactiveLineEnabled`（**新線預設關**，Liora 2026-11-12 定案），頻率等其餘設定照主線。
- **延遲自動回覆**：待回清單按線記（同一個 id 規則）；在哪條線上排的就在哪條線上回。非主線先不交給雲端。
- **資料庫**：照「記憶只有一份」，照片不按線拆開——從私聊、見面、角色傳的照片記下 `personaKey`，在別條線上列給角色看時標「在你跟「B」那邊拿到的，「A」不一定看過」。
- **朋友圈**：角色認識的每張卡都算熟人（`PersonaKnowledge.knownKeysOf`），在角色貼文下互動時認識的卡都能選。
- **神經鏈接**：印象、月度總結、激活月份、手動整理／批次總結／導入的記憶片段，都照「現在的我」那條線；記憶片段清單只列這條線的。編輯頁照舊拿原角色卡自動存，但**不再整份寫回 `lines`**，非主線的改動由 `handleLineChange` 直接寫進那條線。
- **記憶宮殿手動區間總結**：區間裡混著好幾條線時按線分開提取（跟自動整理同一套）。
- **小小窩**：「你來訪」寫進私聊的紀錄落在現在的我那條線。
- **日記**（Notion／飛書）：「寫了一篇日記」那則系統訊息落在寫的那條線。

還沒處理的小地方：小小窩當天的歡迎語快取仍是角色一份（A 早上去過、B 下午去會看到同一句）；桌面小組件的未讀只看主線。

## 3b：雲端（主動消息 2.0、即時對話）— 已做（2026-11-12）

做法：**把非主線當成雲端的另一個角色 id**（`c1~line~pB`，跟排程 id 同一套），雲端 Worker 完全不用改、不用重新部署。工具都在 `utils/amsgCloudLine.ts`。

- **主動消息 2.0 的設定照線**：`activeMsg2Config` 是跟著線走的欄位。這條線還沒存過自己那份時，視圖先照主線的頻率、額度、單獨 API，但**開關關著、沒有任務**（`seedLineAmsgConfig`）；存一次之後就是這條線自己的一份。即時對話的單獨開關也照主線起步，所以全局開著即時對話時，新線的聊天照樣上雲。
- **上傳**：排任務、`fire_pack`／`tool_pack`／`limits`、憑據行（`char:<雲端 id>/chat` 這類）、即時對話、延遲回覆交雲端、「正在聊天」心跳、作廢回執台帳，雲端 id 一律寫 `cloudCharId(char)`；讀私聊照舊 `lineArgOf(char)`。`fire_pack` 照那條線的視圖打包，身份是那條線的卡。
- **收件**：收件箱、`chat_outbox` 補收、錯誤推播、狀態點名拿到的 charId 用 `findCloudChar` 找回那條線的視圖。訊息落在那條線、未讀記在那條線；角色自排／取消的任務寫進那條線的清單（`cloudCharPatch`）；拉黑判斷看那條線。DB 讀寫私聊也認得這種 id（`asLine`／`saveMessage` 會拆開），漏接的地方也不會寫錯線。情緒是角色本人的，照舊只有一份。
- **點通知、全局橫幅**：帶著雲端 id 打開時先切到那張卡，聊天頁開在那條線上。
- **批量的路徑**（全角色打髒、改了角色資料、換 API Key 刷任務、啟動補傳）：把每個角色展開成主線＋存過自己 2.0 設定的線（`cloudLineViewsOf`）。
- **刪角色**：主線加每條線的任務、上下文、憑據一起清（`purgeCharAllLinesCloudState`）。導入備份時，主人還在新檔裡的線不算孤兒。設定裡的「雲端資料」清單會標「阿澈（跟「老婆」）」，不會被當成本地已經刪掉的角色。
- **MCP「只給哪些角色」**：上傳 `tool_config` 時把勾了的角色展開成它名下每條線的雲端 id（`expandCharIdsWithLines`），Worker 比得上，非主線在雲端也有 MCP。
- 1b 加的「非主線不上雲」（`chat-line`）和延遲回覆「非主線不交雲端」都拿掉了。

## 收尾：查手機、家園 — 已做（2026-11-12）

現況：兩邊都只認主線——身份照主線解析、讀的是主線的私聊、寫進私聊的卡片也落在主線。

### 查手機

手機是角色本人的，只有一支；會變的是「誰在偷看」。

1. **用哪個身份偷看**：照私聊同一條規則，用「現在的我」（`activeLineFor`）。角色認識這張卡就是那條線：給角色看的「你們最近的聊天」讀那條線、偷看被發現的卡片（刪好友、拉黑那張）落在那條線；角色不認識這張卡就照舊走主線。
2. **角色手機裡的其他身份**：角色認識的其他卡，本來就是它生活裡真的人，應該出現在它手機裡——
   - 通訊錄裡是一種新的聯繫人「身份卡」（不是生成的、也不是 NPC），點進去看到的是**那條線真實的聊天紀錄**（唯讀），不是 AI 編的。
   - 生成通訊錄、聊天列表時告訴模型這幾個人已經在了，別再虛構一份。
   - 偷看本身照舊是秘密：角色不會因為你看到它跟另一張卡的聊天就察覺（跟現在一樣，只有刪好友、拉黑會被發現）。
3. **真角色之間私聊**（A 跟 B 背著你聊）：B 那邊的「你」也照 B 認不認識現在這張卡來定，不再一律拿 B 的主線。

### 家園

家園是你不在場、角色各過各的生活。

1. **世界裡的「你」**：用這個世界指定的身份（世界預設）；角色認識那張卡就是那條線，不認識就照舊主線。演繹時讀的私聊、事後寫進私聊的世界卡片（`world_card`）都走那條線。
2. **角色認識的其他卡**：在提示詞裡提一句「你也認識的 X，是另一個人」（跟現在同世界不同身份那句提醒同一套），免得角色演生活時把兩個人混成一個，或完全忘了另一個人存在。

### 定案（Liora 2026-11-12）

對用戶來說哪張卡都是自己，只有角色「發現」時才有「是哪個身份做的」——也就是替他刪好友、拉黑那類動作。所以：

1. 角色跟其他身份卡的聊天**都看得到**（唯讀、角色不知道）。通訊錄最上面一區列出角色認識的其他卡，點進去是那條線真實的私聊；生成出來同名的聯繫人不再重複列。
2. 家園照建議：居民所在世界（分組）的世界預設身份，角色認識那張卡就走那條線（`worldLineView`），沒設或不認識照主線。

另外：從家園把動態轉到私聊，是你現在做的，落在「現在的我」那條線。
