# 劇情 · 好幾個「你」同場

> 狀態：**已定案**（Liora 2026-11-19：第 8 節三點照建議），分四批做。**第 1～3 批做完**（2026-11-19，實況見第 10 節），第 4 批（好感度）還沒做。照 `CLAUDE.md` 第一句規劃：故事能呈現最完整的狀態，不替用戶省 token；工大就分批，目標是完整版。
> 上層：[`persona-bond-redesign.md`](./persona-bond-redesign.md)（關係線）、[`persona-line-batch5.md`](./persona-line-batch5.md)（群聊裡好幾個身份同場）。

Liora 的話：「劇情其實就是線下群聊。用戶一是妹妹、用戶二是姊姊，一家人出門卻一次只能一個出場，有夠怪。」

所以這份的原則只有一條：**劇情照線下群聊做，口徑跟第 5 批同一套**。在場的你可以好幾個；每個角色照自己認不認識看每個你；記憶跟著線走。

## 0. 現在的樣子，和當初為什麼沒做

- 一條劇情一個執筆身份（`StoryTheaterEntry.mask`），三選一：本人、演某個角色、自訂面具。
- 9 月定多身份範圍時（`multi-persona-isolation-design.md`），劇情被歸在「你是作者／觀眾」那類，理由是「它有面具」，寫了不動。後來群聊做多身份同場只做了線上群聊。
- 結果劇情從頭到尾沒接關係線：
  - 「本人」是全域當前那張卡，不看這個角色認識哪張。
  - 每個角色帶進來的最近聊天和記憶召回一律是主線。
  - 寫回記憶（陪伴模式）的鏡像訊息沒記身份，一律落主線。
  - 提示詞只有一個「你」，`{{user}}` 只有一個名字，「你」的資料只給簡介。
  - 開始之後身份就鎖住，不能換。

## 1. 在場的你

### 1.1 資料

```ts
// types.ts
export type StoryTheaterMaskSelection =
    | { type: 'user' }                    // 舊資料：全域當前那張卡。新的不再寫這個
    | { type: 'persona'; key: string }    // 新：某張身份卡（真實身份是 REAL_IDENTITY_PERSONA_ID）
    | { type: 'character'; id: string }   // 你演某個角色
    | { type: 'custom'; id: string };     // 自訂面具

// StoryTheaterEntry
/** 在場的你。[] ＝ 旁觀（你只當作者）；沒有這個欄位 ＝ 舊劇情，讀 mask 當成一個 */
presence?: StoryTheaterMaskSelection[];
```

- 解析只有一個口：`resolveStoryPresence(entry, profileBase, characters, masks)`，回每個在場的你的名字、頭像、簡介、補充設定、身份鍵。舊的 `mask` 讀成一個；舊的 `{ type: 'user' }` 讀成當下的全域身份。
- 身份卡、面具、你演的角色可以混著選，不限幾個。
- 刪身份卡、刪面具時從每條劇情的 `presence` 拿掉（跟 `groupPresence` 同一處清）。

### 1.2 中途能換

現在劇情一開始身份就鎖住。改成隨時能改：姊姊先回家了，就把她從在場拿掉。

- 每段訊息記當時的在場：`metadata.theaterPresent`（`{ key, name }` 一串，key 是 `persona:<身份鍵>`／`mask:<id>`／`char:<id>`，名字一起存，之後卡改名或刪了還標得出來）。之後歸線、標名字都照訊息上記的，不照現在的設定。
- 在場換了的那一輪，提示詞多一句「『姊姊』這一輪起不在場」或「『姊姊』這一輪起在場」，只說一次。

### 1.3 這段是誰寫的

在場兩個以上時，輸入框上面多一排頭像：這段主要是誰。可以點好幾個，預設跟上一段一樣。

- 記 `metadata.theaterWriters`（同上的格式）。「繼續」那輪沒有人執筆，只記在場。
- 用途有兩個：歷史裡那段標「（執筆：妹妹、姊姊）」；角色認識好幾個在場的你時，照它決定主看哪條線（見 2.2）。

### 1.4 旁觀

一個都不選就是旁觀：你只當作者，寫旁白和導演指示，角色們演自己的戲。提示詞那段換成「這場戲裡沒有用戶側的人物在場」。

## 2. 每個角色怎麼看在場的你

照第 5 批第 3 節，每位演員算一次。認識的＝在場的身份卡 ∩ 它有線的卡。

### 2.1 認識一個

用那條線的視圖（`lineView`）建角色檔案：關係、印象、月度總結都是那條線的。帶進來的最近聊天是那條線的，記憶召回用那條線。

這一條順便修掉現在的問題：角色認識的不是全域那張卡時，劇情裡拿到的是別人的聊天和記憶。

### 2.2 認識好幾個

- **主看的那條線**：它認識的卡裡，最近執筆的那張；都沒寫過就主線，再不然第一張。角色檔案照它建。
- **其他認識的在場卡，每張都做足**：那條線的印象、長期記憶、空窗期各補一段「你也認識在場的『姊姊』」；那條線的最近聊天併進時間線，標 `[私聊·姊姊]`；**記憶召回每條線各做一次**。
- 召回回來的每筆照舊標「這是你跟誰之間的事」。

### 2.3 不認識

- 它眼中是在場的另一個人：名字、頭像描述、簡介、補充設定。
- 身份連結照第 4 批：同一世界有連結的，認識其中一張就告訴它「在場的『妹妹』和『姊姊』是姊妹」（`presentLinkLines`）。小號的，它知道是同一個人才說。
- 它私下認識的那張卡不在場：那條線的聊天不併，角色檔案照主線建，並說明「你私下認識的『X』這場戲不在」。
- 戲後不自動算認識（跟群聊一樣）。那場戲的正文會寫進它的記憶，所以它記得見過這個人。

### 2.4 面具、你演的角色

- 自訂面具：誰都不認識的原創人物，資料照面具（設定、核心性格、世界觀）。
- 你演的角色：照舊帶它自己的記憶和最近聊天給模型參考，現在可以好幾個。

### 2.5 幕後須知

演員私下認識的人不是同一張卡時，加第 5 批後續那段：誰私下認識的是誰，只列名字，不透露卡跟卡的連結。邏輯共用 `utils/groupChat/knownPeople.ts`。

## 3. 共用的提示詞

- **「用戶側執筆身份」那段**改成清單，每個在場的你一塊：名字、簡介、**補充設定**（現在劇情只給簡介，這次補上）、面具的核心性格與世界觀。
- **不准代寫**那條改成複數：這幾位都是用戶親自執筆的人物，續寫不得替任何一位做重大決定。
- **`{{user}}`**：一個人時原樣；好幾個時填「妹妹、姊姊」。劇情預設裡的句子是「不得替 {{user}} 做決定」這類，串起來通順。另外給預設作者兩個新巨集：`{{users}}`（同上）、`{{user_count}}`。
- **歷史**：在場只有一個、而且所有段落都是他寫的，照舊；其他情況每段標執筆的是誰。
- **只有一個人在場時，送出去的提示詞跟現在一字不差**，用測試鎖住。

## 4. 寫回記憶（陪伴模式）

陪伴模式現在強制用本人。改成：可以選好幾張身份卡，不能選面具或演角色（寫進真實記憶的必須是真的你）。

### 4.1 鏡像訊息落哪條線

現在每段正文鏡像一份到每個演員的主線。改成每個演員各自算：

| 這個演員 | 鏡像落在 |
|---|---|
| 認識的卡有在場 | 它認識、而且那一段在場的**每條線**各一份 |
| 一個都不認識 | 主線，標「同場的是『妹妹』『姊姊』，不是你私下認識的那位」 |
| 旁觀（沒有你在場） | 主線，標「用戶不在場的線下戲」 |

之後不管用妹妹還是姊姊跟它私聊，往上翻都看得到那天一起出門的原文。姊姊先回家之後的段落，不會出現在姊姊那條線。

同一段的幾份鏡像記同一個 `theaterCentralId`，改正文、重新生成、刪除時一起動（現在的 `theaterMirrorIds` 從「演員 → 一個 id」改成「演員 → 每條線的 id」）。

### 4.2 記憶宮殿

- 同一段在好幾條線都有鏡像時，只從主看的那條線抽一次記憶，別的線的鏡像標記跳過，免得同一件事記成兩筆。
- `MemoryNode` 多一個 `withPersonaKeys`：同場還有哪幾張它認識的卡。召回時標「這是你跟『妹妹』『姊姊』一起的事」。
- 抽記憶時給模型的用戶名照線的名字（管線已經支援）。

### 4.3 舊資料

以前寫進主線的鏡像不動、不搬。舊劇情沒有 `presence`，讀成一個人，行為跟現在一樣。

## 5. 好感度

現在每個演員一格：角色對你、你對角色。改成每個演員 × 每個在場的你各一格。

- 模型輸出的好感面板：每個角色底下分對象（對「妹妹」、對「姊姊」）。舊格式照舊能解析，當成對第一個在場的你。
- 你這邊每輪能填的「你對角色的變化」：先選是哪個你，再填。
- 面板介面：角色底下列每個你一行。

## 8. 已定案（Liora 2026-11-19：「三點就照你的建議」）

照原則直接定的：陪伴模式開放多選；認識幾條線就召回幾次；不認識的卡也給完整資料。

1. **旁觀：要**（1.4）。跟群聊一致，角色們自己的戲也能演。
2. **戲後不自動算認識**（2.3）。跟群聊一致：正文已經進它的記憶，它記得見過；要它「認識」姊姊（有自己的私聊線、印象）自己再去加。沒選的另一種：劇情頁每個演員旁邊給一顆「這場戲之後認識『姊姊』」。
3. **主看的線：最近執筆的那張**（2.2）。跟群聊一致。沒選的另一種：固定主線。

## 9. 順手會碰到的

- 劇情客串的舊 NPC 那條路（`npcIds`、`buildTheaterNpcContext`）：配角搬家時客串已經併進演員，搬完的人用不到。程式留著給還沒搬的，跟 `plans/todo.md` 第 3 條一起清，這次不動。

## 10. 實況

### 第 1 批：在場與提示詞（2026-11-19 做完）

- **純邏輯在 `utils/storyPresence.ts`**：`resolveStoryPresence`（解析、濾已刪的、去重、全濾光回全域那張、空的是旁觀）、`togglePresenceSelection`（多選頁點一下）、`storyPromptIdentityName`（`{{user}}` 填什麼）、`storyYouLabel`、`defaultWriterKeys`／`resolveWriters`（這段是誰）、`presenceMetadata`、`presenceChangeNote`（在場換了的提醒）。劇情裡要知道「你是誰」一律從這裡拿，別再直接讀 `entry.mask`。
- **資料**：`StoryTheaterMaskSelection` 多一種 `{ type: 'persona', key }`，`StoryTheaterEntry.presence`。舊的 `mask` 欄位留著，跟著是第一位。`normalizeStoryTheater` 會整理 `presence`。
- **提示詞**（都在 `utils/storyTheater.ts`）：`buildTheaterPersonas`、`buildStoryIdentityGuard` 多一個參數（好幾位、旁觀各有自己的寫法）、`formatStoryHistoryText`（原本寫在對話頁裡的那段搬出來）、巨集 `{{users}}`／`{{user_count}}`。
  - **一位、沒填補充設定時，送出去的跟以前一字不差**，`utils/storyPresence.test.ts` 拿舊的 `buildTheaterPersona` 當對照鎖著。填了補充設定就多一行，這是這批要的。
  - 在場換了的那一輪多一段 system 提醒。
- **介面**：面具箱改成多選（身份卡每張列出來、你演的角色、原創人物，有搜尋，頂上寫在場幾位、能一鍵改成旁觀）；編輯頁那顆「你」開始之後不再鎖（誰先落筆、真實／虛構模式照舊鎖）；對話頁頭像疊著放、在場兩位以上輸入框上有「這段是誰」、旁觀時有一行說明；每段你寫的照執筆者標名字；列表與匯出同理。
- 你演的角色：勾了從演員名單拿掉，取消會放回去（以前切走不會放回）。

**跟設計稿不一樣的地方**

- **寫進角色記憶的劇情（真實時間陪伴）這一批還是只能本人**，多張身份卡同場在第 3 批（要先有鏡像分線）。所以現在「一家人出門」要在虛構劇場裡才選得到好幾個。
- 刪身份卡、刪面具時**沒有**去改每條劇情存的 `presence`：解析時會濾掉已刪的，結果一樣，不必多寫一輪資料庫。
- **好感度**還是每個角色一格。在場好幾位時多一段提醒說明這一輪的 U 指誰（執筆的第一位），第 4 批換成每位各一格。旁觀時好感度整套不跑。

### 第 2 批：角色各自怎麼看（2026-11-19 做完）

只對「帶角色記憶」的劇情有作用（真實時間陪伴，或虛構劇場開了攜帶記憶）。不帶記憶的虛構劇場裡演員只有設定，沒有「認識誰」這回事。

- **認識誰、主看哪條線**在 `utils/storyActorView.ts`：`storyActorPresence`（共用群聊的 `memberPresence`）、`focalStoryKey`（最近執筆的 > 主線 > 第一張，照訊息上記的 `theaterWriters`）、`buildStoryActorPresenceNote`（「在場的人你認識誰」那段）、`buildStoryKnownPeopleNote`（幕後須知，共用群聊的 `membersKnownPeople`）。
- **一個演員的檔案塊怎麼組**在 `utils/storyActorContext.ts` 的 `buildStoryActorBlock`：讀資料庫、召回、組核心人設由對話頁給進來，這裡決定照哪條線、放哪幾段、聲明寫什麼，有測試。
  - 主看的那條線用 `lineView` 建檔案；最近聊天讀那條線的；記憶標籤照那條線。
  - 其他認識的在場卡：那條線的印象、長期記憶放進「你也認識在場的某某」，那條線的最近聊天另起一塊。
  - 不認識的在場卡：說明是另一個人；有身份連結的照它知道的說（`presentLinkLines`）。
- **記憶那兩段的歸屬聲明**（`buildStoryActorMemoryEnvelope`、`formatActorRecentMessages`）多一個參數：好幾個你同場時說清楚記憶裡的「你」是在場的哪一位；它認識的那位不在場時說不得改綁到在場的人。
- **只有一位在場、是它認識的、它只有一條線時，送出去的跟以前一字不差**：實測同一條劇情在改之前和改之後送出的整份請求逐字相同。

**順手修掉的**

- 以前不管角色認識誰，檔案和最近聊天都拿全域那張卡去配主線。角色認識的不是全域那張時，現在會拿對的那條線。
- 你演的角色：它記憶裡的「你」改成它自己認識的那位（以前寫成全域那張卡的名字）。
- 旁觀時，演員的記憶聲明以前會寫成「當前執筆身份是『作者』」，改成它認識的那位不在場。

**跟設計稿不一樣的地方**

- **沒有每條線各召回一次。** 記憶宮殿只有一份，一次召回本來就把每條線的事都找出來，再召回一次只會拿到同一批。真正缺的是標籤：劇情以前沒有標「這是你跟誰之間的事」，這批接上了（`memoryLineLabelsFor`，照主看的線）。
- **沒有把別條線的聊天併進同一條時間線標 `[私聊·姊姊]`。** 劇情不像群聊有一條合併的時間線，改成每條線各一塊最近聊天，標題寫明是跟誰的。
- **沒放私聊空窗期。** 那是線上才有意義的東西，劇情是面對面，虛構劇場的時間也不是現實時間。
- **在場的卡一張都不認識時，照樣帶它自己主線的最近聊天和記憶**，只是聲明改成「那位不在場」。設計稿原本寫不併；但劇情一直都是帶著的，拿掉角色等於失憶。
