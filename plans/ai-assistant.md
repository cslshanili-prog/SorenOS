> 狀態：第 1 批（答疑）已做，實況見第 9 節；第 2 批（美化 CSS）已做完，實況見第 10 節；第 3 批（預設＋正則）已做完，實況見第 11 節末；第 4 批（世界書＋小組件）已做完，實況見第 12 節末。四批都做完了。第 2 批 Liora 定了：預覽先做白框和氣泡、可以傳圖給 Sore、八處都放捷徑、快照不進備份。Liora 已定：桌面 App＋各處捷徑；寫入前先給你看、按「套用」才寫，寫前留快照可還原；第一版做答疑＋美化 CSS；API 設定裡可選，預設用副 API。名字叫 **Sore**：有點幽默毒舌、隨意、偶爾用 emoji、像朋友聊天、簡短不囉嗦。頭像先用佔位圖。

## 1. 要做什麼

一個內建的小助手，用戶用說的就能：

- **答疑**：怎麼用、設定在哪、為什麼角色不說話／主動消息不來、API 報錯看得懂。
- **美化**：「把聊天頂欄改成奶茶色、加一點蕾絲」→ 助手讀現在的 CSS、寫新的、先預覽，用戶按套用才寫進去。
- 之後的批次：寫預設條目和正則、世界書、桌面小組件。

它是工具，不是角色：不進記憶宮殿、不排主動消息、不跟角色的設定混在一起。

## 2. 參考 FloraOS「小卷」

FloraOS（`lib/mascot-*.ts`、`lib/qa-agent-engine.ts`）：

- 一個常駐助手＋一個答疑 App。工具分「套件」（CSS、圖像、角色卡、世界書、預設、正則、狀態欄、桌面組件、特調），要用哪套才展開那套的工具說明，省 token。
- 原生 function calling 和文字協議兩套都支援；agent 循環由畫面驅動（讀工具自動跑、跑完把結果回給模型）。
- 每個寫入工具都有格式檢查（例如狀態欄契約沒有成對標籤就拒絕）。
- 答疑的知識是一份手寫的產品知識全量放進系統提示詞，專題文件照關鍵詞再附加。

Soren 照這個思路，但：

- **只用文字協議**：很多人用中轉，原生工具支援參差不齊；Soren 角色的動作本來就是文字標籤，解析和容錯有經驗。
- **寫入一律走「提案卡片」**：助手不能直接寫，只能提案；用戶按套用才寫（Liora 定的）。

## 3. 畫面

- **桌面 App「助手」**（名字待定）：一個聊天頁。對話存在本機（新表 `assistant_sessions`，可以開新對話、刪掉舊的）。
- **提案卡片**：助手要改東西時，在對話裡出一張卡片——改哪裡（「聊天白框 · 全域」）、改之前／之後（CSS 給差異或全文、可以展開）、**預覽**（美化類開一個小窗套上看效果）、**套用**、**不要**。套用後卡片變成「已套用 · 還原」。
- **快照**：每次套用前把那個位置原本的內容存一份，跟著那張卡片存在對話裡（`AssistantProposal.snapshot`），「還原」就是寫回去。沒有另開表：卡片在、快照就在；刪掉對話快照也跟著沒了。不進備份。
- **各處捷徑**：白框 CSS 編輯器、氣泡工坊、見面畫面美化、心象卡片設定、交換日記／日程外觀、預設 App（第 2 批起）放一顆「請助手幫忙」：點了打開助手，帶上「我在改哪裡、現在的內容」，助手第一句就知道要做什麼。
- **設定**：助手用哪組 API（預設副 API → 全域）、模型建議（寫 CSS 用聰明一點的）。

## 4. 工具（文字協議）

模型在回覆裡寫：

```
<tool name="讀取CSS">{"location": "chat_chrome_global"}</tool>
```

- **讀的工具**：畫面自動執行，把結果回給模型再讓它接著寫（一輪最多 6 次，超過就停下來請用戶看）。
- **寫的工具**：不執行，變成提案卡片。用戶按套用時才真的寫，寫之前再跑一次格式檢查。
- 解析容錯：標籤沒閉合、JSON 有尾逗號、用了全形引號，照聊天標籤那套兩層容錯；解析不出來就把原文當普通回覆。

## 9. 實況：第 1 批（答疑）

- 桌面 App「Sore」（`apps/AssistantApp.tsx`，`AppID.Assistant`）：聊天、對話列表（新對話、刪除）、設定（用哪組 API）。空的時候有幾個建議問題可以點。
- 對話存在 `assistant_sessions` 表（DB v80，`DB.getAssistantSessions` / `saveAssistantSession` / `deleteAssistantSession`）；只在這台裝置，**不進備份**（答疑紀錄沒什麼好留的；之後的寫前快照要不要進備份，第 2 批再定），也不進記憶宮殿。

- 引擎：`utils/assistant/engine.ts` 的 `runSoreTurn`。文字協議（`utils/assistant/protocol.ts`）：模型寫 `<tool name="X">{json}</tool>`，結果用 `<tool_result>` 當 user 回給它；一輪最多叫 6 次工具，超過就叫它先停下來講目前查到的。容錯：標籤沒閉合、JSON 尾逗號、全形引號、少一個 `}` 都收。
- 工具（`utils/assistant/tools.ts`，第 1 批都是讀，全部自動跑）：查看設定概況（只回有沒有設、模型名，Key 一律只說有／沒有）、測試API（真的打一次很小的請求，全域或副 API）、讀說明（`utils/assistant/knowledge.ts` 的專題，MCP 那篇直接讀 `docs/mcp-user-guide.md`）。
- 知識：`SORE_BASE_KNOWLEDGE` 每輪都帶（功能版圖、首次設定、排查方向、「使用幫助」的常見問題，常見問題搬到 `utils/faqData.ts` 兩邊共用）。**改了 App 的行為（設定在哪、按鈕叫什麼），這裡要跟著改**，不然 Sore 會指錯路。
- 打 API：`utils/assistant/client.ts`。錯誤訊息一律過 `scrubSecret`（整串 Key、前後 12 碼、`sk-…` 長字串都換成 `[Key]`），不讓 Key 進到 Sore 的上下文；回覆只剝 `<think>` 這類有標籤的思考，不用 `stripLeakedReasoning`（那是給角色台詞的，會把 Sore 正常說的「我先看一下」剝掉）。
- 畫面上工具結果只顯示一行小字（🔍 查看設定概況），內容只給模型看。
- 埋點：`向Sore提问`（入口）、`切换Sore的API`（选择），見 `docs/analytics.md`。
- 測試：`utils/assistant/assistant.test.ts`、`utils/assistant/client.test.ts`。

## 11. 第 3 批設計：預設＋正則

### 現況（寫之前摸清的）

- 通用預設（`meeting_presets`，`MeetingPresetDoc`）：ST 格式，條目照送出順序排；**資料佔位條目**（`slot`，角色資料、聊天記錄、Soren 的記憶／表情包…）內容由 Soren 填，只能開關、排順序，不能刪、不能改內容。
- 正則（`regexScripts`，ST 欄位）存在預設裡，**目前只在見面生效**；私聊、群聊、電話用自訂預設時正則不跑。
- 劇情專用預設（`story_theater_presets`）：引擎靠固定條目 id 跑分區、快捷選項，id 不能動。
- 「內建」不是一份存著的預設，要改得先「複製內建」成一份新的。
- 一份預設可能同時被好幾個角色、群、場景預設用著。

### 工具

讀（自動跑）：
- `列出預設`：每份的名字、適用場景、條目數、正則數、誰在用（場景預設、哪些角色／群）。
- `讀取預設`：一份的概況，**不含條目全文**（ST 預設常有幾十條、幾萬字）：每條的 id、名字、開關、角色、是不是資料佔位、字數、插在哪；生成參數；正則清單。
- `讀取條目`：一條的全文（或一個正則的全部欄位）。

寫（出提案）：
- `改預設`：一份預設的一串操作，一張卡片：改條目（內容、名字、開關、角色）、加條目、刪條目（佔位不能刪）、排順序、改生成參數；加／改／刪正則（`parseStRegex` 檢查寫法）。
- `新建預設`：從內建（私聊／群聊／電話／見面）複製或空白開一份，可以同時帶上一串修改。還原＝刪掉。

卡片：列出每個改動（「改了『文風』+120 字」「關掉『表情包』」「新增正則『去掉星號』」），可展開看改前改後；寫明「這份正在被誰用」。快照是整份預設改前的樣子，還原就整份寫回。

### Liora 定了（2026-11-14）

1. **正則先只在見面生效**：Sore 寫正則時要講清楚只有見面會跑；私聊／群聊／電話跑預設正則另外排一批（牽涉落庫、顯示、雲端）。
2. **劇情專用預設能改條目內容**：能讀、能改既有條目的內容和開關、生成參數；不能加刪條目、不能改 id。
3. **共用的預設直接改**：卡片上列出「這份正在被誰用」（場景預設、哪些角色／群），看了再決定套不套；不喜歡一鍵還原。
4. **Sore 能幫你設誰用這份**：一樣是提案（場景預設、某個角色的私聊／電話／見面預設、某個群的預設），還原設回原本的。

### 實況（第 3 批做完）

- 純邏輯：`utils/assistant/presetOps.ts`。找預設（名字或 id，同名要 id；內建要先複製）、誰在用（`presetUsage`：場景預設、角色的私聊／電話／見面、群、劇情劇場）、概況（不含條目全文，標出資料佔位和 Soren 功能、關掉功能的後果）、讀一條全文。
- 套操作都在**副本**上（`applyGeneralOps`／`applyStoryOps`），回改好的整份＋改動清單（內容改動帶改前改後）；出錯就整批不出卡片，讓 Sore 改好再送。通用預設的操作：edit、add、remove、move、params、rename、prefill、scenes、addRegex、editRegex、removeRegex（`parseStRegex` 檢查寫法、placement 用 user／ai／worldinfo／reasoning）。資料佔位、Soren 功能只能開關和排順序。劇情預設只有 edit（內容、開關，佔位和區塊邊界只能開關）、params、rename、prefill。
- 新建：從私聊／群聊／電話／見面／劇情內建、空白劇情，或一份既有預設複製（`buildNewPreset`），新 id 先產好放在卡片上。
- 誰用這份（`parseBindings`）：場景預設、角色的私聊／電話／見面、群；劇情預設只能設成劇情場景預設。通用預設的「適用場景」沒勾到要用的場景，會順便勾上（選單裡才看得到）。「設定預設用途」也能設成「內建」或「跟著場景預設」。
- 工具：列出預設、讀取預設、讀取條目（讀）；改預設、新建預設、設定預設用途（提案，三個都能帶 `use`）。
- 提案（`AssistantPresetProposal`，提案型別改成 CSS／預設的聯合）：整份改好的預設、改動清單、出提案時誰在用、綁定。卡片列出每個改動（有改前改後的可以展開），有人在用就寫「這份正在被…用，改了這些地方都會跟著變」。
- 套用、還原（`applyPresetProposal`／`restorePresetProposal`）：套用前記下整份原樣（新建的記 null）和每個綁定原本的值；還原整份寫回、綁定設回去，新建的刪掉。套用後那份又被改過，還原前先問。存通用預設會發 `MEETING_PRESET_UPDATED_EVENT`（見面畫面重讀、雲端打髒）。
- 捷徑：通用預設編輯頁（`MeetingPresetManager` 頂欄）、劇情預設編輯器（自訂的才有）都有「請 Sore 幫忙」，交接的 location 是 `'preset'`，Sore 第一句就知道是哪份。
- 預設條目的名字表搬到 `utils/meetingPreset/slotLabels.ts`，編輯頁和 Sore 共用。
- 埋點：`处理Sore的提案` 的位置加上 通用预设／剧情预设，`从捷径找Sore` 加上 预设。
- 測試：`utils/assistant/preset.test.ts`。

## 12. 第 4 批設計：世界書＋桌面小組件

### 現況

- 世界書（`Worldbook`，照 ST 欄位：關鍵詞、常駐、位置、深度、順序…）以「組」（category）分組；寫入一律走 `DB.mutateWorldbooks`（同一個事務順便更新掛了它的角色緩存），新增走 `addWorldbook`。
- 掛給角色＝角色的 `mountedWorldbooks` 加一份（`toMountedWorldbook`）；整組「全局啟用」＝那組每條寫 `global`，所有角色都讀得到。
- 桌面自訂小組件：模板存 `OSTheme.launcherCustomWidgets`（HTML＋CSS＋欄位＋圖片鍵，佔位符 `{{time}}`、`{{char}}`…），在沙盒 iframe 裡跑（可以有 script，拿不到 Soren 的資料）；放上桌面是另一步（`addCustomWidget` 找空位）。

### 工具（草案）

讀：`列出世界書`（每組條目數、全局沒、誰掛了）、`讀取世界書`（一組或一條的全文和觸發設定）、`列出小組件`、`讀取小組件`（HTML／CSS／欄位）。
寫（提案）：`改世界書`（一組裡加條目、改條目、刪條目、整組改名、全局開關、掛給／取消掛給角色）、`寫小組件`（新建或改一個模板；可以順便放上桌面）。
卡片：世界書列出每條改動（新條目可展開看內容和觸發設定）；小組件卡片可以「預覽」（沙盒 iframe 照尺寸畫出來）。快照：改到的條目原樣、角色掛載原樣、模板原樣。

### Liora 定了（2026-11-14）

1. **世界書不能刪**：Sore 只能加、改、停用（`disable`）；要刪自己去世界書 App。取消掛給某個角色可以（不是刪條目）。
2. **小組件套用時可以順便放上桌面**：卡片上勾「放上桌面」，放在第一個放得下的空位（滿了就加一頁）；不勾就只存模板。
3. **Sore 能讀角色人設**：多一個「讀取角色」工具（描述、人設、世界觀、掛了哪些世界書），不讀聊天記錄和記憶。
4. **小組件可以帶 script**：跟匯入的小組件同一個沙盒；卡片標出「有程式」。

### 實況（第 4 批做完）

**世界書**（`utils/assistant/worldbookOps.ts`）
- 工具：列出世界書（每組條目數、停用幾條、全局、掛給誰）、讀取世界書（一組的每條觸發／位置／開頭；給 entry 是全文）、讀取角色（簡介、人設、世界觀、掛了哪些；不給聊天和記憶，太長截在 6000 字）、改世界書（提案）。
- 一張卡片只動一組。ops：add（沒給 keys 就常駐；其他預設值跟世界書 App 新增時一樣）、edit、disable／enable、rename（不能併到既有的組）、global（整組全局）、mount／unmount（不給 entries＝整組）。delete／remove 一律擋，回「請用戶自己去世界書 App」。加進全局組的新條目跟著全局。
- 提案（`AssistantWorldbookProposal`）：新條目（id 先產好）、既有條目要改的欄位、角色掛載的加減、改動清單。
- 套用（`applyWorldbookProposal`）：新增走 `addWorldbook`、改走 `updateWorldbook`（同一事務順便同步角色緩存、全局的會打髒所有角色）、掛載走 `updateCharacter` 寫 `mountedWorldbooks`；寫掛載時已經掛著的條目換成改完的版本，不然會蓋掉事務剛同步的那份（測試抓到過「整組掛載時沒改到的條目被漏掉」，已修）。
- 還原：刪掉 Sore 加的那幾條（撤銷不算違反「不能刪」）、改過的欄位寫回原值、角色掛載回原樣。

**桌面小組件**（`utils/assistant/widgetOps.ts`）
- 工具：列出小組件（尺寸、欄位、有沒有程式、桌面上幾份）、讀取小組件（HTML／CSS／欄位／圖片鍵）、寫小組件（提案）。
- 寫：新的給 name、size（1x1～4x4 那八種）、html、css、fields；改既有的只給要改的（html／css 整段取代）。欄位走 `normalizeFields`，鍵撞內建佔位符就擋；HTML 上限 6 萬字、CSS 4 萬字。可以帶 script（沙盒 `allow-scripts`，拿不到 Soren 的資料），卡片標「有程式」。Sore 給不了圖：改既有的圖片照舊，新的沒有圖。
- 卡片可以預覽：沙盒 iframe 照格數大小畫（欄位用預設值）。
- 放上桌面：新的預設放（`place: false` 就只存模板）。桌面版面跟安裝了哪些 App、Dock 有誰有關，只有桌面算得準，所以套用時在 `utils/assistant/widgetPlacement.ts` 留字條，`apps/Launcher.tsx` 看到模板出現在主題裡就用自己的 `placeCustomWidget`（找空位、滿了加頁）放，再收掉字條。字條只在記憶體，重新整理就沒了（模板還在）。
- 還原：新的刪模板，連桌面上那幾份一起拿掉；改既有的寫回原本的模板。

**捷徑**：世界書 App 頂欄（新的一組）和每組底下、小組件編輯頁（既有的）都有「請 Sore 幫忙」，交接 location 是 `'worldbook'`／`'widget'`。
**埋點**：`处理Sore的提案`、`从捷径找Sore` 的位置加上 世界书、小组件。
**測試**：`utils/assistant/worldbook.test.ts`、`utils/assistant/widget.test.ts`。
