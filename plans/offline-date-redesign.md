# 見面（線下）改版：線下故事＋自訂預設

2026-11-06 討論定案，還沒開工。範圍只有**見面的一般模式**；「劇情」劇場（StoryTheater）不動，只共用它的預設引擎。

## 為什麼改

用戶覺得見面的內建提示詞太死，不能照自己喜好調。不少人手上有大量 SillyTavern 資源（預設、正則），想一鍵匯入、自己視情況開關，不想一條條重寫。線上私聊沒這個問題，大多用世界書規範就夠。

後台數據裡 GAL 模式（立繪＋對話框逐句播）只有 2～5% 的人在用，這次整段拿掉，以新功能順利為主。

## 已定案

| 場景背景 | 留著，併進新的「畫面美化」 |

| 預設 | 見面可選「內建」或自己的預設；內建規則也改寫成一份預設，跟匯入的 ST 預設走同一套引擎，用戶可複製一份再調 |
| ST 匯入 | 讀 `prompts`／`prompt_order`／生成參數／`assistant_prefill`、預設內嵌正則 `extensions.regex_scripts`；分組開關介面可參考 `extensions.baibaiToolkit.presetPromptGroups` |
| 巨集 | 照 ST 規則實作預設裡常見的：`setvar`／`getvar`／`getglobalvar`、`random`、`roll`、`{{// }}`、`trim`、`time`／`date`／`timestamp`、`uuid`、`char`／`user` |

| 時間「自定義＋流動」 | A：從用戶設定的時間起算，跟著現實經過的時間往前走 |
| 情緒 | 跟私聊整合成同一套，加褪色，放寬條數，見下 |

## 線下故事

新增一個「線下故事」物件，每個角色同時只有一場進行中。現在的「繼續上次」（很多人見面分好幾天玩，路線圖裡定過要保留）就是繼續這場進行中的故事。

- **跟著角色走**（設定頁的角色層）：開場白庫、用哪份預設、回應字數、畫面美化
- **跟著這場故事走**：劇情大綱、時間設定、總結紀錄、狀態（進行中／已完結）；「線下情緒獨立」開著時，情緒也跟著故事走
- 完結的故事收進「已完結」列表，可以回看

## 設定頁要加的東西

1. **劇情大綱（Scenario）**：自由填寫，填進預設的 `scenario` 佔位（日月西等預設都有這格）；不填就留空讓模型自己跑
2. **開場白**：角色層的開場白庫，可新增多條（對應 ST 的 `first_mes`＋`alternate_greetings`）。開新故事時選一條或隨機；一條都沒有就照現在讓模型生成開場
3. **目前情緒**：見下面「情緒」
4. **拍下這一刻**：角色已有專屬生圖設定＋參考圖鎖臉（OOTD、朋友圈在用）。要補用戶這邊：身份卡加生圖參考圖和外觀描述。一張圖同時鎖兩張臉，要先查生圖 API 支不支援多張參考圖
5. **時間**：真實／自定義 × 流動／靜止。真實＋流動＝現狀（跟角色時區）；真實＋靜止＝定格在開始那一刻；自定義＋靜止＝停在填的時間；自定義＋流動＝從填的時間起跟著現實往前走
6. **關閉線上功能**：一鍵開啟後，故事進行中（未完結）這個角色不發朋友圈、便簽、評論等線上行為。本機觸發的加閘門；主動消息跑在用戶的雲端 Worker，要同步一個暫停狀態上去（見 `plans/amsg2-expansion.md`）
7. **對話總結**：
   - 自動總結開關：按條數（填幾條總結一次）或按天（選總結時間）
   - 總結要求：可填提示詞（文風、人稱…），可另存成總結預設
   - 立即總結（現有全部）、選範圍總結（第幾到第幾條）
   - 總結紀錄（條列）；自動進記憶宮殿（選條件）或手動點選進
   - **見面改成只走總結這條路進記憶宮殿**：現在見面每輪會把最近 50 則原始訊息丟進記憶宮殿（`DateApp` 的 `runMemoryPalacePostHook`），兩條都開會把同一段劇情記兩次
8. **完結故事**：生成大總結進記憶宮殿，故事標成已完結，解除第 6 項的線上暫停
9. **回應字數**：最少／最多。內建預設注入提示詞；ST 預設同時餵給 `getglobalvar::字数总要求`／`单段落字数`（日月西就靠這兩個讀字數，在 ST 裡原本由「預設助手」腳本設）
10. **畫面美化**：
    - 底圖：上傳（原有），加遮罩濃度
    - 字型大小
    - 字色：台詞、旁白各一個（預設台詞深、旁白淺一階，已先做好）
    - 原生淺色、深色兩套
    - 自訂 CSS：作用範圍限定在見面的閱讀區（照私聊白框 `.sully-chat-root` 的做法），提供穩定的 class 鉤子（已有 `date-line-dialogue`／`date-line-narration`，之後再補用戶輸入、裝飾容器等）並寫進用戶說明。裝飾 iframe 是獨立文件，自訂 CSS 管不到裡面

## Soren 自己的佔位

預設引擎除了 ST 的佔位（角色、世界書前／後、用戶、情境、示例、聊天記錄），再加幾個 Soren 的：

- 記憶（記憶宮殿召回）
- 時間
- 情緒
- 語音規則
- 回應字數

用戶可以在預設裡移動它們的位置；預設沒放的，預設附在系統提示詞最後，確保語音、時間這些照常生效。

## 語音標籤

主對話每句開頭加英文方括號 voice tag（`[lazy]`、`[chuckles]` 這類）；旁白、動作描寫不帶。

提示詞不分服務商，統一一種寫法（`DATE_VOICE_GUIDE`）；送去 TTS 前才按服務商處理（`utils/dateVoiceTags.ts` 的 `applyDateVoiceTags`）：

| 服務商 | 怎麼處理 |
|---|---|
| ElevenLabs v3 | 原生支援，標籤原樣放回句首（任意英文詞都行） |
| 魚聲 | 只留官方支援的那一小撮（`normalizeFishCue` 對得上的），其餘丟掉 |
| MiniMax | 方括號會被念出來，不放進文字；標籤剛好是它支援的情緒（happy / sad / calm…）就當 emotion 參數 |
| ElevenLabs 非 v3 | 不支援，全部不帶 |

標籤留在存下來的訊息裡，閱讀畫面不顯示（句首、句中都藏）。取代原本行尾的 `[v:xxx]`；舊消息的 `[v:xxx]` 和行首立繪表情照樣認得、照樣藏掉。

## 情緒

整合成一套，私聊和見面共用（「線下情緒獨立」開著時見面另存一份）。

- **褪色**：每條情緒記「淺／中／深」和產生時間，強度隨現實時間衰減（半衰期大約：淺幾小時、中一天、深三四天，數值實作時再調），衰減到很低就自動移除
- **條數放寬**：現在是提示詞規定最多 5 個、最好 2～4 個（`hooks/useChatAI.ts`），因為沒有褪色會一直堆。有了褪色之後改成最多存 12 條；注入提示詞時按目前強度取前 6 條左右，加一段「當下情緒總結」，避免 token 膨脹
- 「當下情緒總結」可以手動改；每條可刪；「重置情緒狀態」清空
- 顯示：設定頁放完整列表（強度條就是現在還剩多少），見面畫面頂端放一行小字的當下情緒，點開看完整列表

## 劇情大綱、開場白、回應字數的實作（已做）

小工具都在 `utils/dateExtras.ts`，設定頁那三塊在 `components/date/DateStoryExtras.tsx`。

| 項目 | 存在哪 | 怎麼用 |
|------|--------|--------|
| 劇情大綱 | `dateScenario` | 內建模式：見面正文在「場景上下文」前加一段「當前劇情大綱」，感知頁開場也帶。預設模式：填「場景」佔位，`{{scenario}}` 也讀它；`{{char}}`／`{{user}}` 先換好（ST 也是先展開角色卡欄位）。線下故事物件還沒做，先跟著角色存，第 2 輪搬進故事 |
| 開場白庫 | `dateGreetings`（`{id, text}[]`）、`dateOpeningSource` | 選「用開場白」又有寫，感知頁就隨機挑一條，不叫模型；重新感知換一條不一樣的。赴約（帶 meetup）那次還是讓模型寫，才接得上邀約。感知頁和設定頁都能切，記在角色上；開場白刪光就退回模型寫 |
| 回應字數 | `dateResponseLength`（`{min?, max?}`） | 內建模式在大綱後加一句「這一輪正文大約 …」。預設模式：預設裡名字有「字數／字数」又有「總／总」的全域變數（日月西的 `字数总要求`）直接蓋成「800–1200 字」這種寫法，蓋到了就不另外補；沒有這種變數才由 Soren 的「回應字數」佔位說一句。`单段落字数` 是每段長度，意思不同，不動，照預設變數頁填的 |

開場白、大綱裡的巨集只換 `{{char}}`／`{{user}}`（走同一個巨集引擎，認不得的原樣留著）。
