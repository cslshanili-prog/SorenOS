# 見面（線下）改版：線下故事＋自訂預設

2026-11-06 討論定案，還沒開工。範圍只有**見面的一般模式**；「劇情」劇場（StoryTheater）不動，只共用它的預設引擎。

## 為什麼改

用戶覺得見面的內建提示詞太死，不能照自己喜好調。不少人手上有大量 SillyTavern 資源（預設、正則），想一鍵匯入、自己視情況開關，不想一條條重寫。線上私聊沒這個問題，大多用世界書規範就夠。

後台數據裡 GAL 模式（立繪＋對話框逐句播）只有 2～5% 的人在用，這次整段拿掉，以新功能順利為主。

## 線下故事

新增一個「線下故事」物件，每個角色同時只有一場進行中。現在的「繼續上次」（很多人見面分好幾天玩，路線圖裡定過要保留）就是繼續這場進行中的故事。

- **跟著角色走**（設定頁的角色層）：開場白庫、用哪份預設、回應字數、畫面美化
- **跟著這場故事走**：劇情大綱、時間設定、總結紀錄、狀態（進行中／已完結）；「線下情緒獨立」開著時，情緒也跟著故事走
- 完結的故事收進「已完結」列表，可以回看

## 設定頁要加的東西

1. **劇情大綱（Scenario）**：自由填寫，填進預設的 `scenario` 佔位（日月西等預設都有這格）；不填就留空讓模型自己跑
2. **開場白**：角色層的開場白庫，可新增多條（對應 ST 的 `first_mes`＋`alternate_greetings`）。開新故事時選一條或隨機；一條都沒有就照現在讓模型生成開場
3. **目前情緒**：見下面「情緒」
4. **拍下這一刻**：角色已有專屬生圖設定＋參考圖鎖臉（OOTD、朋友圈在用）。要補用戶這邊：身份卡加生圖參考圖和外觀描述。一張圖同時鎖兩張臉，要先查生圖 API 支不支援多張參考圖
5. **時間**：真實／自定義 × 流動／靜止。真實＋流動＝現狀（跟角色時區）；真實＋靜止＝定格在開始那一刻；自定義＋靜止＝停在填的時間；自定義＋流動＝從填的時間起跟著現實往前走
6. **關閉線上功能**：一鍵開啟後，故事進行中（未完結）這個角色不發朋友圈、便簽、評論等線上行為。本機觸發的加閘門；主動消息跑在用戶的雲端 Worker，要同步一個暫停狀態上去（見 `plans/amsg2-expansion.md`）
7. **對話總結**：
   - 自動總結開關：按條數（填幾條總結一次）或按天（選總結時間）
   - 總結要求：可填提示詞（文風、人稱…），可另存成總結預設
   - 立即總結（現有全部）、選範圍總結（第幾到第幾條）
   - 總結紀錄（條列）；自動進記憶宮殿（選條件）或手動點選進
   - **見面改成只走總結這條路進記憶宮殿**：現在見面每輪會把最近 50 則原始訊息丟進記憶宮殿（`DateApp` 的 `runMemoryPalacePostHook`），兩條都開會把同一段劇情記兩次
8. **完結故事**：生成大總結進記憶宮殿，故事標成已完結，解除第 6 項的線上暫停
9. **回應字數**：最少／最多。內建預設注入提示詞；ST 預設同時餵給 `getglobalvar::字数总要求`／`单段落字数`（日月西就靠這兩個讀字數，在 ST 裡原本由「預設助手」腳本設）
10. **畫面美化**（已做，見 [`docs/date-appearance.md`](../docs/date-appearance.md)）：
    - 底圖：上傳（原有），加遮罩濃度
    - 字型大小
    - 字色：台詞、旁白各一個（預設台詞深、旁白淺一階，已先做好）
    - 原生淺色、深色兩套
    - 自訂 CSS：作用範圍限定在見面的閱讀區（照私聊白框 `.sully-chat-root` 的做法），提供穩定的 class 鉤子（已有 `date-line-dialogue`／`date-line-narration`，之後再補用戶輸入、裝飾容器等）並寫進用戶說明。裝飾 iframe 是獨立文件，自訂 CSS 管不到裡面

## Soren 自己的佔位

預設引擎除了 ST 的佔位（角色、世界書前／後、用戶、情境、示例、聊天記錄），再加幾個 Soren 的：

- 記憶（記憶宮殿召回）
- 時間
- 情緒
- 語音規則
- 回應字數

用戶可以在預設裡移動它們的位置；預設沒放的，預設附在系統提示詞最後，確保語音、時間這些照常生效。

## 語音標籤

主對話每句開頭加英文方括號 voice tag（`[lazy]`、`[chuckles]` 這類）；旁白、動作描寫不帶。

提示詞不分服務商，統一一種寫法（`DATE_VOICE_GUIDE`）；送去 TTS 前才按服務商處理（`utils/dateVoiceTags.ts` 的 `applyDateVoiceTags`）：

| 服務商 | 怎麼處理 |
|---|---|
| ElevenLabs v3 | 原生支援，標籤原樣放回句首（任意英文詞都行） |
| 魚聲 | 只留官方支援的那一小撮（`normalizeFishCue` 對得上的），其餘丟掉 |
| MiniMax | 方括號會被念出來，不放進文字；標籤剛好是它支援的情緒（happy / sad / calm…）就當 emotion 參數 |
| ElevenLabs 非 v3 | 不支援，全部不帶 |

標籤留在存下來的訊息裡，閱讀畫面不顯示（句首、句中都藏）。取代原本行尾的 `[v:xxx]`；舊消息的 `[v:xxx]` 和行首立繪表情照樣認得、照樣藏掉。

## 情緒

整合成一套，私聊和見面共用（「線下情緒獨立」開著時見面另存一份）。

- **褪色**：每條情緒記「淺／中／深」和產生時間，強度隨現實時間衰減（半衰期大約：淺幾小時、中一天、深三四天，數值實作時再調），衰減到很低就自動移除
- **條數放寬**：現在是提示詞規定最多 5 個、最好 2～4 個（`hooks/useChatAI.ts`），因為沒有褪色會一直堆。有了褪色之後改成最多存 12 條；注入提示詞時按目前強度取前 6 條左右，加一段「當下情緒總結」，避免 token 膨脹
- 「當下情緒總結」可以手動改；每條可刪；「重置情緒狀態」清空
- 顯示：設定頁放完整列表（強度條就是現在還剩多少），見面畫面頂端放一行小字的當下情緒，點開看完整列表

## 劇情大綱、開場白、回應字數的實作（已做）

小工具都在 `utils/dateExtras.ts`，設定頁那三塊在 `components/date/DateStoryExtras.tsx`。

| 項目 | 存在哪 | 怎麼用 |
|------|--------|--------|
| 劇情大綱 | `dateScenario` | 內建模式：見面正文在「場景上下文」前加一段「當前劇情大綱」，感知頁開場也帶。預設模式：填「場景」佔位，`{{scenario}}` 也讀它；`{{char}}`／`{{user}}` 先換好（ST 也是先展開角色卡欄位）。進行中的故事改自己的大綱（`DateStory.scenario`）；角色身上的 `dateScenario` 變成「下一場的大綱」，開新故事時搬進去並清掉 |
| 開場白庫 | `dateGreetings`（`{id, text}[]`）、`dateOpeningSource` | 選「用開場白」又有寫，感知頁就隨機挑一條，不叫模型；重新感知換一條不一樣的。赴約（帶 meetup）那次還是讓模型寫，才接得上邀約。感知頁和設定頁都能切，記在角色上；開場白刪光就退回模型寫 |
| 回應字數 | `dateResponseLength`（`{min?, max?}`） | 內建模式在大綱後加一句「這一輪正文大約 …」。預設模式：預設裡名字有「字數／字数」又有「總／总」的全域變數（日月西的 `字数总要求`）直接蓋成「800–1200 字」這種寫法，蓋到了就不另外補；沒有這種變數才由 Soren 的「回應字數」佔位說一句。`单段落字数` 是每段長度，意思不同，不動，照預設變數頁填的 |

## 線下故事物件的實作（已做）

邏輯在 `utils/dateStory.ts`，表是 `date_stories`（DB v77，進完整備份）。

- **一場故事**：`DateStory { id, charId, status, title?, scenario?, createdAt, completedAt? }`。角色身上 `activeDateStoryId` 指進行中的那場，同時只有一場
- **哪些訊息屬於這場**：只看見面訊息 `metadata.dateStoryId`。開場落庫時建故事、開場帶上 id，之後送出、重擲、繼續都帶。不用「某個 id 之後都算」：故事完結後再出現沒標的見面訊息（情人節活動那種）會被吞進去
- **舊存檔**：有 `savedDateState`、還沒有故事的角色，按「繼續上次」或「開始新的故事」時，從最後一次開場起轉成一場（`migrateLegacyDateStory`），那段訊息補標 `dateStoryId`；大綱搬進那場。沒存檔的舊見面不轉，在見面記錄「按故事」裡顯示成「故事功能之前的見面」
- **發現進度彈窗**：有存檔或有進行中的故事就跳。「開始新的故事」先問要不要結束這段：完結並總結／直接結束／取消
- **見面記錄**：有故事就多一個「按故事」分頁（預設選它），標進行中／已完結，可以改名、導出這場
- **改故事欄位**一律 `patchDateStory`（先讀庫裡最新的再合併），別拿手上的舊物件整個蓋回去：總結紀錄之後也存在故事上

## 對話總結與前情提要的實作（已做）

邏輯在 `utils/dateSummary.ts`（送宮殿那半在 `utils/dateSummaryPalace.ts`），設定頁是 `components/date/DateSummarySettings.tsx`。

- **見面原文照舊進記憶宮殿**（Liora 定的）：記憶宮殿逐段讀原文提取，長文細節多；總結主要當前情提要和完結總結用
- **總結存在故事上**：`DateStory.summaries`（舊 → 新，按涵蓋範圍排）、`summarizedThroughId`（自動總結做到哪）
- **設定跟著角色**：`dateSummaryConfig`。自動總結預設開，按角色回覆輪數（預設 10 輪，1–100）或每天固定時間；只在見面 App 開著時跑：每輪回覆後檢查，進見面（繼續上次）時補跑錯過的每天那次
- **立即總結**＝把還沒總結的部分總結掉（跟自動同一套，推進進度，不會重複總結）；**選範圍**＝第幾到第幾則，不動進度
- **總結要求**可以自己寫，另存成預設（`date_summary_presets` 表，DB v78，進完整備份，所有角色共用）
- **總結用角色的對話模型**（同見面），不串流、溫度 0.3；送給它的是拿掉語氣標籤／HTML 的純文字，帶這場的大綱和上一段總結
- **前情提要**：`buildDateRecap` 把這場的總結照順序接起來（最多約 6000 字，超過留最近的、說省略了幾段）。內建模式放在劇情大綱後、場景上下文前；自訂預設是 Soren 佔位「前情提要」（`recap`），預設沒放就補在聊天記錄前
- **進記憶宮殿**：只有完結時送（預設）／每次總結都送／手動。一段總結＝一條記憶（`importDateStorySummary`，見 `docs/memory-system-overview.md`），不叫模型再提取；角色沒開記憶宮殿或沒設 Embedding 就不送
- **「見面原文不進記憶宮殿」開關沒做**：要動記憶宮殿的水位線和上下文隱藏，既然原文照舊進，目前用不到

- **兩個入口**：「開始新的故事」的確認窗（完結並總結／直接結束／取消），和見面選單裡的「完結故事」（完結並總結／直接完結／取消，完結後回選角色頁）
- **整場總結**：先把還沒總結的尾巴總結成一段（跟「立即總結」同一套），再把這場所有分段總結收成一份回顧；只有一段就直接用那段。存在 `DateStory.finalSummary`。故事再長，餵給模型的也只是總結
- **失敗就不完結**：任何一步出錯都原樣丟錯，故事還是進行中，用戶可以重試或直接結束
- **送記憶宮殿**：總結設定是「手動」以外都送（整場回顧進臥室、importance 8，標籤帶故事名和「完結」）
- **見面記錄**：已完結的故事在「按故事」裡顯示整場總結；直接結束的可以「寫整場總結」補寫，沒送進宮殿的可以補送
- **一個舊坑**：見面會話卸載時會把手上那份角色資料連存檔整個寫回庫（`DateSession` 的 `saveStateToDB`，另外每 30 秒、切到背景也寫）。完結後離開會話時，這一下會把剛清掉的 `activeDateStoryId`、`savedDateState` 寫回去，所以完結時用 `suppressAutoSaveRef` 擋掉這次
- **完結時解除線上暫停**：完結會清掉 `activeDateStoryId`，見下面「關閉線上功能」那節，暫停跟著自動解除

## 情緒褪色與條數的實作（已做）

邏輯在 `utils/emotionDecay.ts`，私聊和見面共用一套。

- **怎麼褪**：每條情緒記 `since`（強度是什麼時候定的），強度 1／2／3＝淺／中／深，半衰期 6 小時／1 天／3.5 天；剩不到 0.3（以「淺」為 1）就當淡掉了：不顯示、不帶進提示詞，下次情緒評估落庫時清掉。舊資料沒有 `since` 的不褪，評估跑過一次就補上
- **評估落庫**（`utils/emotionApply.ts` 的 `settleBuffs`）：同一個情緒（id 或 name 對得上）強度沒變就沿用原本的時間繼續褪；變了或新的從現在算。最多存 12 條
- **評估模型看到的**：已淡掉的不給，強度換成此刻的，附「已持續」多久；規則從「最多 5 個、最好 2–4 個」改成最多 12 個、會自己褪、被重新觸發就把強度往上調
- **提示詞**：照舊帶評估寫的「當下情緒總結」（`buffInjection`，記 `buffInjectionAt`），後面補一行「這段寫於 N 小時前，此刻還在的情緒：…（最強的 6 條）；沒列出來的都淡掉了」。全部淡掉就整段不帶。時間刻度到小時，免得提示詞每分鐘都變、提示詞快取失效
- **畫面**：私聊設定和見面共用 `EmotionStatusPanel`：強度條是此刻還剩多少、每條可刪（只刪那條，不再整段清掉總結）、當下情緒總結可直接改、「重置情緒狀態」清空。私聊頂欄只顯示沒淡掉的。見面畫面左上角一行小字（`.date-emotion-line`），點開是同一個面板
- **沒做**：「線下情緒獨立」（見面另存一份情緒）。見面現在不跑情緒評估、只讀私聊那份，要獨立得先讓見面也跑評估，之後再說

## 關閉線上功能的實作（已做）

邏輯在 `utils/dateOffline.ts`，開關在見面設定（`dateOfflineMode`，跟著角色）。

- **停什麼**（Liora 定的）：主動消息 2.0、本機定時消息。**朋友圈照常**：線下見面時發個朋友圈按個讚也不奇怪

## 時間模式的實作（已做）

邏輯在 `utils/dateStoryTime.ts`，設定頁是 `components/date/DateStoryTimeSettings.tsx`。

- **存在哪**：進行中的故事 `DateStory.time`；還沒開始就存在角色 `dateNextStoryTime`，開新故事時帶進去（從故事開始那一刻起算），跟劇情大綱同一套
- **四種**：真實＋流動＝原本的樣子（不給時鐘，什麼都不改）；真實＋靜止＝停在起算那一刻；自定義＋靜止＝停在填的時間；自定義＋流動＝從填的時間起跟著現實往前走（A）。進行中改設定就從改的那一刻起算
- **填的時間是角色那邊的牆上時間**（`wallClockToTimestamp` 照角色時區解讀，見 `docs/character-timezone.md`）；自定義沒填就當真實
- **提示詞**：不是真實＋流動時，核心上下文那段現實時間不帶，散文塊的 Time 那行改成故事時間（附「這是故事裡的時間、聊天記錄是現實的」「時間停在這一刻」）；感知頁的「當前時間」和分隔線也換，不算「距離上次多久」。自訂預設的「時間」佔位、`{{time}}`／`{{date}}` 這些巨集都照故事時間
- **記錄時間**：這場故事的見面訊息照同一個鐘換算（別場、私聊的不動），同時關掉「距離上次多久」，兩把尺混著算出來是亂的
- 角色關了「線下時間感知」時整個不生效（照舊不帶時間）

## 條目增刪排序、複製、匯出（已做）

- **條目**：每個分組（或「全部條目」）最下面有「+ 新增條目」，新條目接在那區最後一個後面，但不越過聊天記錄（要送在聊天記錄後面就用排序移）。編輯單多了「位置」：照順序／插進聊天記錄＋倒數第幾則（ST 的 `injection_position = 1`、`injection_depth`）。一般條目能刪；資料佔位（聊天記錄、角色描述、Soren 的佔位）只能關、不能刪
- **排序**：條目和正則分頁都有「排序」，進去後每列換成上下箭頭。條目只跟同一區的鄰居換位置，`doc.prompts`（送出順序）和分組的 `promptIds`（畫面順序）一起換，兩邊不會走樣；分組本身不跨區移動
- **複製**：設定頁每份預設右邊的「⋯」→ 複製一份（新 id，名字加「（副本）」），想改又怕改壞就先複製
- **匯出**：同一個選單 → 匯出成 ST 的 .json，丟回酒館能直接用（條目、順序、開關、插入深度、生成參數、預填、`wi_format` 這些、內嵌正則、`baibaiToolkit` 分組都照 ST 欄位寫）。Soren 自己的佔位酒館沒有，寫成空白條目。另外整份 doc 原樣放在 `extensions.soren_meeting_preset`，連同 prompts／prompt_order／regex_scripts 的指紋：匯回 Soren 時指紋對得上就整份還原（變數的值也在）；在酒館改過、對不上，就照一般 ST 檔讀，不拿舊的蓋掉酒館裡的修改
