# 關係線 · 第 6 批：NPC 改成配角、角色私聊、群聊觸發私聊

> 狀態：**設計定案**（2026-11-12，第 5 節 Liora 已決定；第 6 節 AI 批量生成配角是新加的，細節待定）。上層見 [`persona-bond-redesign.md`](./persona-bond-redesign.md) 第 7 節，前一批見 [`persona-line-batch5.md`](./persona-line-batch5.md)。
> 已定案（上層 7.1、7.2、9 節）：
> - NPC 改成角色的一種（**配角**），跟主角同一張表、同一套能力；差別只在神經鏈接有自己的「配角」分頁、可以**下戲**、主動消息預設關。
> - 角色私聊從查手機獨立成自己的對話線，查手機改成讀這條線；你在列表裡看得到（上帝視角，它們不知道）。
> - 角色記得自己跟別人私聊過什麼，回頭跟你聊時知道自己說過什麼，標成「你跟小雨私下聊的，用戶不在場」。
> - 先做你手動「讓他們聊一輪」和群聊觸發；角色完全自己去找人，等前兩種跑順再說。

## 0. 現在的樣子

- **NPC** 在另一張表（`npcs`，`NPCProfile`），只有群聊、查手機聯繫人、見面劇情、朋友圈、家園、彼方熟悉度這幾處讀它；有自己的輕量記憶（`memory`，一段條列）、關係清單、認識的你（`knownPersonaId`）、專屬 API。不能私聊、不能見面、沒有日程和情緒。大約 37 個檔案在讀它。
- **角色之間的對話**存在查手機：A 的 `phoneState.records` 裡一筆紀錄，`detail` 是一整段「我:／對方:」腳本，鏡像一份到 B 的手機（翻過來）。沒有逐則時間，也只有查手機看得到；角色跟你私聊時不知道自己跟別人聊過什麼。

## 1. 配角

### 1.1 資料

配角就是 `CharacterProfile`，多兩個欄位：

```ts
/** 主角或配角；沒有就是主角 */
castRole?: 'lead' | 'supporting';
/** 下戲的時間；有值 ＝ 下戲中（主動的東西都停，記憶和紀錄都留著） */
benchedAt?: number;
/** 跟別人的關係（從 NPC 的關係清單搬來；主角之後也能用） */
relationships?: NPCRelationship[];
```

- 能力跟主角一樣：私聊、群聊、角色私聊、見面、通話、記憶宮殿、日程、情緒、朋友圈、節日活動。
- **主動消息預設關**：新建或搬來的配角，主動消息（1.0、2.0）都是關的，你想讓它主動找你再開。
- **下戲**：停掉所有主動的東西：主動消息、日程生成、情緒評估、自動發朋友圈、節日活動，以及其他頁面關著也會自己跑的活動。記憶、聊天、紀錄都留著；你主動找它（私聊、見面、拉進群）照常能聊，叫回來就恢復。背景系統統一過一道 `isOnStage(char)`（`utils/castRole.ts`），不用每個系統各寫一套。

### 1.2 從 NPC 搬過來

開了關係線預覽才搬，搬一次。id 照舊，所以引用它的地方大多只要換種類：

| NPC 的 | 配角的 |
|---|---|
| 名字、頭像、所在世界、世界觀、世界書、時區、時間感知、專屬 API | 照搬到同名欄位 |
| 性格與背景描述 | 核心人設（`systemPrompt`）；第一句當簡介（`description`） |
| 關係清單 | `relationships` |
| 認識的你（沒填就照現在的推法算一次） | 主線（`primaryPersonaKey`）和認識的卡 |
| 輕量記憶 | 長期核心記憶的一筆（標「搬家前的記憶」），開了記憶宮殿的另外匯進記憶宮殿 |

引用它的地方：

- 群聊的 `npcMemberIds` 併進 `members`（禁言照舊），之後配角在群裡就是一般成員，有自己的檔案塊、私聊時間線、話題盒卡片。
- 查手機綁了 NPC 的聯繫人改成真角色聯繫人（`linkedCharId`）。
- 朋友圈 NPC 作者的貼文改成角色作者。
- 見面劇情、家園、彼方熟悉度裡的 NPC 改讀配角。
- 舊的 `npcs` 表不刪，留著當備份（跟第 0 批刪功能時一樣）。

搬完之後，NPC 專用的那些程式（群聊 NPC 檔案塊、NPC 輕量記憶整理、NPC 客串、`resolveNpcApi`）就沒有東西要處理了，拿掉，改走角色那套。群聊的「NPC 客串」改成「客串」：拉一個不在群裡的角色（主角或配角）插一句話。

### 1.3 神經鏈接

- 主列表只放主角，原本的「NPC」分頁變「配角」，點進去是跟主角同一個編輯頁（多一區「關係」、一個「下戲／叫回來」）。
- 主角也能改成配角，反過來也行（編輯頁一個切換）。
- 訊息列表、選角色的地方（見面、通話、查手機、群成員）主角配角都列，配角在後面、下戲的再後面並標「下戲中」。

## 2. 角色私聊

### 2.1 對話線

兩個角色之間一條線，**只存一份**，兩邊讀同一份：

```ts
// 訊息照舊存 messages 表，charId 寫成這對角色的線 id（不是任何一個角色的 id），
// 所以現有「照角色讀私聊」的地方一則都不會讀到它；誰說的記在 speakerId。
charId: 'pair~<小的 id>~<大的 id>'
speakerId: string   // 說這則的角色 id
role: 'assistant'
```

- 純邏輯在 `utils/pairLine.ts`：`pairLineId(a, b)`、`parsePairLineId`、`isPairLineId`、這個角色有哪些對話線（掃訊息的 charId 索引前綴）。
- 讀寫走 `DB` 新加的幾個：某條線的訊息、某個角色所有對話線的最近幾則。
- 備份、刪角色時一起處理：刪掉其中一個角色，那條線的訊息一起刪（另一個角色的記憶裡已經整理進去的照留）。

### 2.2 生成：「讓他們聊一輪」

沿用查手機現在的雙 LLM 引擎（`runRealConversation`）：A 用 A 自己的角色檔案、記憶宮殿（用 B 的名字召回）、跟你的近期私聊說一句，B 用 B 的那一套回。差別是：

- 讀的、寫的都是這條線（逐則有時間），不再是一整段腳本。
- 好感（`[[Δ]]`）、「瞭解」（`[[瞭解:]]`）、話題盒照舊記在兩邊的聯繫人上（那是各自的主觀）。
- 「以對方身份說一句」照留（你冒充其中一個人說話，記成那個人說的）。

### 2.3 在哪裡看

- 訊息列表多一個「角色私聊」分頁，列出所有角色私聊（兩個人的頭像疊在一起、最後一則）。點進去是唯讀的對話頁，底下有「讓他們聊一輪」和「以『某某』身份說一句」。它們不知道你看得到。
- 「＋」多一個「讓兩個角色聊聊」：挑兩個人，開一條新的線，跑第一輪。
- 查手機裡真角色聯繫人的聊天，改成讀這條線（跟訊息列表看到的是同一份）。

### 2.4 角色記得

- **跟你私聊時**：提示詞多一段「你最近私下跟別人聊的（用戶不在場）」：每條線最近幾則，按時間排、標是跟誰。說不說、怎麼說由它決定。跟「近期群聊」同一個做法。
- **記憶宮殿**：角色私聊也整理進兩邊各自的記憶宮殿（各從自己的角度），標成「你跟小雨私下聊的」。之後跟你聊到相關的事召回得到。
- **見面、通話**照私聊那套，也帶得到。

### 2.5 群聊觸發私聊

- 群聊生成時多教一個標記：成員想私下對另一個成員說話時寫 `[[DM|名字: 內容]]`，群裡不顯示，落進兩人的角色私聊線。
- 你看得到：群裡落一行小字「阿澈 私訊了 小雨」（只有你看得到，角色看不到這行）。
- 對方要不要馬上回：見第 5 節第 2 點。

## 3. 實作拆法

- **6a 配角 — 已做**：欄位與 `isOnStage`、背景系統的下戲篩選、配角主動消息預設關、神經鏈接分頁與編輯頁、主角配角互換。
  - 純邏輯在 `utils/castRole.ts`（`isSupporting`、`isBenched`、`isOnStage`、`sortByCast`）。
  - 下戲擋在：主動消息 1.0（`runProactive` 主動那種，延遲回覆你的訊息照回）、主動消息 2.0（自己排程、到點的定時任務在收件那裡不收）、本機定時消息、日程與情緒（`isScheduleFeatureOn`）、朋友圈自動發文／按讚／留言、彼方自己跑（手動照常）。
  - 下戲時把主線排著的雲端任務先停下留底，叫回來照原樣排回去：跟見面「線下故事關閉線上功能」共用同一份留底（`dateOfflinePause`）和判斷（`isOnlinePaused`），OSContext 的 `setCharBenched`。
  - 神經鏈接：預覽開著時分「主角／配角」兩頁（舊 NPC 分頁在搬家前還在），配角頁新建的就是配角；編輯頁「戲份」一區「提升為主角」／「改成配角」（只換戲份，記憶、聊天、設定都不動）、下戲／叫回來，列表卡片標「下戲中」。編輯頁自動存檔不再整份寫回 `benchedAt`、`dateOfflinePause`、`activeMsg2Config`（別處在寫的，舊的會蓋掉剛停下的任務）。
  - 選角的地方都走 `filterCharactersByGroup`，順手照戲份排：主角、配角、下戲的。
  - 節日活動是你自己挑角色開的，下戲的配角照樣選得到，不另外擋。
- **6b 搬家 — 已做**：NPC → 配角、群成員併入、查手機聯繫人、朋友圈作者、劇情劇場的客串。
  - 純邏輯在 `utils/npcMigration.ts`，寫資料庫的在 `utils/npcMigrationRun.ts`；OSContext 在預覽開著、資料載入完、還有沒搬的 NPC 時跑一次。舊表留著，搬過的記 `migratedToCharAt`，之後不列、不再搬；同 id 已經有角色的當成搬過了。
  - 輕量記憶放進長期核心記憶的一筆（`YYYY-MM（搬家前的記憶）`）。記憶宮殿是角色自己在記憶宮殿 App 開的，搬來的配角預設沒開，所以不另外匯入；之後開了，從聊天整理照常。
  - 劇情劇場的客串 NPC 併進演員（配角跟主角一樣有記憶）。
  - 家園、彼方熟悉度裡的「NPC」是它們自己生成的鎮民和固定人物，跟神經鏈接的 NPC 無關，沒動。
  - 搬完 `npcs` 清單是空的，NPC 專用的那些路徑（群聊 NPC 檔案塊、NPC 記憶整理、NPC 客串、查手機虛構 NPC 綁定）自然沒事做；程式本身等正式開放、拿掉預覽開關那次一起刪，預覽關著的人還在用。
  - 順手做了第 6 節的「你身邊的人」：`utils/castRelations.ts`，核心上下文多一段 `relations`（自己的關係清單＋別人記到你的），名字表（`charNameRegistry`）多記一份關係清單；見面預設也帶。
- **6e AI 批量生成配角 — 已做**（第 6 節）：生成、預覽、建立、關係與通訊錄、頭像（「你身邊的人」在 6b 就做了）。
  - 純邏輯在 `utils/castGenerate.ts`（提示詞、兩層容錯解析、草稿轉配角、兩邊通訊錄），打 API 的在 `utils/castGenerateRun.ts`（全局 API，一次生成），頁面是 `components/character/CastGeneratorPage.tsx`，入口在神經鏈接「配角」頁頂端。
  - 讀主角的人設、世界觀、常駐世界書（`constant` 的那幾條），以及同一個世界裡的角色（沒分組的主角就讀沒分組的）。
  - 關係照名字對：主角、同一批、世界裡現有的、你（勾了才記，`targetId: 'user'`）；對不上的丟掉。查手機通訊錄兩邊各加一筆真角色聯繫人（身份標籤用那句關係），已經有的不重複加。
  - 頭像：生圖 API 配好才能勾，照外觀一張張畫，畫風跟生圖設定的補充提示詞，這頁可再加一句；沒畫成的用預設頭像。
  - 單張重生會避開這一批和世界裡已有的名字；新建的配角不切換正在聊的角色（OSContext `addCharacters`）。
  - 埋點 `AI 生成配角`（数量：1／2-3／4-5，头像：有／无）。
- **6c 角色私聊線**：`pairLine`、DB、訊息列表「角色私聊」分頁與對話頁、讓他們聊一輪、查手機改讀這條線（含舊對話搬家）。
- **6d 角色記得**：私聊提示詞的「私下跟別人聊的」、記憶宮殿整理角色私聊、群聊 `[[DM]]`（被私訊的人馬上回一句）。

順序：6a → 6b → 6e → 6c → 6d。每一步做完都跑一次完整驗證、提交一次。

## 4. 不做的

- 角色自己去找人私聊（上層 7.1：等手動和群聊觸發跑順再說）。
- 查手機裡**虛構**的聯繫人（沒綁神經鏈接的路人）照舊是查手機自己腦補的人，不變配角。
- 羈絆（團隊還在討論，之後接在關係線上）。

## 5. 已定案（Liora 2026-11-12）

1. **開了關係線預覽就自動搬一次**，舊表留著當備份（主要是讓同事測）。
2. **群聊裡被私訊的人馬上回一句**（自動聊）。
3. **查手機裡已有的真角色對話搬進角色私聊線**：腳本逐行拆成訊息，時間從那筆紀錄往前排開，兩邊的話題盒、好感照留。
4. **你只能看**、按「讓他們聊一輪」、或冒充其中一人說一句；想一起聊就開群。

## 6. AI 批量生成配角（Liora 2026-11-12 提，評估）

在「配角」分頁按「AI 生成配角」：

- **選為哪位主角生成**：讀那位主角的人設、世界觀、掛的世界書（常駐的那幾條）、所在世界，還有同一個世界裡已經有的角色（主角、配角都算，避免撞名、也能拿來連關係）。
- **一次幾個**：1～5 個。
- **方向**：一格自由填，例如「他的聯姻對象和她的閨蜜」「公司裡會跟他作對的人」；不填就由 AI 照人設挑劇情上最用得到的人。
- **關係連好**：每個生成出來的人都帶「跟誰、是什麼關係」——跟那位主角、跟同一批生成的其他人、跟世界裡現有的角色，也可以跟你（哪張卡照那位主角的主線）。存成兩邊的關係清單，也加進兩邊查手機的通訊錄（真角色聯繫人），之後角色私聊、查手機都接得上。
- **先看再存**：生成完先列成卡片（名字、一句話、人設、關係、外觀描述），可以改、單張重生、取消勾選，按「建立」才真的存成配角（所在世界跟那位主角一樣；主動消息照配角預設關）。
- **頭像**：勾了才生，要先配好生圖 API；照每個人的外觀描述一張一張生，失敗的保留預設頭像、之後可以在編輯頁重生。
- **主角也知道**：主角的提示詞多一段「你身邊的人」，列它的關係清單（不然生了一個聯姻對象，主角自己卻不知道）。這段主角配角都適用，手動加的關係也算。

份量中等：一次生成（兩層容錯解析）、預覽頁、建角色＋關係＋通訊錄、可選的頭像生成。排在 6b（搬家）之後、6c 之前，因為要用到配角的關係清單。

已定（Liora 2026-11-12）：
- 跟你的關係可以讓 AI 填，**有個勾選、預設不勾**。勾了就寫進那個配角的人設和關係清單，主線用那位主角的主線那張卡。
- 頭像畫風：照生圖設定裡現有的「補充提示詞」（全局、每次生圖都會拼上），這頁可以再加一句風格。不拿主角的頭像當參考圖（會把臉也照抄過去）。之後要不要在生圖設定加「畫風」預設、只套在某些地方，另外討論。
