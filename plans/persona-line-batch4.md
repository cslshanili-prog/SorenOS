## 1. 身份連結

身份卡之間兩兩設，存在用戶資料上（`UserProfile.personaLinks`），一張卡可以有好幾條：

```ts
interface PersonaLink {
    id: string;
    kind: 'sameWorld' | 'alt';
    a: string;   // personaKey；alt 時 a 是本來的身份
    b: string;   // personaKey；alt 時 b 是小號
    /** 同一世界的雙向稱呼：a 是 b 的「姊姊」、b 是 a 的「妹妹」。都可以不填 */
    aToB?: string;
    bToA?: string;
    createdAt: number;
}
```

- **在哪裡設**：身份卡編輯頁多一區「跟其他身份的關係」，選另一張卡、選種類（同一世界／小號）、填稱呼。小號那一種，建的時候順便勾「讓哪些角色知道」（只列兩張都認識的角色）。
- **刪卡**：連到它的連結一起刪；角色那邊對這條連結的狀態也一起清。

### 同一世界

只影響提示詞。角色認識其中一張卡，就在那條線上說一句「跟你聊天的『A』，她的妹妹是『B』」；兩張都認識，兩條線都說，並加一句「你兩個都認識」。沒填稱呼就寫「她跟『B』是同一個世界的人、互相認識」。

### 小號

小號是「認不認得出來」（2026-11-12 Liora 釐清）：角色本來就記得兩條線各自說過什麼，只是不知道是同一個人。只有角色**兩張卡都認識**時，這條連結對他才有意義。

每個角色對每條小號連結各記一個狀態，存在角色卡上（角色本人的，不跟線走）：

```ts
type AltKnowledge =
    | { state: 'known'; since: number }                 // 一直都知道（建連結時勾的）
    | { state: 'discovered'; at: number; how: 'revealed' | 'admitted' }  // 讓他發現／他察覺、你承認
    | { state: 'denied'; at: number; times: number };   // 他懷疑過、你否認了
// CharacterProfile.altKnowledge?: Record<linkId, AltKnowledge>，沒有就是「不知道」
```

| 狀態 | 提示詞（兩條線都放） | 記憶召回的標籤 |
|---|---|---|
| 不知道 | 什麼都不說，兩條線照現在完全隔開 | 「這是你跟『B』之間的事，『A』不一定知道」（照現在） |
| 一直知道／已發現 | 「『B』其實就是『A』，是她的另一個身份。你知道這件事」；已發現的加「你是在〇月〇日發現的」 | 「這是她用『B』的身份跟你說的」 |
| 否認過 | 「你曾經懷疑『B』就是『A』，她否認了（〇次）」 | 照「不知道」 |

## 2. 發現的三種方式

1. **一直都知道**：建連結時勾的角色，狀態直接是 `known`，不會有任何反應。
2. **讓他發現**：在角色那邊（聊天設定「認識的你」那一區）按「讓他發現」。狀態改成 `discovered`，兩條線各落一張「發現」卡片（他看得到、會進上下文），下一輪他會對這件事有反應。
3. **他察覺、你承認**：
   - 角色兩張卡都認識、但還不知道（或否認過）時，提示詞多教他一個標記：覺得眼前這個人其實是另一個他認識的人，就寫 `[[ACTION:SUSPECT|名字|為什麼這樣覺得]]`。提示詞**不透露**哪兩張卡有連結，只說「如果你覺得」。
   - 落成一張「他懷疑你是〇〇」的卡片。猜中有連結的那一張，卡片上有「承認／否認」；猜錯只能「否認」（或不理）。
   - 承認：跟「讓他發現」一樣，狀態 `discovered`（`how: 'admitted'`），兩條線落卡片。
   - 否認：狀態 `denied`、次數加一，他記得你否認過；之後要信還是更懷疑由他。
   - 一則回覆最多一個 SUSPECT，跟其他動作標記同一套剝除與解析。

角色那邊也能單獨改狀態（不知道／一直知道），只改狀態、不落卡片——那是改設定，不是劇情。

## 3. 加好友

現在讓角色認識一張新卡，是在「認識的你」裡直接打勾，像後台操作。改成劇情化的開頭：

- **入口**：訊息列表的「＋」多一個「加好友」，列出**不認識現在這張卡**的角色；在「全部身份」以外的空間點到不認識你的角色，也走這裡。
- **加好友頁**：寫一句招呼（驗證訊息），送出。
- **他決定**：一次生成，給他自己的設定、記憶（記憶只有一份，他可能從別條線聽過這個名字）、這張卡對外看得到的東西（名字、頭像、簡介）和招呼，回「通過／拒絕」加一句話。
  - 通過：這張卡加進他的 `knownPersonaKeys`，那一句當作新線的第一則訊息。
  - 拒絕：落一張「他沒有通過」的紀錄在加好友頁，可以再送；再送時他看得到你之前被拒過幾次、說過什麼。
- 「認識的你」裡的打勾照留，標成「直接讓他認識（不經過加好友）」，給想跳過這段的人。
- 加好友是在本機生成（一次性、需要馬上看到結果），不上雲。

## 4. 實作拆法

- **4a**：連結的資料、身份卡編輯頁那一區、同一世界和「一直知道」的提示詞與召回標籤、角色那邊的狀態切換。
- **4b**：發現——「讓他發現」、SUSPECT 標記、承認／否認卡片、否認紀錄。
- **4c**：加好友。

## 5. 待 Liora 決定

1. 加好友要不要做成**預設**？建議：是。不認識你的角色點進去就是加好友頁；想跳過就在「認識的你」直接打勾。
2. 被拒絕之後要不要**冷卻**？建議：不設硬性冷卻，隨時能再送，但他看得到你被拒過幾次——連送十次本身就是戲。
3. 角色懷疑你的頻率要不要**限制**？建議：不限，他否認過幾次、隔多久都寫在提示詞裡，讓他自己拿捏。
