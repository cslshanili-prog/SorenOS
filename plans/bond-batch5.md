# 羈絆 · 第 5 批：珍藏（禮物圖鑑、信件、留給以後）

> 總規劃見 [`bond.md`](./bond.md)（第 5 批那一列、第 2 節硬規則第 5、7 條）。
> 這一批做完時：羈絆空間多一個「珍藏」分頁，三個小分頁：
> - **禮物**：你送的、TA 送的、你打算送的，像一本圖鑑；購物中心的送禮單、TA 用 `[[ACTION:GIFT]]` 送的會自己出現。每件都能補照片、場合、收到時的反應，還能一直記後續（戴去見面了、壞了、收進抽屜）。
> - **信件**：比紙條長的、有信紙的完整書信，雙方都能寫、能回信，可以慢慢寄；TA 也會主動寫信給你；情人節、520 的特別信也收在這裡。
> - **留給以後**：封起來、到某一天（或某個紀念日、某個等級、某個階段）才能打開的信。沒到期前對方只知道「有一封」，不知道內容。
>
> ★ 照「故事劇情能呈現最完整的狀態」規劃。
>
> **2026-11-27 定案**：第 10 節照建議，只有第 4 題改成「TA 主動寫信多久一次、多長，由用戶自己選」（見 3.3）。照第 9 節分四小批做，最後一個 PR。

## 0.1 圖樣（2026-11-27 Liora 看過樣張定的）

信封、蠟封、禮物盒、留給以後的封條全部用程式畫的 SVG（不用圖片檔），顏色吃羈絆的色票，拆開有動畫、照「減少動態效果」退成淡入淡出。樣張：https://claude.ai/artifact/ESfjwB5U2m6AQSrnhSp3nZ（Liora 看過，「其他都 ok」）。

- **信封**：背面、信紙、前面口袋、封口蓋四層；拆開＝蠟封裂成兩半掉下 → 封口往上掀（尖角朝上）→ 信紙滑出 → 展開成整頁。信紙六種（交換日記那套），信封顏色跟著信紙配；蠟封五色（酒紅、墨綠、靛藍、琥珀、墨黑），中間壓寫信人名字的第一個字。慢寄在路上的信蓋一個「寄出中・預計 X」的郵戳、拆不開。
- **禮物盒**：盒身、盒蓋、緞帶與蝴蝶結分層；拆開＝蝴蝶結鬆開飄走、緞帶淡掉、盒蓋滑到旁邊、裡面的照片或 emoji 浮上來。包裝紙五種（條紋、點點、牛皮紙、格紋、素色）、緞帶四色（酒紅、米白、墨綠、金），每件照自己的 id 固定挑一款。圖鑑格子：打算送是虛線框、淡一點，有新後續亮一個小點，TA 準備的寫「TA 準備了 N 天」。
- **留給以後**：信封外一圈「留給以後」封條、掛一張小牌子（封面那句、還有幾天或「今天可以打開了」）；到期封條微微發亮；拆開＝封條撕成兩半 → 照信封拆；沒到期按拆開先問要不要提前打開。
- 程式放在 `components/bond/treasure/`（`Envelope.tsx`、`WaxSeal.tsx`、`GiftBox.tsx`、`CapsuleBand.tsx`，共用 `treasureArt.ts` 的款式表與 `pickStyle(id)`）。

## 1. 資料

都存在 `bond_entries`，`kind` 多 `gift`、`letter`、`capsule` 三種；**不開新表**。`text` 一律放「內容」（禮物是名稱或一句描述、信是信文、留給以後是封存的內容）。

### 1.1 禮物：`bond_entries` 的 `gift`

```ts
interface BondGift {
    /** 'out'＝你送 TA、'in'＝TA 送你 */
    dir: 'out' | 'in';
    /** 打算送 → 已買 → 已送；TA 送的一出現就是 given（已收） */
    state: 'planned' | 'bought' | 'given';
    /** 品項快照（從訂單來的照訂單；手記的可以只有一樣） */
    items?: Array<{ name: string; qty?: number; emoji?: string; shop?: string; price?: number }>;
    /** 購物中心訂單；有它就照訂單的配送進度算狀態 */
    orderId?: string;
    /** 聊天裡那張購物卡（跳回原文用） */
    messageId?: number;
    /** 資料庫的照片 id（自己挑的、或「生一張」存進去的） */
    photos?: string[];
    /** 場合：生日、紀念日、道歉、加班辛苦、沒有理由…（自由填，有幾個快捷選項） */
    occasion?: string;
    /** 收到時的反應：TA 那句（自動抓卡片後的第一則回覆）、或你寫的 */
    reaction?: string;
    /** 打算送：打算什麼時候送（日期 key）、從誰的願望來、對到購物中心哪件商品 */
    plannedFor?: string;
    fromWishId?: string;
    productName?: string;
    /** 後續 */
    followups?: Array<{ id: string; at: number; by: string; text: string; source?: BondSource }>;
    boughtAt?: number;
    givenAt?: number;
    /** TA 偷偷打算的（第 10 節第 2 題）：送出前你看不到；送出時記「準備了幾天」 */
    secret?: { plannedAt: number; revealedAt?: number };
}
```

**購物紀錄不另存一份**（硬規則第 7 條）：圖鑑是「這條線的送禮單」＋「禮物卡片」合起來現排，跟拾光時間線讀記憶同一招。

- 送禮單每張是一件：`mall_orders` 裡 `charId` 是這個角色，而且是你買給 TA（`buyer: 'user'`、`recipient: 'char'`）或 TA 買給你（`buyer: 'char'`、`recipient: 'user'`）；你在那件上補了照片、場合、後續，才寫一張 `gift` 卡，用 `orderId` 疊上去。
- **這張單是哪條線的**：`MallOrder` 沒記身份卡。新單在結帳時多寫一個 `personaKey`（聊天入口照現在的線；桌面入口照「給誰」那個角色的主線）；舊單照聊天裡那張購物卡（`metadata.orderId`）在哪條線算，找不到算主線。
- 狀態照訂單算，不存：還沒付（等 TA 代付）不算、已下單／配送中＝已買、已送達＝已送、取消的不列。
- 「代付」（`buyer: 'user'`、`recipient: 'user'`、`payer: 'char'`）不是禮物，是你請 TA 付錢買給你自己，不列。

### 1.2 信件：`bond_entries` 的 `letter`

```ts
interface BondLetter {
    /** 收件人：'user' 或角色 id（寄件人是 entry.author） */
    to: string;
    /** 信紙（沿用交換日記的 paperStyle）、署名 */
    paperStyle?: string;
    signature?: string;
    /** 寄出時間；沒有＝草稿 */
    sentAt?: number;
    /** 慢寄：到這個時間（這條線的故事時間）對方才收到；沒有＝寄出就到 */
    deliverAt?: number;
    readAt?: number;
    /** 回哪一封 */
    replyTo?: string;
    origin: 'manual' | 'reply' | 'output' | 'eventCard';
}
```

- **在路上的信不算對方知道**（硬規則第 5 條）：還沒到 `deliverAt` 的不進收件人的提示詞、也不在收件人的清單上（你寄給 TA 的，你這邊看得到「寄出中，預計 X 收到」）。
- **特別時光的信**（情人節、520）：角色卡上的 `specialMomentRecords`（照線存）直接列在信件最底下一段「特別時光」，唯讀、不複製；打開就是原本那封（含大圖）。

### 1.3 留給以後：`bond_entries` 的 `capsule`

```ts
interface BondCapsule {
    /** 給誰：'user'、角色 id、'both'（一起打開；兩人各寫一封，同時封、同時開） */
    to: string;
    /** 打開條件 */
    openWhen:
        | { kind: 'date'; date: string }                       // 這條線的故事日期
        | { kind: 'anniversary'; eventId: string; year?: number } // 行事曆的某個紀念日（下一次）
        | { kind: 'level'; level: number }
        | { kind: 'stage'; stage: string };
    /** 封面那句（雙方都看得到），例如「等我們第一次一起過年再打開」 */
    cover?: string;
    /** 一起附上的資料庫照片 */
    photos?: string[];
    sealedAt: number;
    /** 條件達成的時間（到這時才能拆）、真的拆開的時間 */
    dueAt?: number;
    openedAt?: number;
    /** 沒到期就拆了（第 10 節第 5 題） */
    openedEarly?: boolean;
    /** 一起打開：另一封的 id */
    pairWith?: string;
}
```

- `status`：封存中是 `published`（存在是公開的），內容的知情另外照 `openedAt` 判斷，生成和顯示同一個函式（`visibility.ts` 加 `knownCapsules`）。
- 條件達成由 pact 的 tick 判（OSContext 每 5 分鐘那個）：日期照這條線的故事日期（跟天數同一套）、紀念日讀行事曆、等級讀帳本、階段讀 `bonds.stage`。**達成不等於自動拆**：首頁和聊天各出一張「今天可以打開了」，你按「拆開」才拆（有一個拆信的動畫）。TA 那邊在條件達成的那輪提示詞會知道「今天是你們約好打開那封信的日子」。

## 2. 禮物

### 2.1 圖鑑怎麼排

- 上面三格篩選：**我送的／TA 送的／打算送**（打算送只有你看得到，TA 的打算見 2.4）。
- 每件一格：照片（沒有就用品項的 emoji、再沒有就一個包裝的小圖示）、名稱、日期、場合；後續有新的會亮一個小點。
- 最上面一行統計：送了幾件、收了幾件、第一件是什麼（點了開那件）。

### 2.2 一件禮物（全螢幕）

- 大照片（可以換、可以加幾張）、名稱與品項、誰送誰、哪天、場合、配送進度（購物中心的單）。
- 收到時的反應：TA 送的那件是你寫；你送的那件預設抓聊天裡購物卡後面 TA 的第一則回覆，可以改。
- 後續：時間線樣式，按「記一筆」寫一句；也可以從聊天帶（見第 6 節）。
- 「回到那時」：跳回聊天裡那張購物卡（`chatJumpLaunch`）。
- 「帶去聊聊」。
- 照片：**從資料庫挑**（全螢幕挑選頁，第 2 批片刻那頁），或**生一張**（生圖走 `generateImage`，`feature: 'bondGift'`，畫風照 `resolveImageStyle`，存進資料庫、標這條線；有人在畫面裡才帶參考圖）。

### 2.3 打算送

- 三個來源：**TA 的願望**（願望頁多一顆「我想送這個」）、**購物中心的商品**（商品詳情多一顆「打算送 TA」，選哪個角色、哪條線）、**自己寫**。
- 「去買」：開購物中心、把那件放進購物車、給誰預設 TA、留言預設是你寫的那句；買了之後照品名把訂單連回這件（`productName` 對訂單品項，同一條線最近的一張），狀態變已買。
- 打算什麼時候送：可以填日期或選一個紀念日；到那天前三天首頁提醒一次。
- 打算送的**不進 TA 的提示詞**（第 10 節第 1 題），TA 不會「剛好提到」。

### 2.4 TA 偷偷打算（第 10 節第 2 題，建議做）

- 角色在私聊裡想到要送你什麼、但想給你驚喜時，在回覆最後寫 `[[ACTION:BOND_GIFT_PLAN|東西|什麼時候]]`；標籤剝掉、**你看不到**，存成一張 `dir: 'in'`、`secret` 的卡。
- 之後 TA 的提示詞會帶「你在準備送對方 X（打算 Y 的時候），對方還不知道」，TA 可以自己決定什麼時候用 GIFT 送出。
- TA 用 GIFT 送出、品名對得上：那張卡揭曉，記「TA 準備了 N 天」，圖鑑上這件多一行小字。
- 一直沒送：60 天後自動作廢（TA 的提示詞也不再帶），你永遠不會知道。
- 小號、拉黑中不收；同一時間最多 3 件在準備。worker 直通這個標籤。

### 2.5 事件卡帶禮物

第 4 批延到這批：開演時的情境多帶「跟主題相關的禮物」（例如求婚帶最近一件你送的飾品、紀念日卡帶去年那天送的），照 `occasion`、時間挑最多 2 件，開演前能勾掉。

## 3. 信件

### 3.1 寫信、寄信

- 全螢幕書寫頁：信紙（交換日記那幾種）、內容、署名；存草稿或寄出。
- 寄出時選**馬上到**或**慢慢寄**（1～7 天，照這條線的故事時間；第 10 節第 3 題）。慢寄的在你的清單上是「寄出中，預計 X 收到」。
- 寄出、送達都會在聊天裡落一張信封小卡（「你寄了一封信給 TA」／「TA 的信到了」），點了開那封信；小卡沿用 `bond_invite` 那個訊息類型、`metadata.bondLetter`（跟第 4 批的約定小卡同一招），歷史裡寫成 `[你寄了一封信給對方：「開頭一句…」]`。

### 3.2 讀信、回信

- 讀信頁：信紙全版、寄件人、日期；讀了記 `readAt`（TA 寫給你的信，你讀了沒 TA 看得到，像已讀）。
- 回信：開書寫頁，`replyTo` 連上；一串信在讀信頁下面依序排開。
- **請 TA 回信**：照第 3 批「請 TA 回」那套（`heartRun`），帶人設、羈絆段、最近的總結和私聊、這一串信的全文；篇幅照主動產出的「信」設定。

### 3.3 TA 主動寫信

主動產出多一種 `letter`（第 10 節第 4 題）：

- **多久一次、寫多長由你自己選**（Liora 2026-11-27）：「信」這一種預設關著，在主動產出設定頁打開時，先跳出全螢幕的設定讓你填幾天一封、幾字到幾字（不給預先填好的數字；之後照樣能改）；投遞時段預設 20:00～23:30、在私聊說一聲（落信封小卡）。
- 只有你按「請 TA 回信」、還沒設過篇幅時，那一次照 300～800 字寫，並提醒你可以去設定。
- 會提早寫的事件：里程碑記下、紀念日當天、見面結束、很久沒說話（7 天以上）。
- 本機＋雲端（`bond-output` 多一種，worker 在 `config-check` 報 `bond-output:letter` 才排雲端的；bundle 版本往前推）。
- TA 寫的信照樣可以設「慢慢寄」：主動產出的信有一定機率（建議 30%）用慢寄，讓「信到了」有等待感。

## 4. 留給以後

### 4.1 封一封

- 全螢幕書寫頁：內容（信紙同信件）、附照片、封面那句、打開條件、給誰（TA／我們一起）。
- **一起打開**：你寫好後按「封存」，會請 TA 也寫一封給你（照請 TA 回信那套），兩封互相 `pairWith`，條件一樣、同時拆。
- 封好之後**你自己也看不到內容**（像真的封起來）——第 10 節第 6 題。

### 4.2 TA 封給你

- 大日子的時候 TA 會封一封：里程碑記下時（在一起、求婚、和好…）、事件卡演成了、每年的相識紀念日。由系統在那個時間點請 TA 寫（本機，副 API 或對話 API），條件預設「一年後的今天」，TA 可以自己寫封面那句。
- 每段關係同時封著的 TA 的最多 5 封。

### 4.3 拆開

- 條件達成：首頁最上面一張「有一封信今天可以打開了」、聊天裡一張小卡；**不會自動拆**。
- 按「拆開」：封口撕開的動畫 → 信紙展開 → 讀完下面一顆「帶去聊聊」。
- 拆了之後內容進雙方提示詞；TA 寫的那封，TA 知道你拆了。
- 提前打開（第 10 節第 5 題）：收件人可以「等不及了」提前拆，會問一次；記 `openedEarly`，TA 知道你提前拆了（照個性反應）。

## 5. 提示詞：誰知道什麼

新的一段【你們的珍藏】，跟【你們的約定】一樣放在羈絆段裡（`utils/bond/prompt.ts` 的 `treasureLines`），沒有內容時一字不差。

| 東西 | 帶什麼 | 不帶什麼 |
|---|---|---|
| 禮物 | 最近 6 件（誰送誰、什麼、哪天、場合、最新一筆後續）；你送的、TA 送的都帶 | 你打算送的（驚喜） |
| TA 的打算 | 只進 TA 自己的提示詞：「你在準備送對方 X」 | — |
| 信件 | 最近 3 封已送達的（雙方各自的），每封摘 120 字；還沒回的那封標「對方在等你回」 | 草稿、在路上的信 |
| 留給以後 | 已拆的：摘 120 字；封著的：TA 寫的那封 TA 知道內容與條件、你寫給 TA 的 TA 只知道「有一封、什麼時候能開、封面那句」；今天到期的標「今天可以打開」 | 你寫給 TA、還沒拆的內容 |

- 篇幅上限 `PROMPT_TREASURE_CHARS`（同第 4 批的做法），超過照時間截。
- 雲端（即時對話、fire_pack）吃同一份核心上下文；改了珍藏要打髒。

## 10. Liora 的決定（2026-11-27）

除了第 4 題，全部照建議。第 4 題：**幾天一封、幾個字讓用戶自己選**（3.3）。

以下是當時的題目與建議，留著對照：

1. **你「打算送」的禮物，TA 知道嗎？** 建議**不知道**（驚喜），買了、送達了才知道。
2. **TA 能偷偷打算送你東西嗎？** 建議**能**（2.4）：你這邊完全看不到，送出時才揭曉「TA 準備了幾天」；一直沒送就默默作廢。
3. **寄信要郵程嗎？** 建議**可選**：預設馬上到，可以選慢慢寄（1～7 天，照故事時間）；TA 主動寫的信偶爾也慢寄。
4. **TA 主動寫信的頻率與篇幅**：建議 14～30 天、300～800 字、紀念日／里程碑／很久沒說話會提早，設定頁可調。
5. **提前打開**：建議**收件人可以提前拆**，但會問一次、留下「提前打開」的紀錄，寫的那方會知道。
6. **封好之後自己還看得到嗎？** 建議**看不到**（像真的封起來），只看得到封面那句和條件；要改就只能「拆掉重封」（會留紀錄）。
7. **禮物照片可以「生一張」嗎？** 建議**可以**，照畫風解析，生的存進資料庫。
8. **每日總結提到禮物時**：建議**先問你**（珍藏分頁上一張卡），不自動寫進後續。
9. **TA 在大日子封一封給你**：建議做（4.2），條件預設「一年後的今天」。

## 11. 實況（2026-11-27 做完，5a～5d）

照第 1～10 節做完，跟設計稿不一樣、或設計稿沒寫到的地方記在這裡：

- **慢寄用真實時間**（第 10 節第 3 題原本寫「照故事時間」）：故事時間可以靜止、可以跳，信會永遠寄不到或一下子全到；慢寄的 `deliverAt` 一律是真實時間，TA 主動寫的信 30% 機率慢寄 1～3 天。
- **TA 主動寫信的設定入口**：除了心意的主動產出，珍藏 → 信件上方多一行「TA 主動寫信」狀態＋「設定」，從這裡進去返回會回到信件。第一次打開會先跳全螢幕設定頁，兩格（幾天一封、幾個字）都是空的，填了才能開（第 4 題）。
- **購物中心商品頁改成全螢幕**（原本是半窗，照 AGENTS.md「不要半窗」順手換掉），多了「打算送 TA」；選人是全螢幕的 `GiftPlanTargetPage`（角色 × 身份卡）。
- **一次性的跳轉在 StrictMode 下**：`mallLaunch` 這類字條在 `useState` 的初始值裡只 `peek()`，`useEffect` 裡才 `consume()`，不然開發模式初始值跑兩次會把字條吃掉。
- **見面結束的事件之前沒人發**：第 3 批的 `date_end`（日記、隨筆、願望、信可以提早寫）一直沒有發出的地方；這批補上，見面存檔離開、完結故事時各記一筆（快速離開是掛起，不算）。
- **每日總結對禮物後續**（第 6 節、第 10 節第 8 題）：只對已經送出的禮物（打算送、還在路上、TA 還沒揭曉的不算），一次最多 20 件；同一筆總結只對一次（`bonds.giftSummaryChecked`，留最近 120 筆）；待確認的存在 `bonds.giftFollowupPending`（最多 12 筆，舊的先丟），珍藏分頁上方一張一張問，可以先改那句再「記進去」，記進去的後續來源是那筆記憶。購物中心的單第一次記東西會先開一張疊上去的卡。純邏輯在 `utils/bond/gift.ts`（`buildGiftSummaryPrompt`／`parseGiftSummary`／`withGiftSummaryChecked`），執行在 `components/bond/giftRun.ts` 的 `checkGiftFollowupFromSummary`，接在 OSContext「總結寫好了」那段。
- **挑幾件的禮物**：清單上的圖鑑每件給一個 G 編號（最近的 20 件），AI 說到某件就挑成「禮物後續」，記在那件上；圖鑑裡已經有的不會再挑成新的禮物。收存頁收成禮物時預設方向照說出口的那方（你說「我織了圍巾給你」是你送的），AI 幫填看不出來的欄位留空。
- **埋點比第 8 節多的值**：`羁绊礼物` 的來源多 `每日总结`／`资料库`／`生成`（補照片）；`羁绊信件` 的來源多 `请TA回`；`约定完成` 的模板多 `写信`。
- **外賣不算禮物**（2026-11-27 上線後 Liora 看了滿屏的雞湯、冷萃：「食物怪怪的」）：購物中心的單分商城（`kind: 'shop'`）和外賣（`'food'`），預設商城的算、外賣不算——日常互相點吃的是照顧，不是要留著的東西。兩個方向都能手動改，存在那張單疊上去的卡 `gift.counts`（`true` 算、`false` 不算，沒改過照預設）：聊天裡的購物卡下面一行「算禮物／不算禮物」（`BOND_GIFT_COUNT_EVENT`，私聊頁照這條線的空間寫），一件禮物頁最下面「這件不算禮物」。判斷只在 `utils/bond/gift.ts` 的 `orderCountsAsGift`，`buildGiftViews` 照它篩，所以圖鑑、提示詞、成就、挑幾件、每日總結都是同一套；你打算送的、TA 準備的走外賣送出，連回時自動算。
