# 羈絆（總規劃）

> 來源：Liora 團隊的《Soren「羈絆」功能討論紀要 v0.2》（2026-11-26），加上當天和 Liora 三輪討論的定案。功能方向以紀要為準，這份文件記「在 Soren 裡怎麼落地」。紀要裡已確認的規則這裡不全部重抄，只抄會影響實作的；細節以紀要原文為準。
>
> ★ 照「故事劇情能呈現最完整的狀態」規劃，工大就分批，目標是完整版。

## 0. 這次討論定下來的（2026-11-26）

1. **時間線＝每日總結做骨幹＋手動收存片刻。** 骨幹是神經鏈接「記憶」裡每天那段日總結（`CharacterProfile.memories`，`MemoryFragment`，已經按線標 `personaKey`），跟神經鏈接編輯同一份；另外可以從聊天、見面把某一段「收存成片刻」，記住來源訊息。不重新提取一次。
2. **雲端 worker 可以加東西。** 主動產出（日記、問答、心靈角落、隨筆）照「每天到點生成日程」那條路，在後台任務註冊表（`worker/amsg/src/fireKinds.ts`）多一種 `amsgKind`；沒開主動消息 2.0、或 Worker 還沒更新的，退回本機排程，App 打開時補到期的那份。
3. **角色 × 角色不排時間。** 內容只在有新經歷時產生：
   - 按「讓 AI 寫他們的故事」並保存時，故事裡真的發生的事回寫各區，雙方各留一則隨筆／日記；
   - 各區塊有自己的小按鈕（「讓 A 寫一篇日記」「讓他們回答一題」），不推新劇情、只就已經發生的寫；
   - 他們的私聊線每滿 100 則整理進記憶（`PAIR_ARCHIVE_EVERY`，`utils/pairChatRun.ts`）時，自動讓雙方各留一篇日記；每個空間有開關可以關掉。

## 1. 名詞

| 名詞 | 意思 | 存在哪 |
|---|---|---|
| 羈絆空間（bond） | 一段關係的專屬空間 | `bonds` 表，一段關係一筆 |
| 身份卡 × 角色 | 你某張身份卡跟某個角色 | 掛在那條關係線上，id 一律 `charId::personaKey`（主線也帶身份卡鍵，換主線的卡空間跟著卡走；舊角色沒有身份卡鍵時是 charId），用 `utils/bond/model.ts` 的 `bondIdForChar` |
| 角色 × 角色 | 兩個角色（含配角） | 掛在角色私聊線上，id 用 `pairLineId(a, b)`（`pair~A~B`） |
| 路線（route） | 這段關係允許往哪發展 | `romance`（戀愛）／`friendship`（友情）／`family`（親情／血緣）／沒設＝未指定 |
| 階段（stage） | 路線裡現在走到哪 | 內建階段 id，或自訂名稱（自訂的仍屬原本的路線） |
| 羈絆等級 | 共同經歷的累積 | 第 4 批（任務積點） |
| 親近、信任 | 雙方各自的感受 | 讀現成的：私聊的自訂量表（`affinities`）、查手機聯絡人的好感（兩個方向各一格） |

**「朋友」是階段，不是路線。** 戀愛線、友情線、未指定都可以停在「朋友」這個階段；判斷能不能往戀愛走，一律看路線。

## 2. 硬規則（每一批都要守）

1. **AI 不改路線。** 路線只有你能改（設定頁），角色可以邀請、表白，但寫不進路線。角色用 `[[ACTION:RELATIONSHIP|…]]` 改「角色認為的關係」時，友情線、親情線上帶戀愛字眼的改法不生效。
2. **友情鎖定、親情鎖定。** 路線是友情或親情時，所有生成路徑都帶一段鎖定（內容照紀要 2.2）；這段固定放在預設之後，自訂預設蓋不掉，做法跟群聊導演模式的輸出格式一樣。
3. **自動開的空間不等於鎖定。** 空間可以自動出現，但路線維持「未指定」，直到你自己選。
4. **改現在不改過去。** 「記錄轉折」從轉折那天起生效，提示詞裡會講清楚「之前的友情是真的」。
5. **知情範圍**（紀要 4.1）：發布、投遞、揭曉的才是雙方都知道的；草稿、未揭曉的盲答、沒到期的「留給以後」不進另一方的提示詞。**生成時和顯示時用同一套判斷**，不能只在畫面上遮。
6. **事實和感想分開**（紀要 4.2）：時間線是事件，隨筆、日記、紙條是主觀理解，摘要時不能把「我猜」改成「是」。角色卡上的偏好不能變成已發生的共同經歷。
7. **已有的東西不做第二份**（`plans/persona-bond-redesign.md` 7.3）：天數讀聊天設定的相識起點、紀念日讀行事曆、日記搬交換日記、禮物讀購物和送禮紀錄。
8. **不用半窗**，新增、編輯、詳細內容一律全螢幕頁。
9. **背景系統一律過 `isOnStage`**：下戲的角色空間還能看、不主動產出。**小號不單獨開空間**（跟神經鏈接不單獨列一致；跟小號聊的線算在小號那張卡上，暫不開羈絆）。

## 3. 資料

### 3.1 `bonds` 表（第 1 批建）

```ts
interface BondRecord {
    id: string;                 // charId::personaKey 或 pairLineId(a, b)
    kind: 'persona' | 'pair';
    charId: string;             // persona：角色；pair：字典序小的那位
    personaKey?: string;        // persona：哪張身份卡（主線也寫上，方便列）
    otherCharId?: string;       // pair：另一位
    route?: 'romance' | 'friendship' | 'family';
    stage: string;              // 內建階段 id，或 'custom'
    stageLabel?: string;        // 自訂階段名／親情線的稱謂（哥哥、妹妹…）
    openedAt: number;
    openedBy: 'auto' | 'user' | 'char';
    routeLog: BondRouteChange[];   // 修正設定、記錄轉折都記
    days: BondDays;                 // 天數（見第 1 批 3.3）
    ourNow?: BondOurNow;            // 此刻的我們／我眼中的我們
    pairAutoDiary?: boolean;        // pair：私聊整理時自動留日記，預設開
    // 之後各批加：output（主動產出設定）、level（等級與積點）…
}
```

- **空間不用先建。** 清單是「認識的線＋有訊息的角色私聊線＋表裡已有的」合起來現排；第一次改設定、或角色邀請你接受時才寫一筆。這樣自動開啟不會一口氣寫一堆紀錄。
- **同步讀：登記表。** 提示詞是同步組的，讀不了 IndexedDB。OSContext 開機和每次改動時把整張表放進記憶體登記表（跟 `setTripRegistry` 同一個做法），`utils/bond/registry.ts` 給 `bondForLine(char)`、`bondForPair(a, b)`。
- **備份、雲端備份、還原** 都帶這張表。
- **改了要打髒**：路線、階段、此刻的我們會進提示詞，改了要讓雲端（即時對話、主動消息 fire_pack）重新上傳。

### 3.2 之後各批的資料（先記方向）

| 東西 | 存法 |
|---|---|
| 收存的片刻、隨筆 | `bond_entries` 表，`kind` 分 moment／essay／diary／question／note／wish／promise／habit／gift／letter；都帶 `bondId`、作者、可見狀態（草稿／發布／封存）、來源（訊息 id、記憶 id、故事 id） |
| 時間線骨幹 | 不存，讀 `memories`（照線篩 `personaKey`）＋片刻 |
| 日記 | 交換日記（`DiaryEntry`）搬進來，加 `bondId` |
| 紀念日 | `CalendarEvent`（kind `anniversary`），帶參與者就能篩到這段關係 |
| 禮物 | `bond_entries` 的 gift，連到購物訂單、`[[ACTION:GIFT]]` 紀錄、資料庫照片 |
| 任務、積點 | 第 4 批再定，完成依據讀通話、見面、聽歌紀錄 |

## 4. 提示詞怎麼帶

- **一個模組出所有段落**：`utils/bond/prompt.ts`。沒有空間、或路線未指定又沒改過階段時，吐空字串，**現有提示詞一字不差**（測試鎖著）。
- **進哪裡**：`ContextBuilder` 的核心段多一段 `bond`（放在「印象」後面），這樣私聊、通話、見面、查手機、日程這些吃核心上下文的路徑一次接上；只吃角色設定的（朋友圈）另外接；群聊、劇情照「在場的身份」各自帶；角色私聊、群聊私訊帶「這兩個角色之間」的那段。
- **鎖定段放最後**：友情、親情的鎖定在各條路徑的系統提示詞最後再出現一次（短句），預設改不掉。
- **群聊與劇情的旁人**：在場的人裡有誰跟誰是友情線，給其他成員一句「不要起鬨成戀愛」。
