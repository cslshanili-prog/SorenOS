# 生圖畫風庫與 API 庫

> 狀態：第 6 節四點都定了（Liora 2026-11-12）；**a、b、c 都做完了**。起因：第 6 批 AI 生成配角時發現 Soren 沒有「畫風」可選，只能每次手填「這次的風格」。

## 1. 現在的樣子

- **設置 → 生圖 API**：一組 API（URL、Key、模型、尺寸、品質），下面一格「補充提示詞」，拼在**每一次**生圖的最後（`imageGenConfig.extraPrompt`，`utils/imageGeneration.ts` 的 `generateImage`）。想統一畫風只能寫在這格，全手機一套，畫風和畫質混在一起。
- **角色**：`imageGenCharConfig` 管的是長相：參考圖鎖臉、人物特徵提示詞。
- **AI 生成配角**：一格一次性的「這次的風格」，不存。
- 生圖走 OpenAI 相容的 `/images/generations`（帶參考圖走 `/images/edits`），**沒有負面提示詞欄位**。

## 2. 要做到什麼

- 存好幾套**畫風**（名字＋提示詞），存好幾組**生圖 API**，各挑一個當全域預設。
- 世界（神經鏈接分組）可以指定畫風：古風世界、賽博世界各自一套。
- 角色可以指定畫風，沒指定就跟世界、再跟全域。
- 每一種會生圖的地方可以各自設：關閉／跟全域／某一套畫風。
- 在生圖的地方就能臨時換，不用每次回設置頁。

## 3. 畫風庫

一套畫風：

```ts
interface ImageStylePreset {
  id: string;
  name: string;
  /** 每次都加的：畫風、質感、光影、色調 */
  prompt: string;
  /** 畫面裡有人時才加的：臉、皮膚、構圖（特寫、自拍視角…）；拍食物、風景時不加 */
  portraitPrompt?: string;
  /** 負面提示詞：預設寫成「避免：…」接在正文後面；API 那組勾了「支援 negative_prompt」才改成欄位送 */
  negativePrompt?: string;
  /** 這套畫風固定用哪組 API（選填；沒填跟全域） */
  apiId?: string;
  builtin?: boolean;
}
```

- **為什麼拆「有人時才加」**：群裡常用的這幾套都寫了「人物位於構圖主體、臉部特寫、自拍視角」，套到朋友圈的咖啡、窗外夜景、資料庫的物件圖，就會硬塞一張臉。判斷「畫面裡有沒有人」沿用現成的 `looksLikeSelfieDescription`（參考圖鎖臉就是靠它決定帶不帶）。
- **負面提示詞**：現在的接口沒有這個欄位。預設當文字接在後面（「避免：…」）；有些中轉站收 `negative_prompt` 欄位，在 API 那組勾一下才送，不勾不送，免得嚴格的接口直接 400。
- **內建**：3～4 套，可以改、可以刪、可以「恢復內建」。見第 6 節。
- **原本的「補充提示詞」**：搬進畫風庫變成一套「我原本的補充提示詞」，設成全域預設；行為跟現在一模一樣，那一格之後就不見了。沒填過的人不搬。

## 4. 生圖 API 庫

- 現在那一組變成庫裡的第一組，可以再加幾組（不同中轉、不同模型），挑一組當全域。
- 「允許生圖」「允許角色自己發照片」兩個總開關照舊，在庫外面。
- 這組支不支援參考圖、支不支援 `negative_prompt`，各自記在那一組上。

## 5. 誰用哪一套（解析順序）

| 層 | 設在哪裡 | 說明 |
|----|---------|------|
| 這一次 | 生圖的地方臨時選 | 資料庫生圖、AI 生成配角、小號頭像、聊天照片的「✎ 改提示詞」重生，都多一個下拉，預設是下面解出來的那套 |
| 角色 | 角色編輯頁「生圖」那一區（鎖臉旁邊） | 小號跟著本人 |
| 世界 | 神經鏈接分組 | 這個世界的人都用這套 |
| 功能 | 設置 → 生圖 → 各處畫風 那張表 | 聊天照片、朋友圈、穿搭、見面拍照、頭像、資料庫，各一格：關閉／跟全域／某一套 |
| 全域 | 畫風庫裡挑的預設 | |

- 越上面越優先；某一格是「關閉」就不生圖，誰也蓋不過。
- 跟角色無關的圖（資料庫裡你自己叫 AI 生的）不看角色和世界，只看功能那格和全域。

## 6. 定案與待定

1. **已定**：解析順序照第 5 節（這一次 > 角色 > 世界 > 功能那格 > 全域，「關閉」最大）。
2. **已定**：拆「有人時才加」。內建的幾套都是針對人像寫的，臉、皮膚、構圖那幾句放進 `portraitPrompt`。
3. **已定**：內建四套（**2026-11-14 換過**：Liora 換成 Photographic Realism、Digital Human Render、Illustrated CG Artwork 三套英文的，加上韓系手繪插畫。舊的三套放在 `RETIRED_BUILTIN_STYLES`：讀進來時沒改過的拿掉、改過的留著變成自己的；指著舊 id 的照 `RETIRED_STYLE_ALIASES` 換——半寫實 CG→Digital Human Render、精緻二次元與偽厚塗→Illustrated CG Artwork；角色卡、世界存的舊 id 不回頭改，解析時經 `liveStyleId` 換。旗標 `builtinStylesV2`。下面是最早那版）：
   - 半寫實 CG：3D、真人膚質、寫真感（群友 1）。
   - 精緻二次元：2D 數位插畫、動漫式眼睛高光、霧面瓷肌（群友 3；跟群友 2 幾乎同一套，留一個）。
   - 偽厚塗 CG：韓系乙女 CG、言情小說封面感，描邊清楚、明暗極低、近白灰、啞光（群友提供）。
   - 韓系手繪插畫：看得出手繪痕跡的鉛筆線稿＋水彩／不透明水彩、紙紋、留白（我寫的草稿，跟偽厚塗拉開：不是數位 CG）。
   - 群友 2 那份貼上來時夾了一串零寬字元（看不見），做內建時清掉。
4. **已定**：一套畫風可以「偏好」某組 API，但不鎖死——那組失敗（連不上、5xx、401／403、額度）就自動改用全域那組重試一次，提示一聲；生圖地方的臨時下拉也能選 API。這樣 API 掛了不用回設置。

## 7. 實作拆法（草稿）

- **a — 已做**：畫風庫、API 庫的資料與搬遷、設置頁的兩個庫、全域預設。
  - 純邏輯在 `utils/imageStyle.ts`：`normalizeImageGenConfig`（`normalizeApiConfig` 裡跑，讀進來、每次存都過一次，冪等）、`pickStyle`、`applyStyleToPrompt`、`apiForStyle`、內建四套 `BUILTIN_STYLES`。
  - 搬遷：舊的單組 API 變成庫裡第一組（id `img-api-1`）；頂層 baseUrl／apiKey／model／size／quality 永遠同步成全域那組，所以舊的呼叫點不用改。舊的「補充提示詞」搬成「我原本的補充提示詞」（id `style-legacy`）並設成全域，出來的提示詞跟以前一字不差（正文＋空行＋那段）。沒填過的人全域是「不套畫風」。內建只在第一次放，刪了不自動補（「恢復內建畫風」補回來）。
  - `generateImage(config, prompt, refs?, { styleId, hasPerson })`：不給 styleId 就套全域；`'none'` 不套。`hasPerson` 不給就用 `looksLikeSelfieDescription` 看提示詞決定加不加人像段。負面提示詞預設寫成「避免（Negative）：…」接在後面，那組 API 勾了「支援 negative_prompt」才改用欄位送（純文字和帶參考圖兩條路都送）。畫風偏好的 API 失敗就改用全域那組重試一次，結果帶 `apiFallbackFrom`（b 讓各入口提示一聲）。看不見的字元（零寬、方向控制）送出前一律清掉。
  - 設置頁（`components/settings/ImageGenSettingsPanel.tsx`）：API 一排膠囊（✓ 是全域）、＋新增一組、名稱、原本那些欄位、「支援 negative_prompt」、設為全域／刪除這組；畫風庫：全域畫風下拉、每套展開編輯（名稱、每次都加、畫面有人時才加、避免、偏好的 API、設為全域、內建的「恢復原文」、刪除）、＋新增畫風、恢復內建畫風；保存按鈕黏在底部；測試生圖用正在看的那組 API，可以選畫風。
  - 內建的偽厚塗、半寫實 CG 只把臉、構圖那幾句移到「畫面有人時才加」，字面沒改。
- **b — 已做**：各處畫風那張表、角色／世界的指定、所有生圖入口改走解析。
  - `utils/imageStyle.ts` 多了 `IMAGE_FEATURES`（六處：聊天照片、朋友圈配圖、穿搭、見面拍照、頭像、資料庫生圖）、`resolveImageStyle`（這一次 > 角色 > 世界 > 功能那格 > 全域；那一處 `'off'` 誰也蓋不過；指到刪掉的畫風就往下一層找；資料庫那格不看角色和世界；小號照本人）、`canGenerateFor`、`isImageFeatureOff`。
  - 資料：`imageGenConfig.featureStyles`（沒有＝跟全域、`'off'`＝關閉、`'none'`＝不套、其他是畫風 id）、`imageGenCharConfig.styleId`、`CharacterGroup.imageStyleId`。世界的畫風由 OSProvider 登記到 `charNameRegistry`（`setWorldStyleRegistry`／`getWorldStyleId`），utils 層照角色的分組找。
