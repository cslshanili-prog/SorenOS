# 關係線 · 第 5 批：群聊裡好幾個身份同場

> 狀態：**設計稿**（2026-11-12），第 6 節有三點待 Liora 決定。上層見 [`persona-bond-redesign.md`](./persona-bond-redesign.md) 第 6 節，前一批見 [`persona-line-batch4.md`](./persona-line-batch4.md)。
> 已定案（上層第 6、9 節）：「群身份」換成「在場的身份」，可以選一張、多張或一張都不選；一張都不選就是旁觀，旁觀不再是另一個開關。成員照自己認不認識看每個身份；有同一世界連結的告訴它；成員認識幾張在場的卡，就合併幾條私聊線。

## 0. 現在的樣子

- 一個群只有一個「你」：群單獨指定 > 成員多數認識的 > 全域默認（`personaKeyForGroup`）。你發的訊息記 `metadata.personaKey`。
- 成員認不認識你，只拿它的**主身份**比（`personaKeyForChar`）。關係線開著時，成員認識群裡那張卡、但那張不是它的主線，現在還是會被當成「不認識的人」：群裡把你當群友、私聊時間線不併。這批順手修掉。
- 隱身圍觀是群上的開關（`GroupProfile.userLurkMode`）：開著時你**所有**的群訊息（包括開之前說的）都不給角色看。

## 1. 在場的身份

存在用戶資料上，跟現在的 `perGroupPersonaIds` 放在一起（身份是你的資料，不是群的）：

```ts
// UserProfile
/** 群裡在場的身份（groupId → personaKey[]）。[] = 旁觀；沒有這個群的鍵 = 照舊自動挑一張 */
groupPresence?: Record<string, string[]>;
```

解析統一走一個函式 `presentPersonaKeys(profileBase, group, characters)`（放 `utils/userPersona.ts`）：

1. `groupPresence[group.id]` 有設：濾掉已刪的卡後照用；如果濾完變空、但原本不是空的（卡都被刪了），當作沒設。
2. 沒設、群開著舊的隱身圍觀（`userLurkMode`）：`[]`。
3. 都沒有：`[personaKeyForGroup(...)]`。「自動」照留，就是一張、成員多數認識的那張。

- 關係線預覽**關著**時 UI 跟現在一樣（單選身份＋隱身圍觀開關），底下走同一個解析，只是不會有多張。
- 舊的 `userLurkMode` 不搬：沒設 `groupPresence` 時才看它。在新 UI 改過「在場的身份」就寫 `groupPresence`、把 `userLurkMode` 清掉，兩個不會打架。
- 刪身份卡時把它從每個群的 `groupPresence` 拿掉（跟 `perGroupPersonaIds` 同一處清）。

## 2. 發訊息

- 在場兩張以上時，輸入框左邊多一個小頭像，點了切換「這則用哪張卡說」。預設用你上一則用的那張（還在場的話），否則第一張。記在記憶體裡，換群就重算。
- 訊息照舊記 `metadata.personaKey`，氣泡頭像跟著那張卡（現在已經會）。
- 旁觀時沒選代打，你打的字只留在你的螢幕上，跟現在一樣；另外記 `metadata.offstage: true`，之後你回到群裡，這些話也**不會**突然被角色看到（現在會）。
- 紅包、引用回覆、退回紅包這些「你」做的動作，都用當下選的那張卡。

## 3. 成員怎麼看在場的你

每位角色成員算一次：

- **它認識的在場卡**＝在場的卡 ∩ 它認識的卡（關係線關著時就是它的主身份那一張）。
- **它不認識的在場卡**＝群友，用名字、頭像、對外的簡介認人。

### 3.1 角色檔案塊

- **認識一張**：用那條線的視圖（`lineView`）建角色檔案，關係、印象、月度總結、記憶宮殿的標籤都是那條線的；私聊時間線併那條線。跟現在「同一個人」那段一樣，只是不再限定主線。
- **認識兩張以上**：
  - 「主看的那條線」＝這些卡裡最近在群裡說過話的那張（都沒說過就主線、再不然第一張），角色檔案照它建。
  - 其他認識的在場卡，各補一小段「你也認識在場的『B』」：那條線的印象、私聊空窗期，時間線裡也併進那條線的私聊（標 `[私聊·B]`）。
  - 記憶只有一份（上層 4.4），記憶宮殿照現在用主看的那條線召回，標籤本來就會分「這是你跟『B』之間的事」。
- **一張都不認識**：照現在「群裡的你不是你私下認識的那個人」那段，只是名字可能有好幾個。它私下認識的那張不在場，私聊時間線不併。
- 身份連結照第 4 批的規則說：同一世界的，認識其中一張就說「在場的『A』和『B』是姊妹」；小號的，它知道是同一個人才說「『A』和『B』是同一個人」，不知道就是兩個群友，什麼都不提。
- 群裡**不教** SUSPECT：懷疑卡要落在一條私聊線上，群裡沒有地方放。它在群裡起了疑心，會自己在私聊裡問。

### 3.2 群歷史裡你那一行

- 在場一張、而且所有你的訊息都是那張：照舊寫「用戶」。
- 其他情況（在場好幾張、或以前用別張卡說過話）：一律寫那張卡的名字，規則裡說明「記錄裡的『A』『B』都是真人群友」。
- 導演／輪流模式的「U 還是 U」那條，在場好幾張時改成：「群裡有好幾位真人群友：『A』『B』。每個人照你自己的角色檔案看：你認識的就是你認識的那個人，關係照舊；不認識的就是群友。」

### 3.3 共享場景

現在共享場景放一份「用戶是誰」。改成**每張在場的卡各一份**對外資料（名字、頭像描述、簡介），標題寫「群裡的真人成員」。旁觀時這段換成「這一輪群裡沒有用戶在場」（跟現在的旁觀提示一致）。

## 4. 成員私下發給你的話（`[[PRIVATE: 內容]]`）

現在一律落在成員的主線。改成：

- 只認識一張在場卡：落那條線。
- 認識好幾張：教它寫 `[[PRIVATE|名字: 內容]]` 指定給誰；沒寫名字就給最近在群裡說過話、它認識的那張。
- 一張都不認識、或旁觀中：不教 PRIVATE，寫了也丟掉（跟現在 NPC 一樣）。

## 5. 其他讀群訊息的地方

| 地方 | 改什麼 |
|---|---|
| 私聊裡的「群聊背景」（`chatPrompts`） | 現在跟這條線不同身份說的話都標「不同的人、你不知道他們的關係」。改成分兩種：這個角色**也認識**的卡，標「你也認識的『B』」；不認識的才是那句提醒。旁觀時打的字（`offstage`）不放。 |
| 公共話題盒的私聊卡片 | 現在送到每位成員的主線。改成送到成員認識、而且在這段群聊裡說過話的每條線；一條都沒有就主線。 |
| 話題盒總結、群記憶宮殿、NPC 群記憶 | 你那一行改成照訊息上的卡寫名字（現在全用群身份的名字）；舊的隱身圍觀判斷換成 §1 的解析＋`offstage`。 |
| 朋友圈「見過的身份」 | 現在拿群身份算。改成在場的每張卡都算見過。 |
| 紅包 | 見第 6 節第 2 點。 |
| 群主「我」 | `ownerId: 'user'` 照舊是「你」；在場好幾張時寫進提示詞的是第一張的名字。要細分到哪張卡當群主，等有人要再說。 |
| NPC 成員 | 它認識一張（`personaKeyForNpc`），在場就是那個人，其他是群友，跟角色同一套規則。 |

## 6. 待 Liora 決定

1. **旁觀時，你以前在群裡說過的話要不要也藏起來？**
   - 建議**照現在**：旁觀＝這個群裡沒有你，角色看不到你所有的群訊息，以為群裡只有它們。你回到群裡，這些話又看得到（旁觀時打的不會）。
   - 另一種：只藏旁觀時打的，以前說的照樣看得到（像「你在群裡、只是現在沒出聲」）。但這樣角色會知道你在群裡，就不是「以為只有彼此」了。
2. **紅包：在場好幾張卡時，每張卡算不算一個人？**
   - 建議**算**：每張在場的卡各能搶一次，專屬紅包可以指定給其中一張，錢都進你同一個錢包。故事裡是不同的人，搶了一份再換張卡搶一份，角色看得到。
   - 另一種：不管用哪張卡，同一個紅包你只能搶一次。
3. **成員認識兩張在場的卡，「主看的那條線」要怎麼挑？**
   - 建議**最近在群裡說話的那張**（§3.1）：跟著誰正在說話走，角色對眼前這個人最有感覺。
   - 另一種：固定成員的主線（主線不在場才換）。穩定，但你用 B 在群裡聊了一下午，它的關係底色還是 A 的。

## 7. 實作拆法

- **5a**：`groupPresence` 與解析、刪卡清理、群設定「在場的身份」（多選＋旁觀）、輸入框切換卡、`offstage`、成員認識的判斷改成照它認識的卡（修掉非主線被當陌生人）。
- **5b**：生成這頭：成員檔案塊（認識一張／好幾張／都不認識）、群歷史的名字、共享場景、規則文字、身份連結、PRIVATE 指定。
- **5c**：其他讀群訊息的地方（第 5 節那張表）、紅包。
