# 羈絆 · 第 1 批：骨架、路線與鎖定、「我們」首頁

> 總規劃見 [`bond.md`](./bond.md)。這一批做完時，羈絆 App 能打開、看得到每一段關係、能設路線，聊天各處立刻照路線走；首頁有主視覺、此刻的我們、天數、下一個紀念日。拾光、心意、約定、珍藏四個分頁從第 2 批起陸續出現（沒做的分頁不顯示，不放空殼）。

## 1. 資料

### 1.1 `bonds` 表

- IndexedDB 新表 `bonds`（DB 版本 +1），主鍵 `id`，索引 `charId`、`otherCharId`。型別 `BondRecord` 見總規劃 3.1。
- DB 方法：`getAllBonds`、`getBond(id)`、`saveBond`、`deleteBond`（刪角色時一起刪他所有的空間；刪身份卡時刪那張卡的空間）。
- 備份：`exportSystem`／`importSystem`、雲端備份都帶 `bonds`；新舊備份互通（舊備份沒有這張表就是空的）。
- `utils/bond/registry.ts`：`setBondRegistry(records)`、`bondById(id)`、`bondForLine(char)`（吃 `lineView` 過的角色卡，照它的線算 id）、`bondForPair(aId, bId)`。OSContext 開機讀一次、每次 `saveBond`／`deleteBond` 後更新，並發事件讓羈絆 App 重讀。

### 1.2 路線與階段

`utils/bond/routes.ts`（純邏輯，有測試）：

| 路線 | 內建階段（id → 顯示） | 備註 |
|---|---|---|
| 未指定 | `friend` 朋友、`custom` 自訂 | 不帶任何路線規則 |
| 戀愛 `romance` | `friend` 朋友 → `ambiguous` 曖昧 → `lovers` 戀人 → `steady` 穩定相伴 → `engaged` 訂婚 → `married` 結婚；`custom` 自訂 | 起始階段可以直接選（原本就是夫妻就選結婚） |
| 友情 `friendship` | `friend` 朋友、`close` 摯友、`familyLike` 家人式友情；`custom` 自訂 | 等級再高也不強制改稱摯友 |
| 親情 `family` | `kin` 親屬（`stageLabel` 填稱謂：哥哥、妹妹、媽媽…）；`custom` 自訂 | 稱謂是人物事實，可以改字，不能被升級改掉 |

- 角色 × 角色：同一套路線，各自的稱謂可以不同（A 是 B 的姐姐、B 是 A 的妹妹），所以親情線的 pair 存 `stageLabel` 一份＋`stageLabelOther` 一份。
- **建議路線**（`suggestBond`）：讀「你認為的關係」「角色認為的關係」（`userViewRelationship`／`charViewRelationship`）和角色關係清單裡指向你的那條，碰到明確字眼（戀人、男友、女友、老公、老婆、未婚夫妻、夫妻 → 戀愛＋對應階段；哥哥、姐姐、弟弟、妹妹、爸媽、兒女、堂表兄弟姐妹 → 親情＋稱謂）就在首頁出一張卡：「看起來你們是戀人，要設成戀愛線嗎？〔設定〕〔不是〕」。**只建議、不自動設**；友情線不建議（「摯友」這種字眼不代表你要鎖純友情）。按「不是」記下來，不再問。

### 1.3 路線歷程

- `routeLog` 每筆：`{ at, storyDay, kind: 'fix' | 'turn', from: {route, stage, label}, to: {...}, note? }`。`storyDay` 照這條線的故事時間（`makeChatClock`），沒設就是今天。
- **修正設定**（`fix`）：建立時選錯。直接改現在的值，提示詞不提「轉折」。
- **記錄轉折**（`turn`）：關係真的變了（朋友變戀人、分手變朋友）。現在的值改掉，提示詞多一句「你們在 ○○ 那時從○○變成○○；之前那段是真的，不要改寫成一開始就是現在這樣」。最近一次轉折才帶，舊的留在歷程頁。
- 同一條路線裡換階段（朋友 → 曖昧）也記，算 `turn`。

## 2. 提示詞

### 2.1 段落（`utils/bond/prompt.ts`）

- `bondPromptBlock({ bond, selfName, otherName, viewer })`：
  - 沒有空間，或路線未指定、階段還是預設的朋友、沒有此刻的我們 → **空字串**。
  - 戀愛：「你和 X 的關係路線是戀愛，現在是〔階段〕。身份要經過實際發生的事和雙方的表達才會改變，不要自己宣布交往、訂婚。」＋最近一次轉折句。
  - 友情：紀要 2.2 的鎖定全文（不補寫暗戀、不把失落寫成吃醋、不因親近推斷路線改變、不誘導解鎖戀愛……）＋「友情可以很深」那段，免得角色反過來變冷淡。
  - 親情：「你是 X 的〔稱謂〕，這是血緣事實；你們的親近、理解、信任可以變深，但不會變成戀愛。」
  - 自訂階段名：「你們把這段關係叫作『〔名稱〕』（仍屬〇〇路線）。」
  - 此刻的我們：角色自己寫的那段＋你寫的「我眼中的我們」（兩段都是公開的，見 4.1）。
- `bondFinalLock(bond, selfName, otherName)`：友情、親情才有，一句話，放系統提示詞最後。
- `bondBystanderNote(pairs)`：群聊、劇情裡給旁人的一句（「A 和 B 是朋友，不是戀人，別起鬨」）。

### 2.2 接到哪裡

| 路徑 | 怎麼接 |
|---|---|
| 私聊（本機、即時對話、主動消息 fire_pack） | 核心段 `bond`（`CoreContextSections` 多一段，放 `impression` 後面）；自訂預設的組裝（`utils/chatPresetSession.ts`）把它歸在「關係」那類，可放佔位；`bondFinalLock` 接在整串最後，預設改不掉 |
| 通話 | 吃核心段；`utils/callPrompt.ts` 的段最後加鎖定 |
| 見面（一般模式、ST 預設） | 吃核心段；預設組好後最後加鎖定 |
| 劇情 | 每個演員照 `utils/storyActorView.ts` 認識的卡，各自帶他跟在場那位你的那段；旁人一句 |
| 群聊 | 成員檔案塊各帶他跟在場身份的那段（`utils/groupChat/presence.ts`）；成員之間有友情線的，旁人一句；導演、各自發言都在最後加鎖定 |
| 角色私聊、群聊私訊 | `pairContext`／`buildSpeakerContext` 帶這兩人之間的那段 |
| 朋友圈發文、留言 | 只吃角色設定（`buildRoleSettingsContext`），另外補：發文的人跟你、留言的人跟發文者 |
| 查手機、日程、隨筆類生成 | 吃核心段，自動帶 |

- **測試鎖**：沒有空間時，私聊、通話、群聊、見面、劇情組出來的提示詞跟現在一字不差（照現有的 `chatPrompts.segments.test.ts`、`storyTheater` 那幾支的寫法）；有友情線時，鎖定一定在最後一段、在預設內容之後。
- **打髒**：`saveBond` 後打髒這個角色（`amsgStateSync`），雲端下次就拿新的提示詞。

### 2.3 擋 AI 改路線

- `[[ACTION:RELATIONSHIP|…]]`（`utils/chatRelationship.ts`、OSContext、`applyAssistantPostProcessing.ts` 三處）：這條線是友情或親情、新的關係字串裡有戀愛字眼（同 1.2 的字表）→ 不寫入、留一行系統日誌（開發面板看得到）。其他情況照舊。
- 角色永遠沒有改路線的標籤。

## 3. 介面

### 3.1 App 與入口

- 新 App「羈絆」（`AppID.Bond`，桌面圖示一顆，Dock 預設不放）。
- 入口：桌面；私聊頂端點角色頭像的名片（`components/chat/CharacterCard.tsx`）加一顆「羈絆」，直接開這條線的空間；聊天設定的「關係」那區加一列「羈絆空間 →」。走 `utils/appLaunch.ts` 的一次性字條，返回回到原本的聊天。

### 3.2 空間清單（全螢幕首頁）

- 上方兩個分頁：「我和 TA」（身份卡 × 角色）、「他們之間」（角色 × 角色）。
- 「我和 TA」照身份卡分組（只有一張卡就不分組），每張空間卡：兩個頭像、對方名字、路線小標（戀愛／友情／親情／未指定）、階段或自訂名、主要天數。
- 「他們之間」：有訊息的角色私聊線＋你自己建的。
- 右上「＋」：全螢幕選人頁（沿用 `components/calendar/PersonPickerPage.tsx` 的搜尋、按世界分組），選「我的哪張卡＋哪個角色」或「兩個角色」，接著直接進路線設定頁。
- 下戲的角色排最後、灰一點；小號不列。

### 3.3 空間首頁「我們」

由上往下（紀要 7.3，第 1 批有的部分）：

1. **關係主視覺**：雙方頭像、今天的日期（故事時間）、路線與階段、主要天數；點路線那行進路線設定頁。羈絆 Lv. 第 4 批才出現。
2. **建議路線卡**（1.2，有才出現）。
3. **此刻的我們**：角色寫的一小段＋你寫的「我眼中的我們」，並排。角色那段按「讓 TA 寫」生成（讀印象、最近的日總結、這段關係的設定，照紀要 6.1 的口吻；寫的是願意讓你看到的理解），可以重寫、可以改字；你那段直接寫。點進去是完整關係概覽頁（第 1 批先放這兩段＋路線歷程＋親近信任量表）。
4. **下一個紀念日**：行事曆裡參與者有這個角色的紀念日，最近一個；點進去是篩好的行事曆清單，沒有就是「＋加一個紀念日」（開 `AddEventPage`，預填參與者）。
5. **天數**（主視覺下面的小字列，點進去全螢幕頁）：
   - 起點清單：「相識」讀寫聊天設定的相識起點（`acquaintanceStartDate`，同一份，不另存）；可加「交往」「結婚」或自訂名稱的起點，存在 `days.extra`。
   - 選哪一個當主要天數；文案照路線（相識／交往／結婚，友情的「認識」、親情的「一起長大」……）。
   - 日期用這條線的故事時間算；沒填的起點顯示「還沒填」，不從聊天猜。

角色 × 角色的首頁第 1 批只有：主視覺、路線、雙方怎麼看對方（角色關係清單裡的描述，兩個方向各一句）、查手機的好感（兩個方向）、「私聊整理時自動留日記」開關（第 6 批才真的用到，先放設定）。

### 3.4 路線設定頁（全螢幕）

- 路線四選一（含未指定），每個下面一行說明；友情那個寫清楚「選了之後，羈絆再深也不會往戀愛走，角色也不會被引導成暗戀」。
- 階段：照路線列內建的＋自訂；親情線填稱謂（角色 × 角色兩邊各一格）。
- 改的時候問一次：「這是修正設定，還是關係真的變了？」→ `fix`／`turn`；轉折可以寫一句備註、選故事日期。
- 下方是路線歷程。

### 3.5 角色邀請建立

- 新標籤 `[[BOND_INVITE|一句話]]`：角色想要一個你們兩人的空間時用（提示詞只在「這條線還沒有空間紀錄」時教，一條線最多教到你回應為止）。
- 聊天裡變成一張邀請卡（同好友申請卡的樣式）：「〔角色〕想跟你建一個羈絆空間：『一句話』〔好〕〔先不要〕」。好 → 寫一筆 `openedBy: 'char'`，路線仍是未指定，順手開路線設定頁；先不要 → 記下來，這條線不再教這個標籤。
- 你邀請角色：空間清單「＋」建好後，私聊自動補一則系統小字「你建了你們的羈絆空間」，角色下一輪看得到（不強迫他回）。
- 雲端（即時對話、主動消息）收件也要認這個標籤（worker 直通，跟 `[[TODO|…]]` 一樣）。

### 3.6 視覺基調

- 只套在羈絆 App 裡（`.bond-root` 底下）：米白紙色底、暖灰字、細分隔線、扁平色塊，灰粉／低彩度酒紅少量點綴。先給一組色票（`--bond-paper`、`--bond-ink`、`--bond-muted`、`--bond-line`、`--bond-accent`、`--bond-accent-soft`），Liora 看過再調。
- 標題和敘事文字用襯線字（Google Fonts 加 Noto Serif TC；操作文字和小數字用 App 原本的字），一頁最多兩套字。
- Lv.、天數這類數字做成頁邊小註記的分量，不做大徽章。
