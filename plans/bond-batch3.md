## 1. 資料

### 1.1 日記：沿用 `diaries` 表，加線和雙方的狀態

日記本來就是 `DiaryEntry`（`diaries` 表，一個角色一天一本：你的一頁＋角色的一頁），**不另開一張**，照 bond.md 第 2 節第 7 條「已有的東西不做第二份」。要改的：

```ts
interface DiaryEntry {
    id: string;
    charId: string;
    /** 新：掛在哪段關係（bondIdForChar；舊資料沒有，開機補成主線那張卡的空間） */
    bondId?: string;
    /** 這一本的日期（照這條線的故事時間，makeChatClock；可以改） */
    date: string;
    /** 改成可以沒有：角色可以先寫，你的那頁還空著 */
    userPage?: DiaryPage;
    charPage?: DiaryPage;
    timestamp: number;
    isArchived: boolean;
    chatCardMessageId?: number;
    autoSync?: boolean;
}

interface DiaryPage {
    text: string;
    paperStyle: string;
    stickers: StickerData[];
    /** 新：寫下（最後一次改）的時間 */
    writtenAt?: number;
    /** 新：發布的時間；沒有＝草稿，只有作者自己知道 */
    publishedAt?: number;
    /** 新：誰產生的（角色主動寫、你請 TA 回、你自己寫） */
    createdBy?: 'user' | 'ai' | 'ai_scheduled';
    /** 新：你第一次改角色那頁之前的原文（跟隨筆一樣留著對照） */
    originalText?: string;
    revisedAt?: number;
    /** 新：你讀過角色這頁的時間（首頁「新日記」用） */
    seenAt?: number;
}
```

- **舊資料搬家**：開機時沒有 `bondId` 的日記補成那個角色主線的空間（`bondIdForChar(char)`）；舊的你那頁算已發布（以前寫了就會被讀到）；舊的角色那頁算已發布、`createdBy: 'ai'`。只補欄位，不動內容；搬一次記在 localStorage，跟行事曆搬時光契約同一個做法。
- **一天一本、雙頁感**：一本裡雙方各一頁；誰先寫都行，另一方可以「回這一頁」，也可以不回（紀要：不要求每次雙方都完成）。同一天想再寫就是改自己那頁，或在另一天開新的一本。
- **發布才算說出口**：你那頁有「存草稿」和「發布」兩個鈕；角色主動寫的、你請 TA 回的，生成完直接發布（跟隨筆不同：隨筆是你看過才收下，日記是 TA 寫給你的，寫完就給你了）；不滿意可以「請 TA 重寫」（原本的那版留在 `originalText`）。
- **同步私聊**（這段關係的日記設定）：開著時，角色那頁發布後在私聊送出日記卡（就是現在的 `diary_card` score_card，沿用 `syncDiaryCardToChat`），角色主動寫的另外加一句 TA 自己的口吻（「寫了日記，放在羈絆那邊」這類，跟日記一起生成）；關著就只在羈絆裡。**同步只管傳不傳訊，不管知不知道**：發布了就進提示詞，跟有沒有傳卡無關（紀要 4.1）。
- **刪除**：刪一本照舊連聊天卡一起刪。

### 1.2 拾光問答：`bond_entries` 的 `question`

```ts
// BondEntry 加
kind: 'moment' | 'essay' | 'diary' | 'question' | 'note';   // diary 不用（日記在 diaries 表），先占名字給第 6 批角色之間的日記
question?: BondQuestion;

interface BondQuestion {
    /** 題目；改題目等於開新卡，舊卡不動 */
    prompt: string;
    /** 題目從哪來 */
    origin: 'ai_suggest' | 'user' | 'char';
    /** 主題（推薦題目用、清單篩選用） */
    topic?: 'habit' | 'memory' | 'choice' | 'relationship' | 'daily' | 'custom';
    /** 一輪一輪的回答；重答＝開新的一輪，舊的整輪留著 */
    rounds: BondQuestionRound[];
}

interface BondQuestionRound {
    startedAt: number;
    /** 這一輪誰先答（發起的人） */
    openedBy: 'user' | string;
    user?: BondAnswer;
    char?: BondAnswer;
    /** 雙方都封存（或一方跳過、另一方封存）那刻 */
    revealedAt?: number;
}

interface BondAnswer {
    text: string;
    /** draft：暫存（只有自己知道）；sealed：封存，等對方；skipped：跳過這題 */
    state: 'draft' | 'sealed' | 'skipped';
    at: number;
}
```

- **發起者先答並封存**：你出題（或從 AI 推薦挑一題）＝你先答，封存後題目才送到角色那邊；角色出題時同時交出並封存 TA 的答案，你答完才揭曉。
- **盲答是真的盲**：生成角色答案時，**提示詞裡沒有你封存的答案**（`promptQuestions` 跟顯示用同一套判斷，第 2 節）。
- **揭曉**：雙方都封存那刻揭曉；一方跳過也算揭曉（另一方的答案攤開，跳過那方顯示「這題先跳過了」）。
- **重答**：揭曉後隔一段時間可以「再答一次」，開新的一輪（雙方重答、同樣盲答）；頁面上一輪一輪排下來，看得到想法怎麼變。答案不同不解讀、不扣分（紀要 3.7）。
- **AI 推薦題目**：按「換幾題」讓副 API 依路線、階段、最近發生的事出 5 題候選（主題標在旁邊），只是候選、不存；選中才變成你發起的題。
- `status` 沿用：還在等人回答的是 `published`（題目雙方都知道），你出題但還在寫答案、還沒送出的是 `draft`。

### 1.3 心靈角落：`bond_entries` 的 `note`

```ts
// BondEntry 加
note?: BondNote;

interface BondNote {
    /** 標籤；內建六個，可以自己加（自訂的存在 bonds.noteTags） */
    tags: string[];
    /** 回應：這張是在回哪張紙條（links 也記，刪除對齊用） */
    replyTo?: string;
    /** 收到的那方標的狀態；有回應不等於說開 */
    state?: 'want_to_talk' | 'responded' | 'resolved';
    /** 收到的那方讀過的時間（首頁「新紙條」用） */
    seenAt?: number;
    deliveredAt?: number;
}
```

- **投遞才算說出口**：你寫好按「投遞」才進角色的提示詞；草稿（`status: 'draft'`）只有你知道。角色的紙條是「攢夠了、想說了才丟」：生成完直接投遞，TA 不會有讓你看得到的草稿。
- **內建標籤**：吐槽、掛念、想一起做的事、心結、開心的事、沒說出口的話；可以新增自己的。
- **回應**：對一張紙條可以「回一張」（`replyTo`），或「帶去聊聊」；角色收到你的紙條後，可以在下一次主動產出時回一張（也可以你按「請 TA 回」）。
- **狀態**：收到的那方可以標「想再談」「已回應」「已說開」，角色看到的是狀態本身（第 2 節），不會把「已回應」當成「已解決」。
- **不捏造**：重大心結、創傷要有設定或事件依據；沒有新互動時回望舊片段、接續沒說完的話，不重述同一件事（紀要 3.8，寫進提示詞）。友情、親情線照樣有鎖定，紙條不能變成偷渡暗戀的入口。

### 1.4 主動產出設定：`bonds.output`

```ts
interface BondRecord {
    // …
    /** 主動產出（第 3 批）；沒設＝照預設 */
    output?: Partial<Record<BondOutputKind, BondOutputSetting>>;
    /** 每一種上一次產出的時間（事件觸發或保底都算，下一輪從這裡起算） */
    outputLast?: Partial<Record<BondOutputKind, number>>;
    /** 有值得留下的事、還沒被寫進任何一份（事件觸發用） */
    outputEvents?: Array<{ kind: 'daily_summary' | 'date_end' | 'moment' | 'note_received' | 'question_received'; at: number; ref?: string }>;
    /** 自己加的紙條標籤 */
    noteTags?: string[];
}

type BondOutputKind = 'diary' | 'question' | 'note' | 'essay';

interface BondOutputSetting {
    enabled: boolean;
    /** 每隔幾天一次（區間；到點在區間內隨機挑一天，不固定週期） */
    everyDays: [number, number];
    /** 篇幅：短／中／長，各自對應字數區間（日記另外可以填數字） */
    length: 'short' | 'medium' | 'long' | { min: number; max: number };
    /** 文風（只有日記用，空＝照角色個性） */
    style?: string;
    /** 投遞時段（你的裝置時間），例如 21:00–23:30；沒設＝全天 */
    window?: { from: string; to: string };
    /** 同步進私聊（另外傳一則訊息） */
    syncToChat: boolean;
    /** 暫停到哪天（暫停不等於關掉，到期自己恢復） */
    pausedUntil?: number;
}
```

**預設值**（紀要 4.3 的起步建議；都能改）：

| 類型 | 預設區間 | 篇幅 | 同步私聊 | 預設投遞時段 |
|---|---|---|---|---|
| 日記 | 每 1～3 天 | 中（200～500 字） | 開 | 20:00–23:30 |
| 拾光問答 | 每 3～7 天 | 短 | 開（傳「出了一題給你」） | 全天 |
| 心靈角落 | 每 3～7 天 | 短（可以只有一句） | 關（紙條就是要你自己去看） | 全天 |
| 隨筆 | 每 5～10 天 | 照角色個性 | 關 | 全天 |

**整體上限與錯開**（寫成常數，設定頁可調）：

- 每段關係一天最多 2 份、任兩份之間至少隔 3 小時；
- 全部關係加起來一天最多 6 份（多的順延到明天，先排最久沒產出的）；
- 同一種類型產出一次後，下一輪從這次起算（事件觸發的也算，不會剛被事件觸發又馬上補一份保底，紀要 4.3 第 5 條）。

### 1.5 事件觸發＋區間保底

- **事件**：每日總結寫好（`memories` 多一筆，照線）、一場見面結束、你收存了一個片刻、你投遞了紙條、你出了一題給 TA。發生時記進 `outputEvents`（只記，不立刻生成）。
- **提早觸發**：有事件、且離上一次這種產出已過區間下限的一半，就在下一個投遞時段排一份（日記吃總結和見面、紙條吃你的紙條和情緒、問答吃你出的題、隨筆吃片刻）。
- **保底**：沒有事件，到了區間（在 `everyDays` 裡隨機挑的那天）就在投遞時段排一份。
- **沒有新互動時**：提示詞會說「可以回望舊片段、接續沒說完的話題、從人設出發」，不捏造新的對話、心結或共同經歷（紀要 4.3 第 6 條）。
- **同一件事不重述**：生成時帶這件事已經在哪裡留過痕跡（隨筆、日記、紙條的標題），要求帶來新的理解（紀要 4.3 第 7 條）。
- **誰不產出**：下戲的角色（`isOnStage` 為假）、拉黑中的線、沒開羈絆空間的小號、角色之間的空間（第 6 批照「有新經歷才寫」另做）。

### 1.6 誰來跑：本機排程＋雲端後台任務

照「每天到點生成日程」那條路（`plans/calendar.md` 第 5 批；bond.md 第 0 節第 2 條：雲端 worker 可以加東西）：

- **本機**：OSContext 每 5 分鐘的 tick 多一個「羈絆產出」，純判斷 `decideBondOutputs(spaces, now)`（有測試）挑出到期的，一次跑一份、錯開；App 打開時補跑到期還沒寫的。
- **雲端**：開了主動消息 2.0 的角色，每段關係上傳一份 standing job（`amsg:job` 的 `bond-output:<bondId>`：人設上下文、這段關係的羈絆段、最近的總結、設定、下一次各類型的到期時間），worker 在 `fireKinds.ts` 多一個 `amsgKind: 'bond-output'`，到點生成、`ctx.emitResult` 送回，客戶端收件後落庫（日記寫 `diaries`、其他寫 `bond_entries`）；同步私聊那句走現成的主動消息收件路（推播照舊）。提示詞本體放零依賴的 `utils/bond/outputPromptCore.ts`，本機和 worker 同一份。
- **對帳**：本機和雲端不會重複寫同一份：客戶端排雲端時記 `outputLast` 的「已交給雲端」標記，雲端結果回來或過期（超過 1 天沒回）才換本機補。Worker 還沒更新的（不認得 `bond-output`），客戶端看版本號退回本機。

## 2. 提示詞：誰知道什麼

照紀要 4.1，**生成和顯示用同一套判斷**（`utils/bond/visibility.ts`，有測試），`bondPromptBlock` 接在第 2 批那兩段後面多三小段：

| 段 | 內容 | 不帶的 |
|---|---|---|
| 【你們的日記】 | 最近 2 本已發布的，雙方的頁各取前 200 字，標「寫給對方看的」 | 你的草稿 |
| 【拾光問答】 | 最近 3 題已揭曉的（題目＋雙方答案，舊一輪也標出來）；你封存、對方還沒答的（只寫你的答案，標「還沒揭曉，對方還看不到」）；對方問你、你還沒答的（只有題目） | 對方封存還沒揭曉的答案、對方的暫存 |
| 【心靈角落】 | 最近 5 張已投遞的紙條（誰丟的、標籤、內容前 120 字、收到的那方標的狀態） | 你的草稿紙條 |

- 沒有這三種內容時**提示詞一字不差**（測試鎖著，跟第 2 批同一招）。
- 角色寫日記、出題、丟紙條、寫隨筆時帶的段：人設、羈絆段（含上面三段）、這條線最近的每日總結、最近一段私聊（照 `loadCharacterContextMessages`）、這件事已在哪裡留過痕跡；角色答題時**不帶你封存的答案**。
- 角色之間的空間不變（這批沒有他們的心意）。

## 3. 「心意」分頁

紀要 7.2：「我們／拾光／心意／約定／珍藏」五個主分頁，這批加第三個（身份卡 × 角色的空間才有）。

### 3.1 版面

- 上方三個小分頁：**日記／問答／紙條**，旁邊有一顆「主動產出」設定（全螢幕設定頁）。
- **日記**：月曆（沿用交換日記的月曆）＋清單；每一本顯示日期、誰寫了（你／TA／都寫了）、有沒有新的。點進去是雙頁（左右翻或上下兩頁，手機寬度用上下），每頁有信紙和貼紙（沿用交換日記的 `PAPER_STYLES`、貼紙），角色那頁沒讀過的有小標記。
- **問答**：等你回答的放最上面，再來是等 TA 的、已揭曉的；右上「出一題」（自己寫，或「換幾題」看 AI 推薦）。
- **紙條**：一面「信箱」：TA 丟給你的、你丟的，各自的狀態；右上「寫一張」。

### 3.2 全螢幕頁

- **寫日記**：日期（預設今天，故事時間；可以改）、信紙、正文、貼紙；「存草稿」「發布」；角色那頁還空著時有「請 TA 回這一頁」（帶上你這頁、照日記設定的篇幅和文風）。
- **讀一本日記**：兩頁、各自的寫下時間、角色那頁的「請 TA 重寫」「看原本的版本」「帶去聊聊」、你那頁的「編輯」。
- **一題問答**：題目、每一輪（揭曉前只看得到自己的；暫存、封存、跳過）、「再答一次」。
- **寫一張紙條**：標籤（多選，可加）、內容；「存草稿」「投遞」。
- **讀一張紙條**：內容、標籤、投遞時間、回應串（回一張、請 TA 回）、狀態（想再談／已回應／已說開）、帶去聊聊。
- **主動產出設定**：四種類型各一區（開關、區間、篇幅、文風（日記）、投遞時段、同步私聊、暫停到…），下面寫「下一次大概什麼時候」（照現在的設定和上次產出估的）。

### 3.3 首頁「最近值得留意的一件事」（紀要 7.3 第 2 點）

放在「此刻的我們」下面、「下一個紀念日」上面，只挑一則，順序：TA 丟來還沒讀的紙條 → 等你回答的問答 → 還沒讀的新日記 → 剛揭曉的問答。點了直接開那一則；都沒有時這塊不出現。
