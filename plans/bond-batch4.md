## 1. 資料

### 1.1 願望：`bond_entries` 的 `wish`

```ts
interface BondWish {
    /** 誰的願望：'user'＝你、角色 id＝TA、'both'＝我們想一起完成的 */
    owner: 'user' | string | 'both';
    state: 'want' | 'agreed' | 'done' | 'shelved';   // 想做／已約好／完成／暫時擱著
    /** 對方表示支持（不等於答應一起做）：誰、什麼時候、說了什麼 */
    support?: { by: 'user' | string; at: number; words?: string };
    /** 談妥了：變成哪一個共同約定 */
    promiseId?: string;
    /** 完成：什麼時候、連到哪些拾光（片刻／記憶） */
    doneAt?: number;
    doneLinks?: BondLink[];
}
```

- 卡片 `text` 是願望內容；`author` 是寫下的人；草稿／發布跟紙條一樣，**發布的才是雙方知道的**。
- **看見不等於答應**：你寫了願望，角色知道，但它不會因此被寫成「已約好」；要變成共同約定得走 1.2 的「說好」。
- 個人的願望可以只得到支持，不必轉成雙人任務（紀要 3.5）。
- 從聊天收存時不能把單方願望自動變成共同約定：收存頁會問「這是誰的願望」，預設是說出口的那一方。

### 1.2 共同約定（含任務）：`bond_entries` 的 `promise`

```ts
interface BondPromise {
    /** 一次性（一起看海）或重複的（每天晚安） */
    repeat: { kind: 'once' } | { kind: 'daily' } | { kind: 'weekly'; days?: number[] } | { kind: 'monthly' } | { kind: 'everyNDays'; n: number } | { kind: 'yearly'; date: string };
    /** 參與者：你和 TA（身份卡 × 角色就是這兩位） */
    participants: Array<'user' | string>;
    /** 完成依據：照實際紀錄自動判、你手動確認、或請 AI 讀那天的聊天判斷 */
    check: BondTaskCheck;
    /** 計分：不計分就是單純的約定 */
    points?: number;
    /** 誰說好了：雙方都說好才成立 */
    agreedBy: { user?: number; char?: number };
    state: 'proposed' | 'active' | 'paused' | 'done' | 'dropped';
    /** 從哪個願望談來的、用的哪個模板 */
    fromWishId?: string;
    templateId?: string;
    /** 連續天數紀念（重複的約定才有）：目前連續、最長、最近一次斷在哪天 */
    streak?: { current: number; best: number; lastDay?: string; brokeOn?: string };
}

type BondTaskCheck =
    | { kind: 'record'; record: 'chat' | 'goodnight' | 'photo' | 'call' | 'date' | 'music'; min?: number }
    | { kind: 'manual' }
    | { kind: 'ai'; hint: string }       // 請 AI 讀那天這條線的聊天判斷（副 API），回「是／否＋依據哪幾則」
    | { kind: 'keyword'; words: string[]; both: boolean };
```

- **說好才成立**：你提的約定，按「問問 TA」讓角色照人設回答（答應、想改一下、這次先不要），答應了才是 `active`；角色提的（1.7、4.3）在你這邊是一張「TA 提議」的卡，你按好才成立。提議中的約定不計分、不進「約定」的提示詞段（只進「還在商量」那一小行）。
- **任務模板**（紀要 3.9 原始需求）：

| 模板 | 預設頻率 | 完成依據（照實際紀錄） | 預設分數 |
|---|---|---|---|
| 今日聊幾句 | 每天 | 這條線當天你至少 3 則、TA 至少 1 則 | 1 |
| 互道晚安 | 每天 | 當天雙方各有一則帶「晚安／good night／睡了」的訊息（判不到可以手動補） | 1 |
| 分享照片 | 每天 | 當天這條線有照片（你傳的圖、TA 的 `SEND_PHOTO`／`SEND_SAVED_PHOTO`） | 2 |
| 連續互動 | — | 不是另一個任務，是「今日聊幾句」的連續天數紀念（見下面） | — |
| 通話 | 每週 | 這條線有通話紀錄（`metadata.source: 'call'`，你至少說過一句） | 3 |
| 見面 | 每週 | 有見面（`metadata.source: 'date'` 或這條線的線下故事當天有新段落） | 5 |
| 一起聽歌 | 每週 | 當天有 TA 決定一起聽的音樂卡（`music_card` 的 `join`／`join_and_add`） | 2 |

  三條路線的模板清單一樣，文案照路線換（例如友情線的「互道晚安」寫「睡前說一聲」）；你可以改頻率、分數、依據，也可以全部自訂。
- **連續天數**：重複的約定各自記連續；斷了只把 `current` 歸零、`best` 和已加的分都留著（紀要 3.9「中斷時保留已累積的經歷」）。連到 7／30／100／365 天記一筆里程碑。

### 1.3 完成紀錄與積點：新表 `bond_ledger`

完成一次就是一筆，跟卡片分開放（一年的每日任務會有幾百筆，不塞進 `bond_entries` 的登記表）：

```ts
interface BondLedgerRow {
    id: string;                 // `${bondId}|${promiseId}|${periodKey}`：同一個約定同一期只有一筆 → 不重複加分
    bondId: string;
    promiseId: string;
    periodKey: string;          // 每天 'YYYY-MM-DD'、每週 'YYYY-Www'、每月 'YYYY-MM'、一次性 'once'
    at: number;
    points: number;             // 記下當時的分數（之後改分數不回頭改舊紀錄）
    how: 'auto' | 'manual' | 'ai';
    /** 依據：哪幾則訊息、哪段通話、哪個見面、AI 判讀的理由 */
    evidence?: { messageIds?: number[]; storyId?: string; reason?: string };
    /** 你撤銷的：留著但不算分 */
    revokedAt?: number;
}
```

- **id 就是去重**：同一個約定、同一期，自動判和手動補只會留一筆。撤銷的保留（看得到「撤銷了」），可以恢復。
- **期**照你裝置的日期（任務是你們兩個一起做的，跟角色時區無關；`docs/character-timezone.md` 的「用戶自己的時間」）。
- **總積點**＝沒撤銷的加總；等級照門檻表算（第 10 節第 1 題），不另存，改門檻就重算。
- 新表要登記進 OSContext 的 `allStores`、`textOnlyFieldByStore`、匯出的 `switch` 和 `importFullData`（`utils/backupStoreCoverage.test.ts` 會擋）；刪角色、刪身份卡跟著清。

### 1.4 我們的默契：`bond_entries` 的 `habit`

```ts
interface BondHabit {
    /** 雙方確認的時間；兩邊都有才算數 */
    confirmedBy: { user?: number; char?: number };
    /** 說好的、還是反覆形成的（只是顯示用） */
    origin: 'agreed' | 'formed';
    /** 從哪幾則聊天、哪些片刻看出來的 */
    examples?: BondLink[];
    state: 'proposed' | 'active' | 'retired';
}
```

- **單方期待不能直接登記成默契**（紀要 6.2）：你寫的默契要 TA 確認（「問問 TA」，角色照人設認或不認），TA 提的要你按「對」。兩邊都確認才 `active`、才進提示詞。
- 默契跟一次性的任務完成紀錄分開：它沒有分數，會一直參與日後相處（提示詞每次都帶）。
- 可以「不再這樣了」（`retired`），保留在清單裡、不進提示詞。

### 1.5 事件卡與里程碑

**事件卡**（`bond_entries` 的 `eventCard`）：

```ts
interface BondEventCard {
    cardId: string;          // 內建清單裡的哪一張（第 2.2 節）或自訂
    state: 'locked' | 'unlocked' | 'playing' | 'done' | 'setAside';
    unlockedAt?: number;
    /** 在哪演：私聊（帶一段情境進下一輪）或見面（開一場新的線下故事） */
    venue?: 'chat' | 'date';
    startedAt?: number;
    /** 演完你確認的結果：成了（照卡片的去向改階段）、還沒（保持原樣，可以再演）、換個方向 */
    outcome?: { result: 'yes' | 'notYet' | 'other'; at: number; note?: string; storyId?: string };
}
```

**里程碑**（`bond_entries` 的 `milestone`）：一件已經發生的關係大事（告白成功、交往、求婚、摯友、和解…），帶日期、來源（事件卡、聊天的那幾則、每日總結那一筆、你手動補的）。

- 里程碑也會出現在拾光的時間線上（跟片刻同一條路，類型另外標）；可以選「同時記成紀念日」（行事曆 `CalendarEvent` 的 `anniversary`，帶參與者，首頁「下一個紀念日」自然就讀到）。
- 改階段一律寫進路線歷程（`routeLog`，第 1 批的「記錄轉折」），標出是哪張事件卡或哪段聊天。

### 1.7 角色主動：願望與提議

- 主動產出（第 3 批）多一種「願望」：角色寫一張自己的願望（或「想跟你一起做的事」），照人設、最近的事；預設 7～14 天一次，跟其他四種同一套上限、錯開、雲端。

## 2. 等級、事件卡、階段推進

### 2.1 等級

- 起步門檻（第 10 節第 1 題）：Lv.1 0 分、Lv.2 20、Lv.3 60、Lv.4 120、Lv.5 200、Lv.6 320、Lv.7 480、Lv.8 680、Lv.9 920、Lv.10 1200，之後每級再加 300。照預設任務，天天聊幾句＋晚安一個月大約到 Lv.3，加上每週通話、見面大約到 Lv.4。
- **等級不換身份**（紀要 3.9）：等級只解鎖「事件的機會」；友情線、親情線升到幾級都不會往戀愛走，親情升級不改血緣。
- 首頁主視覺：`Lv.3` 放在天數旁邊，像頁邊註記；點了進約定分頁的積點頁。

### 2.3 開演與結果

1. **選在哪演**：私聊（下一輪的系統提示詞帶一段「事件情境」，只帶一輪，角色照自己的方式開口或回應）或見面（開一場新的線下故事，開場白照事件寫）。
2. **情境帶什麼**（紀要 3.9「事件卡帶入這一對的願望、回憶與禮物」）：卡片的主題、這段關係最近的里程碑、跟主題相關的願望（例如「想一起看海」）、幾件代表性的拾光；禮物第 5 批接上。**角色怎麼表達照它自己**：情境只說「這是一個可能發生 X 的時刻」，不寫台詞、不保證答應——角色可以猶豫、拒絕、要時間。
3. **結束**：在約定分頁那張卡上按「演完了」，副 API 讀從開演到現在的那段（私聊或見面故事）整理一句結果和依據（「他說他也是，所以答應了」），你選：成了／還沒／換個方向。**成了**才改階段、記里程碑（＋可選紀念日）；**還沒**卡片回到解鎖狀態，可以之後再演；整段對話照舊留在私聊或見面裡。
4. 階段改了要打髒（路線、階段進提示詞，第 1 批的規則）。

### 2.4 聊天先發展：同步承認

紀要 3.9：「若已在聊天裡自然告白成功，直接同步承認並補上里程碑，不因等級不足阻擋既成關係。」

- **看哪裡**：角色用 `[[ACTION:RELATIONSHIP|…]]` 改了「角色認為的關係」（已經有，`CHAR_RELATIONSHIP_CHANGE_EVENT`），以及每日總結（記憶多一筆的時候，第 3 批已經在看）。
- **怎麼判**：副 API 讀那一段（改關係的那則前後、或那天的總結），回「看起來是：告白成功／開始交往／求婚成功／成為摯友／和好…（或什麼都不是）＋依據」。看起來有，而且跟目前階段不同，就在首頁跳一張「看起來你們 11 月 26 日在一起了，要記下來嗎？」，列出依據（點了跳回那則訊息）。
- **你按「對」**：改階段、記里程碑（來源是那幾則聊天或那筆總結）、可選紀念日；按「不是」記下來不再問同一段（`syncAsked`）。
- **路線擋**：友情線、親情線看到戀愛的變化一律不問（第 1 批的規則：AI 不改路線，這裡也不鼓勵你改；你真的要改去路線頁）。未指定路線看到告白成功，卡片會問「要把路線設成戀愛嗎」，兩件事一起確認。
- 等級不夠也照樣承認；之後的事件卡從新的階段接著排。

## 3. 提示詞：誰知道什麼

照紀要 4.1，`bondPromptBlock` 接在第 3 批後面多一段【你們的約定】，生成和顯示同一套判斷（`utils/bond/visibility.ts` 加 `knownWishes`／`knownPromises`／`knownHabits`）：

| 內容 | 帶 | 不帶 |
|---|---|---|
| 願望 | 發布的、最近 6 個（誰的、狀態、對方支持了沒） | 草稿 |
| 共同約定 | 成立的（`active`）全部：內容、頻率、今天／這期做了沒、連續幾天；提議中的一行「還在商量：…」 | 你撤銷掉的紀錄、`dropped` 的 |
| 默契 | 雙方確認的全部 | 提議中、不再這樣的 |
| 里程碑 | 最近 3 個（日期、什麼事） | — |
| 等級 | 一句「你們的羈絆等級是 Lv.N」——**只在戀愛線以外不帶任何「往戀愛發展」的暗示**；友情、親情鎖定段照舊在最後 | — |

- 沒有這些內容時**提示詞一字不差**（測試鎖著）。
- 事件卡情境只在開演那一輪帶（2.3），不常駐。
- 角色寫願望、回應約定、確認默契時，帶人設、羈絆段、最近的總結和私聊；回應你的約定時**不知道你心裡希望它答應**（提示詞只給內容，不給「請答應」的暗示）。

## 4. 「約定」分頁

紀要 7.2：「我們／拾光／心意／約定／珍藏」，這批加第四個（身份卡 × 角色才有）。

### 4.1 版面

- 上方四個小分頁：**願望／約定／默契／里程碑**。
- **願望**：三欄篩選（我的／TA 的／我們的），每張顯示狀態；右上「寫一個」。
- **約定**：成立的在上（今天這期做了沒的小勾、連續天數），提議中的、暫停的在下；右上「新增」（自己寫／從模板挑）。
- **默契**：雙方確認的一張張小卡；提議中的灰一點，寫著等誰確認。
- **里程碑**：等級與積點進度條（頁邊註記的樣子）、完成紀錄入口、事件卡（解鎖的、鎖著的、放著的）、已經發生的里程碑（時間由新到舊）。

### 4.2 全螢幕頁

- **寫願望**：誰的（我的／我們的；TA 的只能由角色寫或你從聊天收存）、內容、「存草稿」「發布」。
- **一個願望**：內容、狀態、支持（「問問 TA 怎麼想」）、「談成約定」（帶進新增約定，標 `fromWishId`）、「完成了」（挑拾光連上）、暫時擱著、帶去聊聊。
- **新增／編輯約定**：內容、頻率、完成依據（實際紀錄／手動／AI 判讀／關鍵字）、要不要計分與分數；存了是「提議中」，按「問問 TA」看角色答不答應（或直接帶去聊聊跟 TA 討論，紀要 3.9「先丟到 chat 與角色討論」）。
- **一個約定**：每一期的勾（月曆）、連續天數、完成紀錄（依據、撤銷／恢復、補記一筆）、暫停、結束、帶去聊聊。
- **完成紀錄**：全部約定的紀錄，照時間排，能篩、能撤銷、能補記。
- **一張事件卡**：主題、會帶進去的願望與回憶（可以勾掉）、在哪演、「開演」；演過的顯示結果和依據；「先放著」。
- **同步承認卡**：依據（可跳回原文）、要改成什麼、要不要記紀念日、「對」「不是」。

### 4.3 首頁

- 主視覺：天數旁邊加 `Lv.N`（小字、頁邊註記）。
- 「最近值得留意」多三種（照順序插在紙條後面）：等你確認的同步承認、剛解鎖的事件卡、TA 提的約定／默契。
- 紀要 7.3 第 5 點「近期共同約定入口」：一行列出今天這期還沒做的約定（最多 3 個），點了進約定分頁。

## 5. 完成判定怎麼跑

- **自動判**（`utils/bond/taskCheck.ts`，純函式有測試）：給一條線一期的訊息（照 `periodKey` 撈），照 `check.record` 判；回「完成＋依據的訊息 id」。
- **什麼時候判**：OSContext 的 5 分鐘 tick 順便看（跟主動產出同一個），只看「這期還沒完成、有新訊息」的約定；寫一則訊息不會立刻判。開 App 時補判昨天和上一週（跨天才判得完整的，例如晚安）。
- **AI 判讀**（`check.kind === 'ai'`）：一期結束後判一次（副 API），回是／否＋理由＋依據哪幾則；判否不重試，你可以手動補。
- **雲端**：完成判定只在本機（要讀 IndexedDB 的訊息），App 關著時不判，開 App 補判（不會漏分，因為一期的紀錄都還在）。

## 6. 聊天銜接（紀要 4.4）

- **收存頁**（第 2 批的 `bondLaunch.collect`）多三種「收成」：願望、約定、默契；AI 幫忙填欄位（只照那幾則寫，資訊不夠的留空讓你補，紀要 4.4「保留待補狀態，不擅自補完」）；收存成約定或默契時預設是「提議中」，要對方確認。
- **從最近的聊天挑幾件**：候選多三種（願望、約定、默契），一樣你勾了才存。
- **帶去聊聊**：願望、約定、默契、里程碑四種卡（`bondRef` 多四種寫法）。
- **角色在聊天提議**：1.7 的兩個標籤；私聊、雲端即時對話、主動消息都要接（worker 直通，跟 `BOND_INVITE` 一樣）。

2. **4b**：任務模板、完成判定（自動、手動、AI、關鍵字，純判斷有測試）、完成紀錄（撤銷、補記、不重複）、連續天數、積點與等級、首頁 Lv. 與近期約定入口。

## 10. 待 Liora 定

1. **分數與等級門檻起步值**：任務分數照 1.2 的表（聊幾句 1、晚安 1、照片 2、通話 3、見面 5、聽歌 2），等級照 2.1 的表（一個月天天聊大約 Lv.3）。要不要調？之後在設定裡能改嗎？建議**分數每個約定都能改、門檻固定**（門檻改來改去，等級就沒有意義了）。
2. **漸進的階段（朋友→曖昧、朋友→摯友）怎麼推進**：建議**跟明確身份一樣，系統提出、你按「對」才改**（事件卡演成了、或同步承認看到了）；另一個選法是到了條件就自動往前、事後通知你、可以撤回。
3. **事件卡預設在哪演**：建議告白、求婚、婚禮、承認摯友、和解預設**見面**（一場完整的線下故事），其他預設**私聊**；開演前都能改。
4. **角色主動的部分要不要都做**：角色在聊天裡提議約定與默契（兩個標籤）、主動產出多一種「願望」。建議**都做**，提議一律等你按好才成立。
5. **晚安這種主觀任務判不到時**：建議**先照關鍵字判，判不到留給你手動補**，不另外叫 AI；只有你自訂成「AI 判讀」的才叫副 API。
