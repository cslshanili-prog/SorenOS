# 單一貼文池（朋友圈）設計文件

路線圖第 6 項。這份是開工前的設計。

> **2026-09-25 定案**：三個待定都照建議——角色之間**單向**加好友就算朋友；互動**微信式**（只看得到自己朋友的讚和留言）；新貼文**不要**假路人互動。
> 「路人互動」之後會跟一個還沒具體規劃的「AI 生成角色卡抽卡」功能一起討論；資料結構裡的 `stranger` 身份先留著，搬遷來的舊路人留言就用它。

## 現況

- **兩個池子、互不相通**
  - Chat「動態」分頁：直接跳到舊的沖浪 App（`apps/SocialApp.tsx`，1275 行，`social_posts` 表），內容是隨機生成的，跟角色、用戶的生活沒有關係。
  - 查手機 → 軌跡 → Moments：每個角色各存一份在 `CharacterProfile.phoneState.trajectoryMoments`（`TrajectoryMomentPost[]`）。按按鈕生成一條「文案 + 一張生圖 + 假的點讚數 + 0–3 條路人評論」，純展示、不能互動；可以同步到私聊、存相冊、重生照片、刪除。
- **朋友圈互動設定**（第 3 項做好的）：`userProfile.momentsSettings`，誰能自動發帖、發帖間隔、留言／點讚機率、各種延遲。**目前沒有消費者**，就等這一項接上。
- **朋友關係的現成資料**
  - 角色之間：查手機通訊錄 `phoneState.contacts`，每條有 `kind`（real／npc）、`linkedCharId`／`linkedNpcId`、`status`（friend／pending／blocked／deleted）。
  - NPC：`NPCProfile.relationships[]`，對象是某個角色 id 或 `'user'`。

## 資料結構

新增一張 IndexedDB 表 `moment_posts`（keyPath `id`，索引 `authorId`、`createdAt`）。按讚和留言直接放在貼文裡：貼文數量不大，放一起讀寫簡單；改動一律走「讀－改－寫」的事務（跟 `DB.updateMessageMetadata` 同一種寫法），避免兩個留言同時寫入時互相覆蓋。

```ts
type MomentActorKind = 'user' | 'character' | 'npc' | 'stranger';

interface MomentActor {
    kind: MomentActorKind;
    /** 'user' / 角色 id / NPC id；stranger 沒有 id */
    id?: string;
    /** 名字快照：路人一定要有；其他人發文當下的名字，改名或刪除後展示用 */
    name: string;
}

interface MomentPost {
    id: string;
    author: MomentActor;              // 路人不能發文
    content: string;
    images: string[];                 // blobref 令牌
    imagePrompt?: string;             // 生圖描述，重生照片用
    visibility: {
        mode: 'friends' | 'public' | 'custom';
        /** mode = custom 時看得到的人（'user' / 角色 id / NPC id），可以多選 */
        allow?: string[];
    };
    likes: { actor: MomentActor; at: number }[];
    comments: {
        id: string;
        actor: MomentActor;
        content: string;
        at: number;
        /** 回覆某條留言（「A 回覆 B：…」） */
        replyTo?: string;
    }[];
    /** 舊的假點讚數（搬遷來的），只加在顯示的數字上，不對應任何人 */
    legacyLikeCount?: number;
    createdAt: number;
    /** 從哪來的：手動發、自動發、從軌跡 Moments 搬來的 */
    source: 'manual' | 'auto' | 'migrated';
    /** 同步到私聊寫入的消息 id（沿用 syncedMessageId 的作用） */
    syncedMessageId?: number;
}
```

用戶發文時存的是 `author: { kind: 'user', id: 'user', name: 當下的名字 }`。身份卡的處理見文末「用戶身份」。

## 可見範圍

一個函數 `canView(viewerId, post, graph)` 決定誰看得到，純函數、寫單測。

1. 作者自己 → 看得到
2. `public` → 所有人看得到
3. `custom` → 只有 `allow` 裡的人
4. `friends` → 作者跟看的人是朋友才看得到

**誰跟誰是朋友**（`areFriends(a, b)`）：

| | 用戶 | 角色 | NPC |
|---|---|---|---|
| **用戶** | — | 一律是朋友 | NPC 的關係清單裡有 `'user'` |
| **角色** | 一律是朋友 | 任一方通訊錄把對方標成 friend（單向） | NPC 的關係清單裡有這個角色，或角色通訊錄裡有綁這個 NPC、狀態是 friend |
| **NPC** | 同上 | 同上 | 不是朋友（NPC 的關係對象目前只能是角色或用戶） |

- 任何一方把另一方拉黑（`blocked`）或刪掉（`deleted`）→ 不是朋友，這條優先。
- **角色之間要「單向」還是「雙向」才算朋友？**（定案：單向）
  - **單向**（我建議這個）：任一方通訊錄裡把對方標成 friend 就算。查手機的通訊錄是生成出來的，兩邊常常不對稱，要求雙向的話很多角色互相看不到。
  - **雙向**：兩邊都標 friend 才算，比較真實，但朋友圈會比較空。
  - 第 4 項最後一批的「雙向拉黑」做好之後，拉黑直接套用上面「拉黑優先」那條。

**互動的可見範圍**（定案：微信式）

- **微信式**（我建議這個）：看得到一篇貼文，不代表看得到上面所有的讚和留言，只看得到**自己的朋友**按的讚、留的言。例如小雨發的文，用戶和 NPC 房東都留了言：用戶看得到房東的留言嗎？要看用戶跟房東是不是朋友。這樣「角色視角的朋友圈」跟「用戶視角的朋友圈」才真的不一樣。
- **全部公開**：看得到貼文就看得到所有互動。簡單，但角色視角和用戶視角只差在貼文，差異小。

## 兩個入口

- **Chat「動態」分頁 = 用戶視角**（`viewer = 'user'`）
  - 不再跳 SocialApp，改成直接嵌在 Chat 主頁的分頁裡：時間線、發文（文字 + 最多 9 張圖 + 可見範圍）、按讚、留言、回覆留言、刪自己的貼文和留言。
  - 看得到的：自己的、所有角色的（角色跟用戶一律是朋友）、跟用戶是朋友的 NPC 的，再按可見範圍過濾。
- **查手機 → 軌跡 → Moments = 角色視角**（`viewer = 這個角色`）
  - 版面保留現在的樣子（按日期分組、點開看大圖），內容換成這個角色看得到的整個池子，不只它自己發的。
  - 「生成一條」按鈕保留，生成的貼文落進池子，作者是這個角色，預設可見範圍 friends。
  - 同步到私聊、存相冊、重生照片照舊，但只對它自己發的貼文有效。
  - 軌跡相冊（`TrajectoryAlbum`）改讀池子裡這個角色自己發的貼文。
- **舊的沖浪 App（SocialApp）不動**，留在桌面當獨立 App。Chat 裡原本的「打開動態」入口拿掉。

## 生成與互動

所有會自動花 API 的東西都受第 3 項朋友圈互動設定控制，**總開關預設關**。

- **發文**
  - 手動：用戶自己發；軌跡 Moments 的「生成一條」。
  - 自動：總開關開著、沒被單獨關掉的角色／NPC，每人各自在「最短～最長間隔」之間隨機排下一次發文時間（存在 localStorage）。App 開著時檢查到點才發。文案用這個人自己的 API（角色走 `resolveCharacterChatApi`，NPC 走 `resolveNpcApi`）。生圖設定開著才配圖，照片走第 7 項的「佔位 → 補生成」那條路。
- **按讚、留言**
  - 一篇貼文發出來後，看得到它的每個角色／NPC 各自擲一次骰：按讚機率、留言機率。
  - 留言不是一人打一次 API：同一篇貼文、同一批要留言的人，**一次呼叫**像群聊導演模式那樣一起生成（每人一句），按「第一則留言延遲」「留言間隔」分批落地。NPC 另外多等「NPC 互動延遲」。
  - **用戶在角色貼文底下留言 → 作者一定回**，其他角色照留言機率決定要不要接話。角色回覆 NPC 留言的延遲用「回覆 NPC 留言延遲」。
  - 排好還沒落地的互動存成一張待辦表，重新整理頁面後接著跑。**只在 App 開著時跑**，第一版不搬到 Worker。
- **角色會知道朋友圈的事**
  - 私聊的易變段加一小段「最近的朋友圈」：這個角色看得到的最近幾篇，加上底下跟它有關的互動（它按讚／留言的、別人回它的、用戶留的），讓角色聊天時接得上「你昨天發的那張照片」。
  - NPC 的輕量記憶把朋友圈互動也整理進去（第 5 項 B 預留的來源）。
  - 主動消息 2.0 的雲端打包第一版不帶朋友圈。

## 搬遷

- App 啟動時跑一次（localStorage 記旗標，已經跑過就跳過）：每個角色的 `phoneState.trajectoryMoments` 逐條轉成池子裡的貼文。
  - 作者是這個角色，可見範圍 friends，`source: 'migrated'`。
  - 舊的假點讚數放進 `legacyLikeCount`。
  - 舊的路人評論轉成 `stranger` 留言，保留名字。
  - `syncedMessageId`、`imagePrompt`、圖片令牌原樣帶過去。
- 舊欄位**先不刪**，保留一個版本當退路；確認沒問題後再出一個小 PR 清掉。
- **新貼文還要不要假的路人讚和路人留言？**（定案：不要）
  - 我建議不要：新貼文只有真的人互動。舊的搬過來照樣顯示路人，不動它們。
  - 如果想保留「網紅感」，可以在設定加一個「路人互動」開關，預設關。

## 分批

1. **第一批：池子本身 + 兩個入口**
   - 表、資料結構、`canView`／`areFriends`（含單測）、搬遷。
   - Chat 動態分頁：時間線、發文、按讚、留言。
   - 軌跡 Moments 改成角色視角、「生成一條」寫進池子、軌跡相冊改讀池子。
   - 用戶在角色貼文底下留言時作者會回。
2. **第二批：自動化**
   - 自動發文排程、互動待辦表、留言的一次性生成。
   - NPC 參與發文和互動，並整理進 NPC 記憶。
   - 私聊易變段的「最近的朋友圈」。

每批各一個 PR，第一批做完你就能手動玩；第二批才開始自動花 API。

### 第二批落地實況

- **總開關只管自動發文**（設定頁原本就寫「關掉的不會自動發帖，但還是會看到、回應別人的動態」）。看到新貼文的反應照「按讚機率」「留言機率」走，不受總開關管；按讚不花 API，留言會花，調成 0% 就不自動留言。角色和 NPC 的機率分兩組調（NPC 留言預設 20%，比角色的 40% 低，NPC 多的時候免得洗版；舊存檔補預設，角色那組不動）。
- **自動發文**（`utils/momentsAuto.ts` 排程＋`utils/momentsAutoRuntime.ts` 執行）：總開關開著、沒被單獨關掉的角色／NPC 各自排下一次發文時間，存在 localStorage `soren_moments_next_post`。第一次在 2 分鐘～min(最短間隔, 6 小時) 之間隨機（不然開了總開關要等 48 小時才看得到第一篇），之後照「最短～最長間隔」。App 開著時每分鐘看一次，一輪最多發一篇；失敗的人往後推 30 分鐘。角色走 `generateCharacterMoment`（生圖設定開著才配圖），NPC 走 `generateNpcMoment`（純文字，用 NPC 自己的 API）。
- **看到新貼文的反應**：`createMomentPost` 廣播 `moment-created`，OSContext 替看得到的角色／NPC 各擲一次骰子，排進待辦（localStorage `soren_moments_jobs`）：
  - 讚：在「首則留言延遲」之內隨機一個時間點。
  - 留言：角色一批在「首則留言延遲」後，NPC 一批再多等「NPC 互動延遲」；一批只打一次模型（全局 API），每人一句，第一則馬上貼、其餘每隔「後續留言間隔」貼一則。
  - NPC 在角色的貼文底下留言 → 作者在「角色回覆 NPC 留言延遲」後回一句。
  - 搬遷來的舊貼文不觸發；貼文刪掉時它的待辦一起清掉；過期超過 24 小時的待辦丟掉（很久沒開 App，回來不會一次噴一堆留言）。
- **私聊裡的「最近的朋友圈」**（`utils/momentsContext.ts`）：易變段帶上角色看得到的最近 3 天、最多 5 篇，附看得到的讚和留言。主動消息雲端打包不帶。
- **還沒做**：NPC 的輕量記憶還沒把朋友圈互動整理進去（目前只從群聊、查手機對話整理）；雲端（Worker）不跑朋友圈，App 關著時不會發文或互動。


## 用戶身份

身份卡（IdentitySwitcher）可以按角色設定不同身份。朋友圈是大家共用一個池子，所以第一版這樣處理：

- 用戶發文存的是**發文當下的預設身份**的名字和頭像快照。
- 角色看到的作者永遠是「用戶本人」（`id: 'user'`），不會因為身份卡不同而分成好幾個人。
- 如果以後想做「對不同角色用不同身份發文」，再在可見範圍那邊擴充。

## 第三個池子：查手機首頁的小 App（改名 Memo）

查手機首頁除了「軌跡 → Moments」，還有一個原本也叫 Moments 的小 App（`apps/CheckPhone.tsx` 的 `renderMoments`，存在 `phoneState.records` 的 `type: 'social'` 記錄，按「刷新動態」生成純文字動態）。寫文件時漏看了。

- **定案（2026-09-25）**：不併進貼文池。標題先改成 **Memo（小紙條）**；以後可能改成隨手留的心情小紙條，不需要留言和讚。內容和生成方式暫時不動。

## 定案紀錄

1. 角色之間的朋友關係：**單向**就算。
2. 互動可見範圍：**微信式**，只看得到自己朋友的讚和留言。
3. 新貼文不要假路人互動；「路人互動」留到抽卡角色功能再討論。
